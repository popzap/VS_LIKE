### 2-2. 웨이브에 적이 섞여 나오지 않는다 — ✅ **해결 (I-46)**

`WaveSpawnEntry` 에 `StartTime`/`EndTime` 을 추가하고 **항목마다 코루틴을 하나씩** 띄웠다.

그 건물에서 직업을 계속 강화"** 를 요구하면서 생겼고, 그대로 구현했다.

이 장르의 표준은 "직업 = 시작 무기와 시작 스탯"이고 런 중에는 안 변한다.
여기서는 **직업이 빌드가 도달하는 목적지**가 됐다 — 무기·건물을 키우면 직업이 승급하고,
승급하면 **스탯 보너스와 소지 상한이 같이 늘어난다**.

| 실제 구현 | |
|---|---|
| 레시피 | `ClassEvolutionData` SO — `FromClass` + `ItemData[] Ingredients` + `int[] RequiredLevels` + `CharacterClassData ResultClass` |
| 원본 데이터 | `Assets/Game/Balance/ClassEvolutions.csv` (→ [`BALANCE.md`](BALANCE.md)) |
| 누적 방식 | `PlayerStats._classChain` — **사슬 전체를 더한다.** 교체가 아니다 |
| 제단 | 재료 중 첫 건물. **필수다** (없으면 임포터가 경고) |
| 소모 | **없다.** 돌려주는 게 무기가 아니라 직업이라 재료까지 먹으면 순수한 손해다 |

### 이벤트 노드 — 배관은 끝났는데 **안이 비어 있다** (2026-08-31 확인)

길은 다 뚫려 있다. `GameManager.cs:252` 가 `StageType.Event` 를 받아
`EventManager.TriggerRandomEvent` 를 부르고, 끝나면 맵으로 돌아간다.
`Events.csv` 에 5종이 등록돼 있고 실제로 뽑힌다.

문제는 **뽑힌 다음에 일어나는 일**이다. `EventManager.cs` 가 할 수 있는 건 세 가지뿐이다 —
`XpBonus` · `CurrencyBonus` · `TriggerRandomWave`. 그래서

- `WaveManager.cs:81-86` 의 `switch` 에 `StageType.Event` 분기가 **없다.**
  `_ => normalWaves[Random.Range(...)]` 로 떨어진다 → **이벤트 전용 웨이브가 존재하지 않는다**
- 이벤트 UI 가 **없다.** `Title`/`Description` 은 `Debug.Log` 로만 나가고
  `GameState.Event` 를 읽는 패널이 하나도 없다 → **플레이어는 무슨 일이 났는지 못 본다**

⇒ 지금의 이벤트는 사실상 **"공짜 XP 또는 노말 웨이브 한 번"** 이다.
장르에서 이벤트가 하는 일(평소와 **다른 규칙**으로 한 판)을 아직 못 한다.

설계는 [`DESIGN_EVENTS.md`](DESIGN_EVENTS.md) 에 있다 (D22, 44차) —
`E1 함정방`(무한 소환 + 시간제한 생존) **상세 1건** + `E2`~`E6` **자리표만**.
**사용자 결정 6건(§7)이 대기 중이라 착수 전이다.**
