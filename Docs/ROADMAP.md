## 2. 코어 루프 — 뱀서라이크의 "맛"이 빠져 있다

### 2-1. 적이 전부 똑같이 움직인다 — ✅ **해결 (I-47)**

| 행동 | 붙일 적 | 상태 |
|---|---|---|
| ~~원거리 투사체~~ | Demon | ✅ **완료** — `AI = Ranged`. `PreferredRange` 유지 + 옆걸음 + `Proj_EnemyBolt` |
| ~~돌진(charge)~~ | Wolf | ✅ **완료** — `AI = Charger`. 예고 0.45s → 3배속 대시 0.4s → 경직 0.6s |
| ~~무리 유지(flocking)~~ | ~~Goblin~~ **전 종류** | ✅ **완료** — 조향식 분리. 적 콜라이더가 트리거라 물리로는 못 떼어 놓는다 |
| 분열 | Slime | ❌ 사망 시 소형 2마리 |
| 소환 | Ogre(보스) | ❌ 주기적 잡몹 소환 → 2-5 보스 패턴과 같이 |
| 자폭 | 신규 | ❌ 접근 → 정지 → 폭발 |

> ⚠️ **상속이 아니라 `EnemyAI` enum(데이터 주도)으로 갔다.** 상속으로 나누려면 행동마다
> 프리팹이 따로 있어야 하는데(컴포넌트 타입은 런타임에 못 바꾼다) 이 프로젝트는 6종이
> `Enemy_Goblin.prefab` 하나를 공유한다. `MoveTowardsPlayer()` 는 여전히 `virtual` 이라
> 행동이 훨씬 복잡해지면 그때 갈라도 된다. 상세는 `SETUP_STATUS.md` 2-18.
>
> 남은 3종(분열·소환·자폭)은 `EnemyAI` 에 값을 추가하고 `Enemies.csv` 에 열을 늘리면 된다.

### 2-2. 웨이브에 적이 섞여 나오지 않는다 — ✅ **해결 (I-46)**

`WaveSpawnEntry` 에 `StartTime`/`EndTime` 을 추가하고 **항목마다 코루틴을 하나씩** 띄웠다.
`Waves.csv` 문법은 `적Id*마리수@간격:시작-종료` 가 됐고, 6웨이브를 전부 시간창으로 재구성했다.

- 여러 종이 **동시에** 나온다 (검증: t=20s 에 Slime 10 + Goblin 6)
- 종료초를 넘기면 남은 마리수를 **버린다** → 웨이브 안에서 적 구성이 교대되는 난이도 곡선
- `MaxAlive` 상한 + **소환 반경 1.9배 밖 적 재배치**를 같이 넣었다 (→ §6)

> 사용자가 말한 "몬스터가 전 종류 안 나온다"의 실제 원인이 이것이었다.
> 남은 관련 작업은 **층별 난이도 스케일링** — 지금도 1층에서 Normal3 가 나올 수 있다 (→ `TODO.md` §3).

### 2-3. 무기 진화가 없다 ★★★

뱀서라이크의 핵심 보상 구조다. 코드에 `Evolv` 문자열이 **한 번도 없다.**

- 무기 Lv.MAX + 특정 패시브 보유 → 진화형 해금
- 진화는 **보물상자**에서 나온다 (아래 2-4)
- `ItemData` 에 `EvolvesInto` / `RequiredPassive` 필드 추가 + `Items.csv` 열 추가

### 2-4. 필드 픽업이 2종뿐이다 — 🟡 **절반 해결 (I-48)**

| 추가할 것 | 효과 | 상태 |

| JSON 저장/로드 (`MetaProgressionManager.cs:197,214`) | 런 종료 시 재화 정산 흐름 |
| 직업 3종 | **해금 조건 / 해금 흐름** |

**해야 할 일:** 재화 획득 → 런 종료 정산 → 메타 화면에서 소비 → 다음 런 반영.
이 고리가 닫혀야 "한 판 더" 가 생긴다. 지금은 죽으면 아무것도 안 남는다.
