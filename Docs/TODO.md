## 1. 🔴 최우선 — 수정했지만 아직 안 돌려본 것

I-14~I-18은 **코드 수정이 끝났다.** 하지만 전부 스모크 테스트가 건너뛴 경로에서 나온 버그라
**고쳤다는 사실만으로는 안전하지 않다.** 아래를 실제로 플레이해서 확인해야 한다.

- [ ] **Shop 노드** 진입 → 구매 / 제거 / 리롤 → 닫기 → **맵이 다음 층으로 진행되는지** *(I-14)*
- [ ] **Event 노드** 진입 → 5종 이벤트 중 하나 발생 → 보상 지급 + 맵 진행 *(I-15)*
- [ ] **Event 노드**에서 `TriggerRandomWave` 이벤트(Ambush/Cursed Offering)가 뽑혔을 때 HUD가 정상인지 *(I-15)*
- [ ] **ESC 일시정지** — Wave 중에만 열리고, 맵/상점/메뉴에서는 무시되는지 → 닫으면 원래 상태로 복귀하는지 *(I-16)*
- [ ] **Retry** → 아이템 레벨이 0부터 다시 시작하는지 *(I-17)*
- [ ] **런 종료 후** `TotalRuns` / `TotalKills` 가 증가·저장되는지 *(I-18)*

### 그 밖의 미검증 경로

- [ ] **레벨업 카드 선택 후** 웨이브가 정상 복귀하는지 — 패널 표시와 리롤은 I-24 에서 검증했지만
      `SelectItem` → `HidePanel` → `OnLevelUpCompleted` 경로는 아직 안 눌러 봤다
- [ ] Boss 스테이지 클리어 → `Victory` → `RunEndPanel` (Boss1은 `KillTarget=19` 킬 클리어)
- [ ] **실제 전투에서의 피격** — `TryTakeHit` 단위 동작은 검증했지만(I-20), 적이 실제로 붙었을 때 넉백/깜빡임이 어떻게 보이는지는 눈으로 봐야 한다
- [ ] **타격 반응 체감** *(I-44)* — 수치는 로그로 검증했지만 "맞는 느낌"은 눈으로만 판단할 수 있다.
      특히 ① 넉백 `6.0 / 0.10s` 가 적 대열을 너무 흩뜨리진 않는지
      ② 사망 팝 `0.14s` 가 시체를 쌓아 보이게 하진 않는지
      ③ **엘리트/보스 처치 히트스톱이 렉처럼 느껴지진 않는지**
- [ ] **엘리트/보스 처치 연출** *(I-44 F-5)* — `PlayDeathImpact()` 의 흔들기+히트스톱은
      **노말 웨이브에서 검증할 수 없었다**(엘리트가 안 나옴). Elite/Boss 노드로 실제 확인 필요
- [ ] **웨이브 병렬 소환 체감** *(I-46)* — 로그로는 검증했지만 실제로 플레이해 봐야 아는 것들
      - `MaxAlive`(60~130) 가 **화면을 얼마나 채우는지**. 60마리가 이미 벅차면 전부 낮춘다
      - 시간창 때문에 **버려지는 마리수가 너무 많지 않은지** (예: `Normal3` 의 Goblin 34마리는
        40~90초 창에 1.5초 간격 → 33마리가 다 나오지만, `MaxAlive` 대기가 겹치면 줄어든다)
      - **재배치된 적이 갑자기 나타나 억울하게 맞는 느낌**은 아닌지. 지금은 소환 반경(20)에
        새로 놓으므로 화면 밖이지만, 카메라 룩어헤드가 크면 시야에 들어올 수 있다
      - 적 수가 많아졌을 때 **프레임**. MPB 때문에 적 1마리 = 드로우콜 1개다 (§3 아래)
- [ ] **적 행동 3종 체감** *(I-47)*
      - Demon 이 `PreferredRange`(7)를 유지하면 **무기 사거리(3.5~6) 밖**이다. 근접 직업(Warrior)이
        Demon 을 아예 못 잡는 상황이 되지 않는지 — 되면 사거리를 5~6으로 낮춘다
      - Wolf 돌진 예고(0.45초)가 **보이는지**. 지금 예고 표시는 `_blinkTimer` 기반 깜빡임뿐이라
        난전에서 안 보일 수 있다. 안 보이면 전용 연출(지면 화살표 등)이 필요하다 → 새 애셋
      - 무리 분리(가중치 0.9)가 **추격을 방해하지 않는지**. 적이 플레이어 주위를 맴돌기만 하면
        `SeparationWeight` 를 낮춘다
      - 적탄이 **눈에 띄는지**. 붉은 총알 0.55 스케일이라 난전에서 묻힐 수 있다
- [ ] **보물상자 / 자석 체감** *(I-48)*
      - 자석 `0.6%` 가 실제로 웨이브당 1~2개인지. 체감상 안 나오면 확률을 올린다
        (`SceneWiring.csv` 의 `magnetDropChance`)
      - 상자를 밟았을 때 **레벨업인지 상자 보상인지 구분이 되는지.** 같은 패널을 쓰므로
        구분이 필요하면 패널 제목만 바꾸면 된다 (새 UI 불필요)
      - 상자·자석 스프라이트가 **경험치 오브와 헷갈리지 않는지** (`sortingOrder 1` 로 위에 그린다)
- [ ] **오디오 청취 확인** *(I-49)* — 로그로 검증한 것은 "**울린다**"까지다.
      아래는 **귀로만** 판단할 수 있고, 고치는 곳은 전부 `Assets/Game/Audio/AudioLibrary.asset`
      (클립별 `Volume` / `PitchJitter`) 또는 `AudioManager` 의 `BgmVolume`(0.8) / `SfxVolume`(1.0)
      - 난전에서 **`EnemyHit`(0.28) 이 묻히거나 반대로 시끄럽지 않은지.** 초당 수십 번 울리는
        소리라 다른 것보다 훨씬 낮게 잡아 뒀다. 값 하나가 전체 인상을 좌우한다
      - **`XpPickup`(0.22) 이 자석을 먹었을 때** 어떻게 들리는지. 중복 컷이 20개를 1개로 줄이는 건
        확인했지만, 0.04초 간격으로 **연달아** 울리는 소리는 여전히 기관총처럼 들릴 수 있다
      - `PlayerHit`(0.70) 이 **맞았다는 걸 알아챌 만큼** 튀는지. 피격은 놓치면 안 되는 정보다
      - **BGM 이 SFX 를 덮지 않는지.** 덕킹이 필요하다고 판단되면 그때가 `AudioMixer` 도입 시점이다 (§3)
      - 곡 4개가 **화면 성격과 맞는지** — 특히 `BGM_Shop` 은 스테이지맵·상점·이벤트·승리를 **겸한다**
      - 웨이브 → 레벨업 → 웨이브에서 **곡이 안 끊기는지** (의도된 동작. 끊기면 버그)
- [ ] 플레이어 사망 (지금까지 `OnPlayerDied()` 직접 호출로만 검증)
- [ ] **건물 밀기 감각** — `mass 5 / linearDamping 10` 이 "너무 쉽게 밀리지만 않는" 느낌인지 직접 밀어 볼 것.
      너무 무거우면 `mass` 를, 너무 미끄러지면 `linearDamping` 을 만진다

> 직업 카드의 잠금 오버레이(`LockedOverlay`)와 `UnlockCost` 열은 이미 만들어 뒀으니,
> 해금 흐름을 붙일 때 `IsUnlocked()` 한 곳만 고치면 된다.

## 3. ⚠️ 콘텐츠 — 남은 부분

임시 콘텐츠는 들어갔다. 남은 건 **구조적으로 빠진 것**들이다.

### 🔴 층(Layer)별 난이도 스케일링이 없다 — ✅ **방향 확정 (2026-08-29, 결정 4)**

`WaveManager.StartWave()` 는 노드 타입만 보고 웨이브 풀에서 **무작위로** 하나 뽑는다.

```csharp
_currentWaveData = node.StageType switch
{
    StageType.Elite => eliteWaves[Random.Range(0, eliteWaves.Length)],
    StageType.Boss  => bossWave,
    _               => normalWaves[Random.Range(0, normalWaves.Length)]
};
```

즉 **1층에서 Normal3(108마리)이 나오고 9층에서 Normal1(64마리)이 나올 수 있다.**
난이도 곡선이 존재하지 않는다.

**→ 둘 다 하되 (B) 를 먼저.**

- [ ] **(B) 전역 배율 먼저** — 층에 비례하는 배율(HP/피해/스폰수)을 `EnemyBase.Initialize` 에 곱한다.
      데이터가 거의 안 필요하고 층이 몇 개든 자동으로 늘어난다.
      ⚠️ 배율만 있으면 **"같은 웨이브인데 숫자만 큰"** 느낌이 되므로 (A)의 전 단계로만 본다
- [ ] **(A) 나중에** — `WaveData` 에 `MinLayer`/`MaxLayer` 열을 넣어 층에 맞는 웨이브만 뽑는다.
      **웨이브가 6개뿐이라 지금 넣으면 층당 선택지가 거의 없다.**
      재개 조건: 웨이브를 10개 이상으로 늘렸을 때

### ⚠️ `MaterialPropertyBlock` 과 스프라이트 배칭

I-26 은 적마다 `MaterialPropertyBlock` 을 쓴다(외곽선 폭·색·바운스 위상·플래시).
I-29 로 **플레이어도** MPB 를 쓴다(바운스·기울기) — 드로우콜이 하나 더 늘었다.

> 바닥 타일맵은 MPB 를 쓰지 않는다. `TilemapRenderer` 는 청크 단위로 메시를 합치고
> 색 차이는 `Tile.color`(정점 색)로 들어가므로 타일 종류가 10개여도 **텍스처 수만큼만** 배치가 갈린다.

~~지금은 문제가 안 된다~~ — **I-46 으로 실제로 늘어났다.** `MaxAlive` 가 웨이브별 60~130 이므로
드로우콜이 최대 130개 + 플레이어 1개다. 적 스프라이트가 6종이고 아틀라스로 묶여 있지 않아
어차피 텍스처별로 배치가 갈리지만, **이제 프로파일링할 값어치가 생겼다** (→ §1 체감 확인 항목).

줄이는 방법: 일반 몹은 `sr.SetPropertyBlock(null)` 로 MPB 를 아예 비우고(외곽선 0 · 플래시 0 이면
기본값과 같다), 바운스 위상은 오브젝트 월드 좌표에서 셰이더가 직접 유도하게 바꾼다.
엘리트/보스와 **플래시 중인 개체만** MPB 를 갖게 되어 대부분이 다시 배칭된다.

사용자는 **"캐릭터 이미지도 변하게 하는 게 좋겠다 — 필요하면 생성해"** 라고 승인했다.

**재개 조건: 다음 대화에서 동의를 받고 바로 생성.** 필요한 것은 아래와 같다.

| 항목 | 값 |
|---|---|
| 필요한 것 | `WalkSheet` **4장**. `Portrait` 는 **불필요** |
| 왜 Portrait 이 필요 없나 | `Portrait` 를 읽는 곳은 `ClassCardUI.cs` / `ClassSelectUI.cs` **둘뿐**이고, 그건 직업 선택 화면이다. T2 이상은 그 화면에 안 뜬다 |

| 놓을 곳 | `Assets/Game/Sprites/Classes/Walk/{Id}_Walk.png` (T1 3종과 같은 규칙) |

| 생성 방법 | `GenerateSpritesheet` + `referenceImageInstanceId` 로 **해당 T1 원화를 참조**해야 같은 캐릭터가 강화된 모습으로 나온다 (§6) |

> ⚠️ **`BodySprite` 만 채우면 소용없다.** `PlayerVisual` 이 `sr.sprite` 를 걷기 프레임 0으로
> 덮어쓰기 때문에 **`WalkSheet` 이 있어야 겉모습이 바뀐다.**

> T1 외형이 그대로 유지된다 — 프리팹 기본값으로 되돌아가지 않는다 (의도된 동작)

> ⚠️ **빈 슬롯을 `?.` 로 건너뛰려 하지 말 것.** 미할당 직렬화 필드는 C# 기준 `null` 이 아니라
> 접근 시 `UnassignedReferenceException` 을 던지는 Unity 의 **"가짜 null"** 이다.
> 실제로 이것 때문에 레벨업 패널이 통째로 안 떴다 (I-24). 반드시 `if (field != null)` 로 검사한다.
