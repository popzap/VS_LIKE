## 2. ⚠️ 결정이 필요한 항목 (착수 전 확인)

### 🔴 재화 구조 — 가장 먼저 정해야 함

런 중에 쓰는 골드와 영구 저장되는 메타 골드가 **`MetaProgression.Currency` 하나**를 공유한다.
이게 정해지지 않으면 [`BALANCE.md`](BALANCE.md) §3-1의 수치를 제대로 잡을 수 없다.

현재 10층 런 예상 수입이 **약 1,240G** 인데 상점 아이템은 5~12G다. 사실상 무제한.
(→ 처치 보상 `≈1,084G` 가 클리어 보상 `156G` 를 압도한다)

**선택지**
- (A) 분리 — 런 골드는 상점 전용, 런 종료 시 소멸. 메타 골드는 별도 수급
- (B) 유지 — 하나로 쓰되 상점 가격을 100G 단위로 올리고 메타 강화는 훨씬 비싸게

### 그 밖

| 항목 | 현황 | 필요한 것 |
|---|---|---|
| `GameState.MetaScreen` | enum에만 존재. **전환하는 코드 0개** | 메타 강화 화면 UI + 메인 메뉴 진입 버튼 |
| `UpgradeDefinition` | 클래스는 완성. **애셋 0개**, `upgrades` size = 0 | 강화 항목 SO 제작. `ApplyStatKey` 는 `XpGain`/`GoldGain` 까지 대응 완료 |
| `UnlockCharacter` / `UnlockSkin` | API만 존재. 호출자 0개 | 캐릭터·스킨 데이터 + 해금 UI. 아니면 **삭제** |
| 직업 해금 | `ClassSelectUI.IsUnlocked()` 가 `UnlockedByDefault` 만 본다 | `MetaProgressionManager.UnlockCharacter` 와 잇기 + 카드에서 골드로 해금하는 흐름 |

> 위 4건은 전부 **새 UI/데이터 결정**이 필요해 범위에서 제외했다.
> 직업 카드의 잠금 오버레이(`LockedOverlay`)와 `UnlockCost` 열은 이미 만들어 뒀으니,
> 해금 흐름을 붙일 때 `IsUnlocked()` 한 곳만 고치면 된다.

## 3. ⚠️ 콘텐츠 — 남은 부분

임시 콘텐츠는 들어갔다. 남은 건 **구조적으로 빠진 것**들이다.

### 🔴 층(Layer)별 난이도 스케일링이 없다

`WaveManager.StartWave()` 는 노드 타입만 보고 웨이브 풀에서 **무작위로** 하나 뽑는다.

```csharp
_currentWaveData = node.StageType switch
{
    StageType.Elite => eliteWaves[Random.Range(0, eliteWaves.Length)],
    StageType.Boss  => bossWave,
    _               => normalWaves[Random.Range(0, normalWaves.Length)]
};
```

즉 **1층에서 Normal3(108마리)이 나오고 9층에서 Normal1(64마리)이 나올 수 있다.**
난이도 곡선이 존재하지 않는다.

**수정 방향 (택1)**
- (A) `StageNode.Layer` 로 웨이브를 선택 — `WaveData` 에 `MinLayer`/`MaxLayer` 열 추가
- (B) 층에 비례하는 전역 배율(HP/피해/스폰수)을 `EnemyBase.Initialize` 에 곱한다 — 데이터가 덜 필요함

### 🔴 스탯 재조정 (I-21 여파 + 직업 보너스 반영)

**아직 아무도 조정하지 않은 수치다.** I-21을 고치면서 플레이어 실효 스탯이 전부 절반이 됐고,
그 위에 I-22 직업 보너스가 새로 얹혔다. 지금 값들은 **2배 버그가 있던 시절에 잡은 감**이라 근거가 없다.

> ⚠️ **I-32 로 패시브까지 약해졌다.** 누적 버그를 고치면서 Lv5 패시브의 실효값이
> 절반 이하로 떨어졌다 (`Damage` +1.57 → +0.55). `Passives.csv` 의 값 자체가
> **"누적된다는 전제로 잡힌 감"** 일 수 있으므로 아래 재조정과 **같이** 볼 것.

| 무엇이 달라졌나 | 전 (버그) | 후 (현재) |
|---|---|---|
| MaxHp | 200 | 100 (+직업) |
| MoveSpeed | 8 | 4 (+직업) — 가장 빠른 적 Wolf(4.2)보다 느림 |
| AttackSpeed | 2 (= 쿨다운 2배 → 느림) | 1 |
| PickupRadius | 4 | 2 |
| CritMultiplier | 3.0 | 1.5 |

- [ ] **플레이 후** `Economy.csv` 의 `baseStats.*` 재조정 — 특히 `MaxHp` / `MoveSpeed`
- [ ] `PlayerStats.invincibleTime`(0.6) 재검토 — 전체 난이도에 가장 크게 작용하는 단일 수치다
      (적 하나가 붙어 있을 때 초당 피해 = `ContactDamage ÷ invincibleTime`)
- [ ] **직업 3종 밸런스** — `Classes.csv` 의 `Bonus*`. 지금은 감으로 넣은 자리표시값이다
      - Warrior(+30HP/+2방어) 가 무난한지, Mage(−25HP/−1방어) 가 너무 물렁하지 않은지
      - `BonusAttackSpeed` 는 **음수라야 빨라진다** (쿨다운 배율)
- [ ] 무기 `Damage` 배열 vs 적 `MaxHp` 대비 — 스탯이 절반이 된 만큼 TTK가 2배 가까이 늘었을 수 있다

> 근거 표와 계산식은 [`BALANCE.md`](BALANCE.md) §3에 있다. 수치를 바꾸면 **그 표도 같이 고칠 것.**

### ⚠️ 바닥이 너무 균일할 수 있다 (I-28 여파)

퀼트를 없애려고 타일 10종의 평균 휘도를 **한 목표색으로 전부 끌어내렸다**.
그 결과 "눈 안 아프게"는 확실히 달성했지만 **변화가 거의 안 보인다.**

- [ ] 실플레이에서 바닥이 밋밋하면 평준화를 **0.85 정도로 완화** — 배율을 `lerp(1, 배율, 0.85)` 로
      섞으면 원래 색이 15% 남아 결이 살짝 돌아온다. 퀼트가 재발하는지 캡처로 확인할 것
- [ ] 반대로 아직 산만하면 `Tile_Grass` 비중(40)을 더 올리거나 특징이 강한 타일을 빼면 된다

> `Tile.color` 는 정점 스트림의 `Color32` 라 **1을 넘는 배율은 잘린다.** 밝히는 방향으로는
> 조정이 안 되므로 목표색은 항상 **가장 어두운 타일 이하**로 잡아야 한다.

### ⚠️ `MaterialPropertyBlock` 과 스프라이트 배칭

I-26 은 적마다 `MaterialPropertyBlock` 을 쓴다(외곽선 폭·색·바운스 위상·플래시).
I-29 로 **플레이어도** MPB 를 쓴다(바운스·기울기) — 드로우콜이 하나 더 늘었다.
**MPB 가 걸린 렌더러는 다른 렌더러와 배칭되지 않는다.** 즉 적 한 마리당 드로우콜 1개다.

> 바닥 타일맵은 MPB 를 쓰지 않는다. `TilemapRenderer` 는 청크 단위로 메시를 합치고
> 색 차이는 `Tile.color`(정점 색)로 들어가므로 타일 종류가 10개여도 **텍스처 수만큼만** 배치가 갈린다.

지금은 문제가 안 된다 — 적 스프라이트가 6종이고 아틀라스로 묶여 있지 않아
어차피 텍스처별로 배치가 갈린다. 다만 **적이 수백 마리로 늘면 프로파일링해 볼 것.**

줄이는 방법: 일반 몹은 `sr.SetPropertyBlock(null)` 로 MPB 를 아예 비우고(외곽선 0 · 플래시 0 이면
기본값과 같다), 바운스 위상은 오브젝트 월드 좌표에서 셰이더가 직접 유도하게 바꾼다.
엘리트/보스와 **플래시 중인 개체만** MPB 를 갖게 되어 대부분이 다시 배칭된다.

## 4. ⚠️ 빈 슬롯 (전부 null 가드됨 — 크래시는 안 남)

| 대상 | 필드 | 증상 |
|---|---|---|
| `HUDManager` | `faceHealthy` / `faceNormal` / `faceWorried` / `faceCritical` | 초상화 표정 변화 없음 |
| `HUDManager` | `levelUpAnimator` / `levelUpEffect` | 레벨업 연출 없음 |

> ⚠️ **빈 슬롯을 `?.` 로 건너뛰려 하지 말 것.** 미할당 직렬화 필드는 C# 기준 `null` 이 아니라
> 접근 시 `UnassignedReferenceException` 을 던지는 Unity 의 **"가짜 null"** 이다.
> 실제로 이것 때문에 레벨업 패널이 통째로 안 떴다 (I-24). 반드시 `if (field != null)` 로 검사한다.
