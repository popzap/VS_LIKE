## 1. 🔴 최우선 — 수정했지만 아직 안 돌려본 것

I-14~I-18은 **코드 수정이 끝났다.** 하지만 전부 스모크 테스트가 건너뛴 경로에서 나온 버그라
**고쳤다는 사실만으로는 안전하지 않다.** 아래를 실제로 플레이해서 확인해야 한다.

- [ ] **Shop 노드** 진입 → 구매 / 제거 / 리롤 → 닫기 → **맵이 다음 층으로 진행되는지** *(I-14)*
- [ ] **Event 노드** 진입 → 5종 이벤트 중 하나 발생 → 보상 지급 + 맵 진행 *(I-15)*
- [ ] **Event 노드**에서 `TriggerRandomWave` 이벤트(Ambush/Cursed Offering)가 뽑혔을 때 HUD가 정상인지 *(I-15)*
- [ ] **ESC 일시정지** — Wave 중에만 열리고, 맵/상점/메뉴에서는 무시되는지 → 닫으면 원래 상태로 복귀하는지 *(I-16)*
- [ ] **Retry** → 아이템 레벨이 0부터 다시 시작하는지 *(I-17)*
- [ ] **런 종료 후** `TotalRuns` / `TotalKills` 가 증가·저장되는지 *(I-18)*

### 그 밖의 미검증 경로

- [ ] **레벨업 카드 선택 후** 웨이브가 정상 복귀하는지 — 패널 표시와 리롤은 I-24 에서 검증했지만
      `SelectItem` → `HidePanel` → `OnLevelUpCompleted` 경로는 아직 안 눌러 봤다
- [ ] Boss 스테이지 클리어 → `Victory` → `RunEndPanel` (Boss1은 `KillTarget=19` 킬 클리어)
- [ ] **실제 전투에서의 피격** — `TryTakeHit` 단위 동작은 검증했지만(I-20), 적이 실제로 붙었을 때 넉백/깜빡임이 어떻게 보이는지는 눈으로 봐야 한다
- [ ] **타격 반응 체감** *(I-44)* — 수치는 로그로 검증했지만 "맞는 느낌"은 눈으로만 판단할 수 있다.
      특히 ① 넉백 `6.0 / 0.10s` 가 적 대열을 너무 흩뜨리진 않는지
      ② 사망 팝 `0.14s` 가 시체를 쌓아 보이게 하진 않는지
      ③ **엘리트/보스 처치 히트스톱이 렉처럼 느껴지진 않는지**
- [ ] **엘리트/보스 처치 연출** *(I-44 F-5)* — `PlayDeathImpact()` 의 흔들기+히트스톱은
      **노말 웨이브에서 검증할 수 없었다**(엘리트가 안 나옴). Elite/Boss 노드로 실제 확인 필요
- [ ] **웨이브 병렬 소환 체감** *(I-46)* — 로그로는 검증했지만 실제로 플레이해 봐야 아는 것들
      - `MaxAlive`(60~130) 가 **화면을 얼마나 채우는지**. 60마리가 이미 벅차면 전부 낮춘다
      - 시간창 때문에 **버려지는 마리수가 너무 많지 않은지** (예: `Normal3` 의 Goblin 34마리는
        40~90초 창에 1.5초 간격 → 33마리가 다 나오지만, `MaxAlive` 대기가 겹치면 줄어든다)
      - **재배치된 적이 갑자기 나타나 억울하게 맞는 느낌**은 아닌지. 지금은 소환 반경(20)에
        새로 놓으므로 화면 밖이지만, 카메라 룩어헤드가 크면 시야에 들어올 수 있다
      - 적 수가 많아졌을 때 **프레임**. MPB 때문에 적 1마리 = 드로우콜 1개다 (§3 아래)
- [ ] **적 행동 3종 체감** *(I-47)*
      - Demon 이 `PreferredRange`(7)를 유지하면 **무기 사거리(3.5~6) 밖**이다. 근접 직업(Warrior)이
        Demon 을 아예 못 잡는 상황이 되지 않는지 — 되면 사거리를 5~6으로 낮춘다
      - Wolf 돌진 예고(0.45초)가 **보이는지**. 지금 예고 표시는 `_blinkTimer` 기반 깜빡임뿐이라
        난전에서 안 보일 수 있다. 안 보이면 전용 연출(지면 화살표 등)이 필요하다 → 새 애셋
      - 무리 분리(가중치 0.9)가 **추격을 방해하지 않는지**. 적이 플레이어 주위를 맴돌기만 하면
        `SeparationWeight` 를 낮춘다
      - 적탄이 **눈에 띄는지**. 붉은 총알 0.55 스케일이라 난전에서 묻힐 수 있다
- [ ] **보물상자 / 자석 체감** *(I-48)*
      - 자석 `0.6%` 가 실제로 웨이브당 1~2개인지. 체감상 안 나오면 확률을 올린다
        (`SceneWiring.csv` 의 `magnetDropChance`)
      - 상자를 밟았을 때 **레벨업인지 상자 보상인지 구분이 되는지.** 같은 패널을 쓰므로
        구분이 필요하면 패널 제목만 바꾸면 된다 (새 UI 불필요)
      - 상자·자석 스프라이트가 **경험치 오브와 헷갈리지 않는지** (`sortingOrder 1` 로 위에 그린다)
- [ ] **오디오 청취 확인** *(I-49)* — 로그로 검증한 것은 "**울린다**"까지다.
      아래는 **귀로만** 판단할 수 있고, 고치는 곳은 전부 `Assets/Game/Audio/AudioLibrary.asset`
      (클립별 `Volume` / `PitchJitter`) 또는 `AudioManager` 의 `BgmVolume`(0.8) / `SfxVolume`(1.0)
      - 난전에서 **`EnemyHit`(0.28) 이 묻히거나 반대로 시끄럽지 않은지.** 초당 수십 번 울리는
        소리라 다른 것보다 훨씬 낮게 잡아 뒀다. 값 하나가 전체 인상을 좌우한다
      - **`XpPickup`(0.22) 이 자석을 먹었을 때** 어떻게 들리는지. 중복 컷이 20개를 1개로 줄이는 건
        확인했지만, 0.04초 간격으로 **연달아** 울리는 소리는 여전히 기관총처럼 들릴 수 있다
      - `PlayerHit`(0.70) 이 **맞았다는 걸 알아챌 만큼** 튀는지. 피격은 놓치면 안 되는 정보다
      - **BGM 이 SFX 를 덮지 않는지.** 덕킹이 필요하다고 판단되면 그때가 `AudioMixer` 도입 시점이다 (§3)
      - 곡 4개가 **화면 성격과 맞는지** — 특히 `BGM_Shop` 은 스테이지맵·상점·이벤트·승리를 **겸한다**
      - 웨이브 → 레벨업 → 웨이브에서 **곡이 안 끊기는지** (의도된 동작. 끊기면 버그)
- [ ] 플레이어 사망 (지금까지 `OnPlayerDied()` 직접 호출로만 검증)
- [ ] **건물 밀기 감각** — `mass 5 / linearDamping 10` 이 "너무 쉽게 밀리지만 않는" 느낌인지 직접 밀어 볼 것.
      너무 무거우면 `mass` 를, 너무 미끄러지면 `linearDamping` 을 만진다
- [ ] **건물이 길을 막지 않는지** — `TryFindSpot` 이 플레이어 주위 3링을 채우므로
      좁은 곳에서 건물 5개를 연달아 세우면 플레이어가 갇힐 수 있다
- [ ] **건물 1.30 유닛 체감** (11차) — 플레이어(1.00)보다 크다. 3링을 채웠을 때 시야를 가리지 않는지,

## 2. ⚠️ 결정이 필요한 항목 (착수 전 확인)

### 🔴 재화 구조 — 가장 먼저 정해야 함

런 중에 쓰는 골드와 영구 저장되는 메타 골드가 **`MetaProgression.Currency` 하나**를 공유한다.
이게 정해지지 않으면 [`BALANCE.md`](BALANCE.md) §3-1의 수치를 제대로 잡을 수 없다.

현재 10층 런 예상 수입이 **약 1,240G** 인데 상점 아이템은 5~12G다. 사실상 무제한.
(→ 처치 보상 `≈1,084G` 가 클리어 보상 `156G` 를 압도한다)

**선택지**
- (A) 분리 — 런 골드는 상점 전용, 런 종료 시 소멸. 메타 골드는 별도 수급
- (B) 유지 — 하나로 쓰되 상점 가격을 100G 단위로 올리고 메타 강화는 훨씬 비싸게

### 🔴 직업 진화 — 다음 큰 작업 (2026-08-29 합의)

사용자 방향: **"무기 + 건물로 직업을 정하고, 특정 패시브나 무기로 조건이 충족됐을 때
해당 건물에서 직업을 계속 강화. 무기 + 무기로 합치는 건 보물상자."**

이로써 조합 → 결과 → 경로가 **완전히 갈린다.**

| 조합 | 결과 | 전달 경로 |
|---|---|---|
| 무기 + **무기** | 진화 **무기** | **보물상자** |
| 무기 + **패시브** | 진화 **무기** | **보물상자** |
| 무기 + **건물** | **직업 T2** | **그 건물 앞 `E`** |
| (이후) 패시브·무기 조건 | **직업 T3 · T4 …** | **같은 건물 앞 `E`** |

경로가 재료에서 파생된다는 17차 원칙(`IsFinalEvolution`)은 그대로 살아 있다 —
**건물이 섞이면 제단**이라는 규칙이 이제 "결과가 직업"과 같은 뜻이 될 뿐이다.

> 🔴 **현재 데이터와 충돌한다.** `Sentinel`(Gun Lv5 + Turret Lv3) 과
> `Doomsday`(Bomb Lv5 + Bombard Lv3) 는 **무기+건물인데 결과가 무기**다.
> 새 분할대로면 이 둘은 무기가 아니라 **직업**이 되어야 한다.
> → 진행 전제로 삼았으나 **사용자 확인을 받지 않았다.** 착수 시 먼저 물을 것.

**착수 전에 정할 것**

| 항목 | 왜 정해야 하나 |
|---|---|
| 직업이 바뀌면 **스탯 보너스가 교체인가 누적인가** | `PlayerStats.Class` 는 하나뿐이고 `RecalculateStats` 가 `Class?.ApplyBonus` 를 **한 번만** 부른다. 교체면 T1 보너스가 사라지고, 누적이면 `Class` 를 리스트로 바꿔야 한다 |
| **소지 상한이 같이 오르는가** (I-55 와 직결) | 오른다면 "직업 진화 = 칸 확장"이 되어 상한이 성장 축이 된다. 안 오르면 스탯만 오르는 밋밋한 보상이 된다 |
| **시작 무기를 다시 주는가** | `StartingWeapon` 지급 경로는 `GameManager.StartRun` 하나뿐이다. 진화에서도 주려면 그 경로를 런 중에 다시 탈 수 있게 해야 한다 |
| 그림 — **T2 이상의 `Portrait`/`WalkSheet`** | 없으면 진화해도 **화면상 아무 변화가 없다.** T1 것을 재사용할지, 새로 생성할지 |
| `CharacterClassData` 에 붙일지 **별도 `ClassEvolutionData`** 로 뺄지 | 17차에 `EvolutionData` 를 아이템에서 뺀 것과 같은 판단이 필요하다 (재료 개수 가변 · 카테고리 무관) |

**손대야 할 것 (예상)**

- `Evolutions.csv` — 제단 레시피 2행을 직업 쪽으로 이관
- `Items.csv` / `Weapons.csv` — 고아가 되는 `Sentinel` / `Doomsday` 무기 항목 삭제 또는 용도 변경
- `Classes.csv` — T2 이상 직업 행 + 상위 직업임을 나타낼 열
- `SceneWiring.csv` — 새 매니저를 쓴다면 배선 행 추가
- `EvolutionManager` — 결과가 아이템이 아니라 직업인 분기

### 그 밖

| 항목 | 현황 | 필요한 것 |
|---|---|---|
| `GameState.MetaScreen` | enum에만 존재. **전환하는 코드 0개** | 메타 강화 화면 UI + 메인 메뉴 진입 버튼 |
| `UpgradeDefinition` | 클래스는 완성. **애셋 0개**, `upgrades` size = 0 | 강화 항목 SO 제작. `ApplyStatKey` 는 `XpGain`/`GoldGain` 까지 대응 완료 |
| `UnlockCharacter` / `UnlockSkin` | API만 존재. 호출자 0개 | 캐릭터·스킨 데이터 + 해금 UI. 아니면 **삭제** |
| 직업 해금 | `ClassSelectUI.IsUnlocked()` 가 `UnlockedByDefault` 만 본다 | `MetaProgressionManager.UnlockCharacter` 와 잇기 + 카드에서 골드로 해금하는 흐름 |

> 위 4건은 전부 **새 UI/데이터 결정**이 필요해 범위에서 제외했다.
> 직업 카드의 잠금 오버레이(`LockedOverlay`)와 `UnlockCost` 열은 이미 만들어 뒀으니,
> 해금 흐름을 붙일 때 `IsUnlocked()` 한 곳만 고치면 된다.

## 3. ⚠️ 콘텐츠 — 남은 부분

임시 콘텐츠는 들어갔다. 남은 건 **구조적으로 빠진 것**들이다.

### 🔴 층(Layer)별 난이도 스케일링이 없다

`WaveManager.StartWave()` 는 노드 타입만 보고 웨이브 풀에서 **무작위로** 하나 뽑는다.

```csharp
_currentWaveData = node.StageType switch
{
    StageType.Elite => eliteWaves[Random.Range(0, eliteWaves.Length)],
    StageType.Boss  => bossWave,
    _               => normalWaves[Random.Range(0, normalWaves.Length)]
};
```

즉 **1층에서 Normal3(108마리)이 나오고 9층에서 Normal1(64마리)이 나올 수 있다.**
난이도 곡선이 존재하지 않는다.

**수정 방향 (택1)**
- (A) `StageNode.Layer` 로 웨이브를 선택 — `WaveData` 에 `MinLayer`/`MaxLayer` 열 추가
- (B) 층에 비례하는 전역 배율(HP/피해/스폰수)을 `EnemyBase.Initialize` 에 곱한다 — 데이터가 덜 필요함

### 🔴 스탯 재조정 (I-21 여파 + 직업 보너스 반영)

**아직 아무도 조정하지 않은 수치다.** I-21을 고치면서 플레이어 실효 스탯이 전부 절반이 됐고,
그 위에 I-22 직업 보너스가 새로 얹혔다. 지금 값들은 **2배 버그가 있던 시절에 잡은 감**이라 근거가 없다.

> ⚠️ **I-32 로 패시브까지 약해졌다.** 누적 버그를 고치면서 Lv5 패시브의 실효값이
> 절반 이하로 떨어졌다 (`Damage` +1.57 → +0.55). `Passives.csv` 의 값 자체가
> **"누적된다는 전제로 잡힌 감"** 일 수 있으므로 아래 재조정과 **같이** 볼 것.

| 무엇이 달라졌나 | 전 (버그) | 후 (현재) |
|---|---|---|
| MaxHp | 200 | 100 (+직업) |
| MoveSpeed | 8 | 4 (+직업) — 가장 빠른 적 Wolf(4.2)보다 느림 |
| AttackSpeed | 2 (= 쿨다운 2배 → 느림) | 1 |
| PickupRadius | 4 | 2 |
| CritMultiplier | 3.0 | 1.5 |

- [ ] **플레이 후** `Economy.csv` 의 `baseStats.*` 재조정 — 특히 `MaxHp` / `MoveSpeed`
- [ ] `PlayerStats.invincibleTime`(0.6) 재검토 — 전체 난이도에 가장 크게 작용하는 단일 수치다
      (적 하나가 붙어 있을 때 초당 피해 = `ContactDamage ÷ invincibleTime`)
- [ ] **직업 3종 밸런스** — `Classes.csv` 의 `Bonus*`. 지금은 감으로 넣은 자리표시값이다
      - Warrior(+30HP/+2방어) 가 무난한지, Mage(−25HP/−1방어) 가 너무 물렁하지 않은지
      - `BonusAttackSpeed` 는 **음수라야 빨라진다** (쿨다운 배율)
