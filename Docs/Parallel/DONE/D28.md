## 2. `D27` 인계 반영 — `CLAUDE.md` §4 에 함정 2건

`D27` 이 새로 확인한 Unity MCP 함정 둘이 **`CLAUDE.md` 에 안 들어가 있었다.**
`PERF.md`·`SETUP_STATUS` 에는 있지만, 매 세션이 읽는 건 `CLAUDE.md` 다.

| 새 행 | 내용 |
|---|---|
| **에러 0 인데 새 필드가 없다** | `Assets/Refresh` 가 컴파일을 건너뛴 것. `CompilationPipeline.RequestScriptCompilation()` 을 직접 부르고, **로드된 어셈블리에서 새 심볼을 조회해** 확인 |
| **컴파일 에러가 `Error` 로 안 잡힌다** | Unity 컴파일 에러는 `Log` 타입으로 온다. `Types:["Error"]` 0건 ↔ `["All"]`+`FilterText:"error CS"` **11건** |

기존 `C# 수정 반영` 행에도 *"`Assets/Refresh` 는 재컴파일을 보장하지 않는다"* 를 붙였다.

### ➕ 이번에 하나 더 나왔다 — **`Unity_RunCommand` 는 클래스 형식을 요구한다**

톱레벨 문(statement)을 그대로 넣으면 **`CS8805: Program using top-level statements must be an executable`** 로
컴파일이 죽는다. 정해진 형식이 있다:

```csharp
using UnityEngine; using UnityEditor;

internal class CommandScript : IRunCommand      // 🔴 이름 고정 · internal 고정
{
    public void Execute(ExecutionResult result)
    {
        result.Log("...");                       // Debug.Log 말고 result.Log
    }
}
```

`public` 으로 쓰면 *Inconsistent Accessibility*, 이름을 바꾸면 실행 실패다.
`CLAUDE.md` §4 에는 안 넣었다 — **툴 설명에 이미 적혀 있는 것**이라 함정이 아니라 내가 안 읽은 것이다.

## 3. `ProjectSettings/QualitySettings.asset` — 사용자 판단으로 `5` 유지

`D27` 이 품질 레벨을 `0`(Very Low) → **`5`(Ultra)** 로 올려 두고 갔다.
근거는 `PERF.md` §7 에 있다 — *"`Standalone` 기본값이 5 다. Very Low 로 재면 렌더 비용이
실제보다 낮게 나온다."* 측정 환경을 빌드에 맞춘 것이므로 **유지**로 결정됐다 (사용자, 2026-09-03).

🔴 **대가를 같이 적어 둔다: Ultra 는 `vSyncCount: 1` 이다.**
`vSyncCount` 는 프로젝트 전역이 아니라 **품질 레벨마다 따로 저장**되고, 강제로 꺼 주던
`PerfHarness` 는 `D27` 이 지웠다. ⇒ **이제 에디터 플레이는 144 Hz 에 고정된다.**
프레임 타임이 정확히 6.94 ms 에 붙어 있으면 성능이 좋아진 게 아니라 **vSync 를 보고 있는 것**이다.
