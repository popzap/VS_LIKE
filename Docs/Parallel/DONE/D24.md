## 4. 🔴 하다가 발견한 것 — `D20` 커밋은 **Luck 이 카드에 안 뜨는 상태**였다

Import 뒤 씬 diff 가 **딱 한 곳**이었다.

```
propertyPath: allItems.Array.size
-      value: 24
+      value: 25
+ allItems.Array.data[24] → Luck.asset
```

**픽업 배열은 diff 가 0 이었다.** `D20` 의 임시 배선이 CONTENT 의 CSV 와 **값이 완전히 같았다**는
뜻이라 그 자체는 좋은 소식이다. 문제는 `allItems` 다.

| | 실제 |
|---|---|
| `D20` 검증 당시 | 런타임에서 `allItems` **25개 · Luck 포함** 을 읽고 **판정 ③ PASS** 로 기록했다 |
| `D20` 커밋(`a3e9e5c`) | 씬 파일은 **`allItems.Array.size: 24`** — Luck 이 **없다** |
| 직전 커밋(`dc9c03b`) | 24 |
| 지금(D24) | **25** |

⇒ **그 상태로 빌드했다면 행운 패시브가 레벨업 3택에 영원히 안 떴다.**
드랍 확률을 올리는 유일한 수단이 게임에서 사라지는 것이고,
`BonusLuck` 배관은 전부 살아 있으니 **예외도 로그도 안 난다.**

### 왜 놓쳤나

**런타임 값만 보고 판정했고, 디스크에 저장됐는지는 안 봤다.**
런타임 `allItems.Length == 25` 는 "메모리에 들어 있다"는 뜻이지
"씬 파일에 기록됐다"는 뜻이 아니다. 둘 사이에 `File/Save` 가 있다.

🔑 **교훈 — 씬/프리팹을 건드리는 판정은 `git diff` 로 한 번 더 본다.**
런타임 로그는 *"지금 이 세션에서 작동한다"* 까지만 증명한다.
`Import` 나 인스펙터 편집처럼 **직렬화된 파일을 바꾸는 작업**은
커밋 직전에 `git diff <파일>` 에 그 변화가 **실제로 보이는지** 확인해야 한다.
이번엔 `D24` 가 우연히 같은 Import 를 다시 돌려서 드러났을 뿐이다.
