## 무엇을 했나

### ① `ProjectileBase` 에 관통 + 자전 (기존 파일 유일한 수정)

```csharp
[SerializeField] private int   pierceCount = 1;   // 1 = 지금까지의 동작
[SerializeField] private float spinSpeed   = 0f;  // 0 = 지금까지의 동작
private readonly HashSet<EnemyBase> _alreadyHit = new HashSet<EnemyBase>();
```

**두 가지가 걸림돌이었다.**

**(가) 관통은 카운터만으로는 안 된다.** `_pierceLeft--` 만 두면 **한 마리의 콜라이더를
세 번 스치는 것**으로 관통 3이 다 소모된다. 그건 관통이 아니라 연타다.
맞힌 적을 `HashSet` 에 기억하고, `Initialize()`(= 풀에서 꺼내는 지점)에서 비운다.

**(나) 자전을 넣으면 발사체가 나선을 그린다.** 원래 이동은 이랬다:

```csharp
transform.Translate(Vector2.right * (Speed * Time.deltaTime));   // ← Space.Self
```

`Space.Self` 는 **"진행 방향 = 현재 회전"** 이라는 뜻이다. 매 프레임 z 를 돌리면
진행 방향도 같이 돌아 원을 그린다. 그래서 방향을 회전에서 떼어냈다:

```csharp
transform.position += (Vector3)(_direction * (Speed * Time.deltaTime));   // ← 월드
```

🔴 **기존 발사체에게는 수식이 완전히 같다.** `Initialize` 가 회전을 `dir` 로 한 번 굳히고
그 뒤로 아무도 안 건드리므로 `TransformDirection(right) == _direction` 이 항상 성립한다.
(`Translate(Space.Self)` 는 **월드 회전**을 쓰고 **스케일을 무시**한다 — 풀 부모에 붙어 있어도 동일.)
그래도 믿지 않고 **대조군 회귀 검사**를 돌렸다(판정 ③).

### ④ 🔴 호의 실제 반지름은 100px 이 아니라 **107.4px** 이었다

요청서는 *"셀 반지름 = 128px"* 을 전제로 `localScale = Range` 를 쓰려 했다.
코드를 쓰기 **전에** 프레임마다 셀 중심에서의 최대 알파 거리를 재 봤더니 **107.4px** 이다.

```
셀 256px · 바깥 반지름 107.4px · PPU 100  →  scale 1 일 때 1.074 유닛
```

그냥 `localScale = Range` 로 뒀으면 **호가 사거리를 7% 부풀려 보여 준다** —
2 만큼 보이는데 실제로는 2.15 를 베는, 요청서 계약 ②의 정면 위반이다.
`AoeProjectile` 이 이미 쓰던 나눗셈 패턴을 그대로 가져왔다:

```csharp
transform.localScale = Vector3.one * (radius / spriteRadiusAtScaleOne);   // 1.074
```

PPU 를 512 로 올려 해결하는 방법도 있었지만, 그러면 판정 ①이 요구한
프레임 `bounds.size ≈ (2.56, 2.56)` 이 깨진다. **PPU 100 을 유지하고 나눗셈으로 맞췄다.**

### 판정-③ — 대조군을 같이 쏴서 봤다 (이번 작업에서 제일 위험했던 것)

`ProjectileBase` 는 **모든 발사체의 부모**다. 이동 수식을 바꿨으니
총알·화살·파이어볼이 조용히 망가질 수 있었다.

| 발사체 | 소멸 지점 | 어느 적 앞인가 |
|---|---|---|
| `Proj_Bullet` (대조군) | `(7.37, −1.92)` | **1번째** 적 0.63 앞 |
| `Proj_Shuriken` | `(11.37, 1.08)` | **3번째** 적 0.63 앞 |

일렬로 4 간격을 띄운 적 3마리에 같은 조건으로 쐈다.
**총알은 첫 적에서 멈췄고, 수리검은 세 번째 적까지 갔다.**

> 🔑 **`0.63` 은 세 번 반복해서 나온 숫자다** — D9 의 총알·화살도 같았다.
> CircleCollider2D r=0.5 + 고블린 캡슐이 만드는 트리거 기하학의 상수다.

프리팹 필드도 직접 읽었다 — `Proj_Bullet` / `Proj_Arrow` 둘 다 **`pierce=1 spin=0`**.
`.prefab` **파일 자체는 git 상 미변경**이다. 새 필드의 기본값(`= 1`, `= 0f`)이
직렬화되지 않은 기존 프리팹에 C# 초기값으로 그대로 먹었다.

### 판정-④ — "3마리를 뚫었다"와 "1마리를 3번 때렸다"를 어떻게 갈랐나

HP 는 `protected` 라 밖에서 못 읽는다. 대신 **소멸 위치**로 갈랐다.

- 한 마리를 3번 때렸다면 → **첫 적 앞**에서 관통이 소진돼 멈췄어야 한다
- 실제 소멸은 **세 번째 적 앞** → 세 마리를 각각 한 번씩 맞혔다는 뜻이다

`_alreadyHit` 이 없었다면 첫 적에서 멈췄을 것이다. 위치가 곧 증거다.
덤으로 소멸 시 `rotZ = 139.4°` — **자전 중인데도 직선으로 날아갔다** (나선 아님).

### 판정-⑦ — 봤다 (0.2초짜리 애니메이션을 한 장으로 찍는 법)

호는 6프레임 **0.2초**라 그냥 찍으면 한 프레임밖에 안 잡힌다.
그래서 **6프레임을 전부 플레이어 중심에 겹쳐 세워** 부채꼴 전체를 한 장으로 만들었다.
그 위에:

- **빨간 점 13개** — 플레이어에서 정확히 **반지름 2.0** 위, +90°~−90°
- **초록 점 1개** — 플레이어 자리

`Unity_Camera_Capture(cameraInstanceID: -1602)` 로 **게임 카메라**를 찍었다.
(인자 없이 부르면 씬 뷰가 찍힌다.)

**화면에서 확인한 것:**

1. 부채꼴의 **오목한 안쪽이 초록 점을 감싼다** → 회전 중심 = 플레이어 ✅
2. 초록 점을 지나는 **수평선에 대칭** → 중심이 위아래로 안 밀렸다 ✅
3. 바깥 **흰 테두리가 빨간 점들 위에 정확히 얹혀** 있다 → 바깥 끝 = 사거리 2.0 ✅
4. 부채꼴이 **오른쪽 반쪽에만** 존재 → z 회전만으로 방향이 결정된다 ✅

산술로도 맞는다: `1.074 × 1.862 = 2.000`.

## 같이 나온 것

**임시 오브젝트 이름 접두어가 겹쳤다.** 정리 코드가 `name.StartsWith("D10_B")` 였는데
레인 B 의 적들과 풀에 있던 `D10_Bullet` 이 **둘 다 걸려** 7개가 지워졌다.
파괴된 GameObject 가 `Proj_Bullet` 풀 큐에 남아 다음 `Get()` 에서
`MissingReferenceException` 이 날 상태였다 — 다만 그 플레이 세션엔 장착 무기가 없었고
`MainMenu` 상태였으며 플레이 종료로 풀이 초기화되므로 **실피해는 없었다.**

🔑 **임시 오브젝트 이름은 정리 접두어가 서로 먹지 않게 지을 것.**
