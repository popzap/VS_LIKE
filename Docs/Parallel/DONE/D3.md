## 왜 했나

**정상 플레이로는 검증이 사실상 불가능했다.**
무기 진화는 Lv5 무기 + Lv3 건물, 직업 승급은 그 위에 조건이 더 붙는다.
한 번 확인하려고 매번 처음부터 몇 분씩 굴려야 했고, 그래서
`TODO.md` §1 의 미검증 항목들이 계속 쌓이기만 했다.

## 설계 결정 3가지

### ① 캔버스 UI 가 아니라 IMGUI(`OnGUI`)

셋 다 실익이다.

| 이유 | 내용 |
|---|---|
| 배선량 | 아이템 20종 + 진화 목록을 스크롤뷰 + 행 프리팹으로 씬에 만들면 **배선이 본 게임보다 커진다** |
| 폰트 | TMP 는 I-60 이후 **Static 115자** — 문자표에 없는 글자가 빈칸이 된다(B4). IMGUI 는 유니티 내장 폰트라 이 제약을 안 받는다 |
| 정렬 순서 | 캔버스 `sortingOrder` 싸움(I-50)에 끼어들지 않는다 |

못생긴 건 개발 도구라 감수한다.

### ② 씬에 넣지 않는다 — `[RuntimeInitializeOnLoadMethod]` 로 자동 생성

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
private static void AutoCreate()
{
    var go = new GameObject("[DevPanel]");
    go.AddComponent<DevPanel>();
    DontDestroyOnLoad(go);
}
```

씬에 오브젝트로 두면 이 클래스가 `#if` 로 잘려 나가는 **릴리즈 빌드에서 "Missing script" 로 남는다.**
런타임 생성이면 **`.unity` 파일에 흔적이 0** 이라 병렬 세션에서 씬 충돌도 안 만든다.
(그래서 `BOARD` 에 적어 뒀던 `SampleScene.unity` 는 결국 **안 건드렸다.**)

`DontDestroyOnLoad` 인 이유 — 이 콜백은 **게임 시작 때 한 번만** 돈다.
Retry 는 씬을 다시 로드하므로(I-17) 그냥 두면 재시작 후 패널이 사라진다.

### ③ 🔑 치트가 게임 로직을 우회하지 않는다

**우회하면 거기서 나온 상태를 신뢰할 수 없다.** 두 군데서 지켰다.

- **슬롯 상한을 지킨다** — `lum.CanAcquire(item)` 이 false 면 `+` 버튼이 비활성이고 `slot full` 이 뜬다.
  여기서만 뚫으면 `LevelUpManager.ApplyItem` 주석이 경고하는
  *"인벤토리에는 있는데 무기는 없는"* 유령 상태가 만들어진다 — **치트로 만든 유령은 버그처럼 보인다.**
- **"레벨 내리기" 경로를 새로 만들지 않는다** — 게임에 그 개념 자체가 없다.
  이미 검증된 공개 API만 조합한다:

```csharp
private static void SetLevel(LevelUpManager lum, ItemData item, int target)
{
    target = Mathf.Clamp(target, 0, item.MaxLevel);
    lum.RemoveItemFull(item);                                   // 배치 인스턴스 + 대기열 + 해금까지 전부
    for (int i = 0; i < target; i++) lum.ApplyItemFromShop(item);
}
```

## 쓰는 법

**백틱(`` ` `` — 숫자 1 왼쪽)** 으로 열고 닫는다. 열려 있는 동안 `Time.timeScale = 0`.

> 🔴 **`F1` 은 못 쓴다** — 유니티 에디터가 "Unity 매뉴얼 열기"로 물고 있어서 브라우저가 뜬다.

| 줄 | 있는 것 |
|---|---|
| 플레이어 | `State` · `Class` · `Lv (xp/next)` · `G` + 버튼 `Level +1` `Gold +100` `Full Heal` |
| 아이템 | Weapon / Passive / Building 별로 `(보유/슬롯)` 헤더 + 행마다 `-` `+` `Max` `X` |
| 진화 | `Ready Evolutions` — 조건이 찬 무기 진화 · 직업 승급을 버튼으로 |

`Level +1` 은 `exp.CollectXp(exp.XpToNext)` 라 **정확히 한 번** 레벨업한다 → 레벨업 카드가 뜬다.

닫을 때 `timeScale` 은 **열 때 값으로 되돌린다.** 무조건 1 로 되돌리면
ESC 일시정지 위에서 열었다 닫았을 때 일시정지 화면 뒤에서 게임만 다시 흐른다.
씬이 바뀔 때를 대비해 `OnDisable` 에서도 되돌린다 — 안 하면 `timeScale` 이 0 인 채 남아
**게임이 멈춘 것처럼 보인다.**

## 남은 것

- 🟡 **`OnGUI` 가 실제로 화면에 그려지는 모습은 눈으로 확인 안 됐다.**
  MCP 로 백틱 입력을 주입해 `Time.timeScale == 0` 을 외부 증거로 삼으려 했으나
  **입력이 게임에 도달하지 않는다** — 게임 뷰에 포커스가 없어서다. **도구의 한계이지 코드 문제가 아니다.**
  (`InputSystem.QueueStateEvent` 뒤에 `InputSystem.Update()` 를 직접 부르면 전이가 그 자리에서
  소비돼 다음 `MonoBehaviour.Update` 에는 `wasPressedThisFrame` 이 안 남는다. 큐만 넣는 방식도 실패.)
  → **사용자가 플레이해서 백틱을 한 번 눌러 보는 것으로 판정한다.**
- ⚠️ **진화 버튼은 제단 근접 판정을 건너뛴다.** 조건이 맞으면 그 자리에서 진화한다.
  따라서 **"건물 앞에서 `E` 를 누르는 경로"는 이걸로 검증되지 않는다** (`TODO.md` §1 에 그대로 남는다).
