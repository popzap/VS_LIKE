## 4. 🔴 ①이 왜 틀렸나 — 10층 중 2.4칸은 수입이 0이다

10층이지만 **추첨은 8칸뿐이다.** 0층은 항상 노말, 9층은 항상 보스로 고정이다.
1~8층만 `0.50 / 0.20 / 0.15 / 0.15` 로 뽑는다.

| 노드 | 기대 | 전투 | 클리어 보상 |
|---|---:|:---:|---:|
| 노말 | **5.0** | ✅ | 8 |
| 엘리트 | **1.6** | ✅ | 20 |
| 상점 | **1.2** | ❌ | **0** |
| 이벤트 | **1.2** | ❌ | **0** |
| 보스 | **1.0** | ✅ | 60 |

⇒ `5.0×8 + 1.6×20 + 60 = **132G**`.

🔑 **"상점 노드도 8G 주겠지"로 읽히게 생겼다.** `OnWaveCleared` 의 보상 `switch` 가
`_ => normalClearReward` 로 끝나기 때문이다. 그런데 `OnWaveCleared` 는 `WaveManager` 만 부르고
`StartWave` 는 **노말/엘리트/보스에서만** 돈다(`OnStageNodeSelected:247-275`).
**그 기본 갈래에는 애초에 도달하지 않는다.** `switch` 만 보고 판단했으면 156G 를 그대로 믿었다.

## 5. 🔴 가격을 **내리는 게 아니라 올린** 이유 — 적 1마리당 1G 바닥

처음엔 "수입이 너무 크니 `CurrencyDrop` 을 깎자"가 자연스러워 보였다. 그게 불가능하다.

`GameManager.GrantGold` — `AddRunGold(Mathf.Max(1, RoundToInt(baseAmount * mult)))`

**어떤 적도 0G 을 주지 않는다.** 한 판 처치 수가 약 **551마리**이므로
`Enemies.csv` 를 전부 `1` 로 깎아도 **수입이 551G 밑으로 안 내려간다.**
현재 수입이 ≈1,177G 이니 **CSV 로 줄일 수 있는 폭은 기껏해야 절반**이다.

⇒ **균형은 가격 쪽에서 맞출 수밖에 없다.** 그래서 10배로 올렸다.

> 처치 수·처치 골드는 `Waves.csv` 를 코드대로 계산해서 냈다 —
> `SpawnRoutine:156-169` 는 **첫 마리를 `StartTime` 에 바로** 뿌리고(선대기 없음)
> 시간창을 넘기면 남은 마리수를 버린다. 즉 `min(마리수, ⌊창/간격⌋+1)` 이다.
> **손으로 센 첫 표는 `+1` 을 빼먹어 1~3마리씩 적었고**, 스크립트로 다시 세서 고쳤다.

## 6. 요청이 묻지 않은 게 더 컸다 — 배수구가 모자란다

가격을 10배로 올린 **뒤에도** 남는다.

| | 값 |
|---|---:|
| 런 수입 | ≈ **1,177G** |
| 최대 지출 (상점 1.2회 × 3칸 × 평균 75G + 리롤) | ≈ **400G** |

런 골드의 지출처는 **상점·상점 리롤·레벨업 리롤 셋뿐**이다(건물 설치는 무료 — `SpendRunGold` 호출처를 전수 확인).
**절반 넘게 소멸한다.** 이건 가격 문제가 아니라 **배수구 문제**다.

🔑 **가격을 더 올리는 건 답이 아니다.** 상점이 1.2번밖에 안 열리므로
아이템 하나가 한 노드 수입을 통째로 먹는 값이 돼야 하고, 그러면 "한 개 사고 끝"이 된다.

그래서 **가격은 여기서 멈추고**, 대신 `StageMapManager` 의 층 수·가중치 6줄을
`Economy.csv` 로 **옮겨** 뒀다 — 코드 기본값 그대로라 **첫 Import 는 아무것도 안 바꾼다.**
런 골드 예산 전체가 이 가중치에 매달려 있는데 **코드 안에 숨어 있어서 돌릴 수가 없었다.**

판정과 고치는 순서는 `TUNING.md` **§2-H** 에 적었다. 종료 로그의 **남은 런 골드 M** 하나로 갈린다 —
**M ≤ 300 이면 지금 값이 맞고, M ≥ 600 이면 배수구를 늘린다**(①`weightShop` ②`shopSlotCount` ③새 소비처).
①②는 **CSV 라 코드가 필요 없다.**

## 10. 남긴 것

- **"인스펙터 값이라 못 고친다"는 말도 실물로 확인한다.** 요청-18 이 해금 비용을 그렇게 불렀는데
  `Economy.csv` 에 이미 있었다. 남이 그은 경계선을 그대로 믿으면 **내 권한을 스스로 반납한다**
- **바꿀 수 없는 하한을 먼저 찾으면 방향이 반대로 뒤집힌다.** `Max(1,..)` 을 못 봤으면
  "드랍을 깎자"로 갔다가 551G 벽에 부딪혔을 것이다. **줄일 수 있는 최소치를 먼저 재고 나서 방향을 정한다**
- **`switch` 의 기본 갈래는 "도달한다"는 뜻이 아니다.** `_ => normalClearReward` 는
  상점 노드도 8G 를 받는 것처럼 읽히지만 **호출 자체가 안 일어난다.**
  분기표를 읽을 땐 **누가 부르는지**를 같이 봐야 한다
- **요청받은 축으로 못 푸는 문제가 있다.** 배수구가 1.2회×3칸인데 가격만으로는 균형이 안 맞는다.
  값을 억지로 우겨 넣는 대신 **숨어 있던 축(가중치)을 CSV 로 꺼내 놓고 판정을 넘겼다** —
  `C26` 에서 소환사의 약점을 스탯 대신 슬롯으로 옮긴 것과 같은 판단이다
- **손으로 센 수는 코드로 다시 센다.** 첫 표는 `SpawnRoutine` 의 "첫 마리는 즉시" 를 놓쳐
  6줄 전부 1~3마리씩 적었다. 표가 그럴듯해 보일수록 스크립트로 재는 게 싸다
