## 2. 🔴 `layerSpawnGrowth` 만 올린 이유 — 유일한 손잡이였다

`PERF.md` §0 이 이 프로젝트를 이렇게 연다:

> *"뱀서라이크는 화면에 적이 수백 마리 뜨는 것이 장르의 정의다."*

그런데 `Waves.csv` 의 `MaxAlive` 최댓값은 **130** 이다. `C28` 에서 확인한 것도 있다 —
**130 에 성능 근거는 없었다.** 난이도 곡선으로 정한 값이고 성능은 `D27` 이 처음 쟀다.

⇒ **층 스케일링이 `Waves.csv` 를 안 건드리고 "수백"에 닿는 유일한 길이다.**

| 성장률 | 9층 최댓값 | |
|---:|---:|---|
| 0.08 (DEV) | 223 | 장르 기준엔 모자라다 |
| **0.14** | **293** | ✅ 채택 |
| 0.17 | 328 | 더 가도 되지만 여유를 남긴다 |

**내가 이미 잰 성능이 선을 그어 준다** (`PERF.md` §8-4 · `C28`):
적 130 = 프레임의 **1 %** · 400 = **7 %** · 800 = **40 %**(붕괴).

🟢 **293 은 400 아래라 `B8`(무리 분리 버퍼 64칸) 재판단이 필요 없다.**
`maxAliveCeiling` 은 **320** — 지금 최대(293) 위, 위험선(400) 아래.
🔑 **천장의 쓸모는 "지금 걸리는 것"이 아니라 "나중에 누가 `Waves.csv` 를 올렸을 때
조용히 400 을 넘지 않는 것"이다.** 그래서 안 걸리는 값이 맞다.

## 3. 🟡 값을 유지하면서 찾은 것 — 방어력이 피해 성장을 무력화한다

`layerDamageGrowth 0.06` 은 9층 `×1.54`. 고블린 8 → 12.3.
그런데 `PlayerStats.cs:316` 이 `Mathf.Max(1, raw - Final.Armor)` 다.

| 방어 | 9층 고블린 피해 |
|---:|---:|
| 0 | 12.3 |
| 2 (전사) | 10.3 |
| 11 (전사 + 패시브 Lv5 + 메타) | 🔴 **1** (바닥값) |

**선형 +6 %/층으로는 정액 방어를 절대 못 따라잡는다.**
🔑 다만 **그건 빌드 선택이지 이 값의 결함이 아니다** — 방어에 레벨업 5칸을 쓴 대가다.
고치려면 성장률이 아니라 **`Armor` 를 정률로 바꾸는 설계**이고, 그건 지금 할 일이 아니다.
