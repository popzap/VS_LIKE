## 2. 🟢 먼저 확인한 것 — **둘 다 코드가 필요 없다**

요청을 쓰기 전에 **꽂을 자리가 있는지** 봤다. 없으면 그림 요청이 아니라 **UI 신설 요청**이 되기 때문이다.

| | 상태 |
|---|---|
| `ShopUI` | `npcDialogueText` 는 있는데 **초상 `Image` 슬롯은 없다** |
| `MainMenuUI` | 타이틀·재화·버튼 4개 — **배경 `Image` 슬롯 없다** |

⇒ 둘 다 **정적 이미지 하나**라 씬에 `Image` 오브젝트를 놓고 스프라이트만 꽂으면 된다.
`[SerializeField]` 도 새 스크립트도 **필요 없다.** 요청 §0 에 그렇게 적었다.

🔑 **"슬롯이 없다"가 곧 "코드가 필요하다"는 아니다.** 바뀌지 않는 그림은 참조를 들 이유가 없다.
확인 안 하고 넘겼으면 DEV 가 안 해도 될 코드 작업을 했을 것이다.

## 3. 🔑 그림 자체보다 중요했던 것 둘

### ① 상점 주인의 성격은 **이미 정해져 있었다**

`ShopUI.cs:47-55` 에 대사 5줄이 이미 있다:

> *"Only the finest goods here."* · *"Today's bargain! Buy quick, or the next customer will."*
> *"Looking for something? I can help. **For a price.**"*

⇒ **너스레 떠는 장사꾼**이다. 무섭거나 신비로운 쪽이 아니다.
"상인을 그려 달라"고 넘기면 후드 쓴 수상한 노인이 나올 수 있고, 그러면 **대사와 그림이 서로 어색해진다.**
그래서 **대사를 그대로 인용해서** 넘겼다.

같이 못 박은 것 둘:
- 🔴 **무기를 들리지 말 것** — 들면 직업 초상처럼 보인다. NPC 는 플레이어와 한눈에 갈려야 한다
- **색은 보라·자주 계열** — 직업 10종의 주조색(주황·청록·검정·은/빨강)과 안 겹치는 대역을 재서 골랐다

### ② 배경은 **어두워야 한다 — 그게 유일한 기능 요구다**

`MainMenuUI` 는 타이틀·재화·버튼 4개가 **전부 글자**다. 배경이 밝으면 **글자가 안 읽힌다.**
취향이 아니라 판정이라 **숫자로 못 박았다** — *중앙 세로 띠 평균 밝기 **≤ 0.25***.
가운데를 비워 달라고도 했다(거기 타이틀과 버튼이 얹힌다).

⚠️ 정사각형으로 나올 경우도 적었다 — `Preserve Aspect` 를 켜고 뒤에 단색 판을 깔 것.
늘려 채우면 **그림이 찌그러진다.**

## 4. ⚠️ 지난 함정 4개를 표로 붙였다

`C28`(직업 그림) 에서 실제로 밟은 것들이다. 같은 자리를 두 번 밟지 않으려고 요청 §4 에 넣었다.

| 함정 | 해법 |
|---|---|
| 알파가 전부 255 (회색 배경이 RGB 에) | `GenerateAsset(command:"RemoveImageBackground", targetAssetPath:<png>)` — `a85cc9f` |
| 생성물 PPU 가 텍스처 크기로 박힌다 | 규약대로 손볼 것 |
| **빈 파일이 그대로 넘어옴** (색 1개) | 색 수를 세 볼 것 |
| 반려가 stale 이 된다 | **`mtime` 을 같이 적기로 약속** |

**판정 ①③④(알파 · 배경 밝기 · 크기감)는 내가 다시 잰다**고 적었다 — `C28` 때와 같은 방식이다.

- 🔴 **요청을 쓰기 전에 "꽂을 자리"부터 본다.** 슬롯이 없다고 코드가 필요한 게 아니었다 —
  바뀌지 않는 그림은 참조를 들 이유가 없다. 이걸 안 봤으면 **DEV 가 안 해도 될 코드를 짰다**
- 🔑 **애셋 요청은 "무엇을 그릴까"가 아니라 "무엇과 맞아야 하나"로 쓴다.**
  상점 주인의 답은 내 취향이 아니라 **이미 쓰여 있던 대사 5줄**에 있었다.
  코드를 읽으니 캐릭터가 이미 정해져 있었다
- **"어두웠으면 좋겠다"는 요청이 아니다.** 밝기는 글자 가독성이라는 **기능**에 걸려 있으므로
  숫자(≤ 0.25)와 측정 위치(중앙 세로 띠)로 바꿔서 넘겼다. 그래야 통과/실패가 갈린다
