## 왜 했나

D10(관통·근접)과 D11(신관·장판)은 **코드와 프리팹만** 만들어 놓은 상태였다.
`Assets/Game/Balance/*.csv` 에 줄이 없으면 **게임에는 존재하지 않는다** — 레벨업 3택에도
상점에도 안 나온다. CONTENT 가 요청-9(C12)와 요청-10(C15)으로 그 줄들을 채웠고,
둘 다 **같은 CSV 3장**(`Weapons` · `Items` · `SceneWiring`)을 건드렸다.

🔴 **그래서 Import 는 1회다.** 두 요청을 따로 처리할 수 없다 — 먼저 도는 Import 가
나중 요청의 줄까지 이미 반영해 버린다. 판정만 두 벌로 나눠 돌렸다.

### 판정-⑤ — "후보 풀에 있다"가 아니라 "실제로 뽑힌다"

풀에 있는지만 보면 가중치가 0이어도 통과한다. **60회 추첨(180장)** 을 돌려 실물을 셌다.

```
Shuriken 등장:  4장 · 6장 · 8장 · 11장   (4회 반복, 매번 나왔다)
```

`LevelUpManager.PickCandidates` 는 비복원 가중 추첨이고 `OwnedWeight = 2f` 다.
소지 중이면 오히려 잘 나오므로 위 편차는 정상 범위다.

### 판정-⑦ — 관통이 실제로 먹는지, 배치를 갈라서 쟀다

`EnemyBase.Reposition()` 으로 적을 **뭉치게 / 흩어지게** 만들고 발사체당 명중을 비교했다.

```
흩어짐   hitsPerProj = 0.91
뭉침     hitsPerProj = 3.10      ← 프리팹 pierceCount: 3 과 일치
```

**3.4배 차이.** 관통값을 코드가 아니라 **실측으로** 되짚은 셈이다.

🔴 **이 숫자를 처음엔 5.00 으로 잘못 쟀다.** 프리팹 상한이 3인데 5가 나올 수 없으니
계측이 틀린 것이고, 원인은 `PlayerStats.TakeDamage` 도 **피해 팝업을 띄운다**는 것이었다
(`PlayerStats.cs:258`). 적 18마리가 붙어 있으면 **플레이어가 맞는 팝업**이 "적 명중"으로 섞인다.
플레이어로부터 2.5유닛 밖의 팝업만 세도록 고쳐 3.10 이 나왔다.

## CONTENT 에게 돌려줄 "느낌" 답

### 요청-9 Q1 — 검이 얼마나 약한가

**맞기만 하면 안 약하다.** Lv5(사거리 2.50 · 쿨 0.70 · 3연타 · 40딜)로 14초에 **14킬** —
같은 조건 수리검 Lv5 의 16킬과 사실상 동급이다.

🔴 **문제는 세기가 아니라 "존재하느냐"다.** 가만히 선 플레이어에게는 적이 **오지 않는다.**
프로브 초기 측정에서 가장 가까운 적이 **4.67유닛**에 머물러 검은 **6초 동안 0회** 휘둘렀다
(`MeleeWeapon.Fire()` 는 사거리 안에 아무도 없으면 즉시 반환한다).
카이팅하는 실제 플레이에서 **검은 자주 놀 것이다.** 사거리를 올릴지, 접근 유인을 줄지가 진짜 질문이다.

### 요청-9 Q2 — 수리검이 떼거리에서 과한가

**그렇다, 뚜렷하게.** 0.91 → **3.10** (3.4배).
Lv5 기준 상한은 초당 4발 × 관통 3 × 23딜 ≈ **276 DPS**. 뭉친 판에서만 나오는 값이라
"몰아넣고 쏜다"는 플레이가 강하게 보상된다 — 의도라면 그대로 둘 만하다.

### 요청-9 Q3 — 검 효과음

**확인됨.** `MeleeWeapon.cs:52` 가 아직 `SfxId.WeaponFire`(총소리)를 쓴다. 베는 소리가 없다.

### 요청-10 Q3 — Lv5 에서 장판이 화면을 덮는가

**안 덮는다.** 웅덩이 하나가 대략 화면 세로의 1/4. 2개가 동시에 떠도 눈에 띄는 정도지
시야를 잡아먹지는 않는다 — **`ProjectileSize` 를 아직 줄일 필요 없다.**

### 요청-10 Q4 — 🔴 장판이 적을 한 번도 안 만나는 판이 있는가

**있다. 눈으로 봤다.** 캡처에서 살아 있던 장판 2개 중 **하나는 안에 적이 0마리**였다.
`FieldWeapon` 은 조준하지 않고 주변 무작위 좌표에 까는 물건이라 **구조적으로 빗나간다.**
헛방 비율이 문제가 되면 (가) 반경을 줄여 플레이어 발밑에 붙이거나
(나) 개수를 늘려 확률로 덮는 두 방향이다.

## 같이 나온 것

**피해 팝업은 플레이어가 맞을 때도 뜬다.** `PlayerStats.cs:258` 과 `EnemyBase.cs:392` 가
같은 `DamagePopupManager.Instance.Show` 를 부른다. 팝업 수로 "적 명중"을 세면 **접촉 피해가 섞인다.**
거리로 걸러야 한다.

**가만히 선 프로브에게 적은 근접 사거리까지 오지 않는다.** 근접 무기를 재려면
`EnemyBase.Reposition()`(public)으로 **직접 몰아 세우는 수밖에 없다.**

**레벨업 패널이 측정을 얼린다** (D11 에 이어 두 번째). `timeScale = 0` 이라
긴 프로브에는 `if (gm.CurrentState == GameState.LevelUp) _lum.HidePanel();` 워치독이 사실상 필수다.
단 `HidePanel` → `OnLevelUpCompleted` → `ChangeState(_stateBeforeLevelUp)` 이므로
**웨이브에 들어간 뒤에** 열고 닫아야 상태가 어긋나지 않는다.

**프리팹 이름이 거짓말을 한다.** `Shuriken` 은 `Weapon_Sword.prefab`(=`ProjectileWeapon`)을 쓰고
`Sword` 는 `Weapon_Melee.prefab`(=`MeleeWeapon`)을 쓴다. 이름은 유물이다.

**풀링 객체의 상승엣지 계수는 안전하다** — 발사체 0.75s · 팝업 0.5s · 호 0.2s 로
전부 한 프레임보다 길어, 60fps 폴링에서 반납 후 재획득이 "계속 있었음"으로 안 보인다.
