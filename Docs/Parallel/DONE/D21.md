## 왜 했나

문어 소환수의 촉수 링(`Fx_TentacleLash`)이 `m_SortingOrder: 20` 이라
**플레이어보다 앞에 그려졌다.** D16 에서 "촉수가 기사 스프라이트 위를 지나간다"를
눈으로 확인해 놓고 [`REQ/CONTENT.md`](../REQ/CONTENT.md) 요청-10 ③ 으로 넘긴 문제다.

DEV 는 두 가지를 제안했었다.

| 안 | 무엇 | CONTENT 판정 |
|---|---|---|
| A | `Range` 를 링이 플레이어를 안 삼킬 만큼 줄인다 | ⛔ **반려** — Lv1 넓이의 44% 가 된다 |
| B | `offsetDistance` 를 2.2 로 늘려 문어를 멀리 세운다 | ⛔ **반려** — 플레이어에게 달라붙은 적을 링이 못 잡는다 |

### 🔑 CONTENT 가 낸 대조군이 문제의 성격을 바꿨다

> 검 아크(`Fx_SwingArc`)는 **똑같이 order 20 이고 플레이어 위에서 바로 터지는데
> 기사를 0.00% 덮는다. 중앙이 비어 있어서다.**

⇒ **기하 문제가 아니라 합성 문제다.** 고칠 곳은 `Range` 도 `offsetDistance` 도 아니고
**정렬 순서 한 줄**이다. A·B 는 둘 다 게임성을 깎는 값을 건드리고 있었다.

## 무엇을 했나

```yaml
# Assets/Prefabs/Fx_TentacleLash.prefab:83
  m_SortingOrder: -5      # was: 20
```

`git diff --stat` = **1 file · 1 insertion · 1 deletion.** 그게 전부다.

`-5` 인 근거는 프로젝트에 이미 있던 선례다 — `Proj_ToxinField`(독 장판)가 `-5` 로
"바닥에 깔리지만 타일보다는 앞" 자리를 쓰고 있다. 새 층을 만들지 않았다.

프로젝트 정렬 순서 지도:

```
바닥 타일 -100  <  촉수·독장판 -5  <  플레이어·적·투사체 0  <  픽업 1 …  검 아크 20
```

### 🔴 일부러 D19 와 분리했다

CONTENT 가 경고했다 — **"둘을 같이 바꾸면 어느 쪽이 들었는지 모른다."**
D19(공전→기차)도 문어가 서는 자리를 바꾸므로 정확히 그 상황이었다.
그래서 D19 커밋에 이 한 줄을 **넣지 않고** 별도 이슈로 쳤다.

`Fx_SwingArc.prefab:83` 은 **`20` 그대로 두었다** — CONTENT 가 ⚠️ 로 못박은 대로.

## 어떻게 확인했나

### 잰 방법 — 🔑 같은 프레임을 두 번 렌더해서 뺐다

플레이어를 `(3.71, 1.08)` 에 고정하고(`PlayerController` 비활성 + 속도 0),
문어를 **Lv3**(`Range` 2.2)으로 올린 뒤, 촉수를 **손으로 세웠다** —
`SwingArcFx` 를 끄고 `Instantiate` 해서 코루틴 없이 프레임을 멈춰 놓았다.
그래야 **6프레임을 한 장씩** 잴 수 있다.

그 상태에서 카메라를 `RenderTexture`(640×360)로 세 번 찍는다:

| 장 | 무엇 |
|---|---|
| `S1` | 촉수 없음 · 플레이어 있음 — **기준선** |
| `S0` | 촉수 없음 · 플레이어 **없음**(`SpriteRenderer` off) |
| `A` / `B` | 촉수 있음 · order **`20`** / **`-5`** |

- **기사 실루엣 마스크** = `S1` 과 `S0` 이 다른 픽셀 = **336px**
- **촉수 잉크** = `A`(또는 `B`)가 `S1` 과 다른 픽셀 → 실제로 화면에 그려진 촉수
- **기사 가림** = 마스크 안에서 `S1` 과 달라진 픽셀 → 촉수가 기사를 지운 양

문어 본체는 D19 기차의 **1번칸**이라 실좌표 `(2.51, 1.08)` — 플레이어에서 1.20 뒤다.

### 최악 조건 — 적을 링 위에 빙 둘러 세웠다

`-5` 는 적(order `0`)보다도 뒤다. CONTENT 가 ④ 로 물은 게 이거다.
그래서 적 8마리를 링 둘레(반지름 2.2)에 **일부러 배치**하고 다시 쟀다.

```
적 12마리 중 8마리를 링 위로 · 적 order=0
잉크 7826 -> 7706 · 손실 120px (1.5%)
```

플레이어만 있을 때(107px)보다 **13px 더 잃었을 뿐이다.** 폴백 `-1` 은 필요 없다.

### 눈으로도 봤다

같은 자리·같은 프레임(`_5`, 예전에 12.2% 를 덮던 최악 프레임)을
**order 만 바꿔** 게임 카메라로 두 장 찍었다.

| order | 보이는 것 |
|---|---|
| `20` (대조군) | 촉수 한 가닥이 **기사의 허리·다리를 가로지른다** |
| `-5` (지금) | 그 가닥이 **기사 뒤로 넘어갔다.** 실루엣 온전 · 촉수도 그대로 읽힌다 |

### 판정 — CONTENT 가 적은 기준 4개

| # | 기준 | 결과 |
|---|---|---|
| ① | 프리팹 `-5` · 검 아크 `20` 유지 | ✅ Unity 직접 보고 — `Fx_TentacleLash order=-5` / `Fx_SwingArc order=20` / `Proj_ToxinField order=-5` |
| ② | 🔴 **Lv3 이상에서 기사의 얼굴·상반신이 보이나** | ✅ **93px → 0px.** 최악 프레임 12.2% → **0** |
| ③ | 바닥(`-100`)에 파묻히지 않나 | ✅ 잉크 7829 → 7722, 손실 **1.37%** |
| ④ | 적(`0`) 위에서 읽히나 (안 되면 `-1`) | ✅ 적 8마리 최악 배치에서도 손실 **1.5%**. `-1` **불필요** |
| ⑤ | 컴파일 에러 0 · 콘솔 경고/에러 0 | ✅ 플레이 종료 후 **Log 7건뿐**, Warning/Error **0** |

**정리 확인** — 임시 오브젝트(`__D21Lash` · `__D21Cap`) **전부 삭제** ·
`PlayerController` **원복** · 링에 세운 적 8마리 **원위치 복귀** ·
`RenderTexture`/`Texture2D` 해제 · 임시 `.cs` 파일 **0개**(`RunCommand` 만 썼다) ·
씬(`.unity`) **미변경**(`git status` = 프리팹 1개뿐) · 플레이 종료.

## 알게 된 것

### 🔑 CONTENT 의 예상 대가(3.7~4.2%)가 실측 1.37% 였다 — **틀린 게 아니라 전제가 바뀌었다**

CONTENT 는 요청-16 에서 "촉수 자기 잉크 3.7~4.2% 를 잃는다"고 예상했다.
실측은 **1.37%.** 이유는 **D19 다.**

소환수가 공전을 그만두고 꼬리처럼 따라오게 되면서 문어가 플레이어 **1.20 뒤**로 물러났다.
링 중심과 기사 중심이 어긋난 만큼 겹치는 면적이 줄었다.
CONTENT 의 3.7~4.2% 는 **공전 시절(중심이 거의 일치) 기준**이었다.

⇒ **예측이 어긋났을 때 "누가 틀렸나"보다 "전제가 언제 바뀌었나"를 먼저 본다.**
여기서는 하루 전 커밋(D19)이 답이었다.

### 값을 찍지 말고 **차이를 찍는다** (D17·D18·D19 와 같은 수법)

"기사가 93px 가려진다"만으로는 심각한지 알 수 없다. 옆에 **실루엣 336px** 을 같이 두니
12.2% 라는 판정이 한 줄로 끝났다. 그리고 order `20`/`-5` 를 **같은 프레임에서 두 번 렌더**하니
"좋아 보인다"가 아니라 **93 → 0** 이 나왔다.

### 대조군이 문제의 **성격**을 바꿀 수 있다

DEV 가 낸 A·B 는 둘 다 "링이 너무 크다 / 문어가 너무 가깝다"는 **기하 가설**이었다.
CONTENT 가 "검 아크는 같은 order 20 인데 0.00% 덮는다"를 들이대자
가설 자체가 무너지고 **합성 문제**로 재분류됐다 — 그리고 한 줄로 끝났다.
**고칠 값을 찾기 전에, 같은 조건에서 안 아픈 사례가 있는지 먼저 찾는다.**

### `protected` 필드는 `RunCommand` 에서 안 보인다

`WeaponBase.Data`/`Level` 이 `protected` 라 `CS0122` 로 컴파일이 막혔고,
`[SerializeField]` 도 아니라 `SerializedObject.FindProperty` 도 `null` → NRE 였다.
`System.Reflection` 은 `CLAUDE.md` 가 금지한다.

**해법은 public 우회로였다** — `AssetDatabase.LoadAssetAtPath<ItemData>("…/SummonOctopus.asset")`
→ `.WeaponRef`(public) · `.CurrentLevel`(public) · `.GetRange(lv)`(public).
`SwingArcFx.frames` 도 private 이라 **스프라이트 시트에서 직접 6장을 로드**했다
(`AssetDatabase.LoadAllAssetsAtPath`). 컴포넌트를 안 건드리고 같은 그림을 얻는다.
