## 왜 했나

지금까지의 무기는 전부 **플레이어를 기준점**으로 판정했다. 소환수는 처음으로
**기준점이 플레이어가 아닌 무기**다 — 저 혼자 떨어져 서서, 저 자리에서 적을 찾고,
저 자리에서 때린다. 그림 5장은 CONTENT 가 이미 다 그려 놨고 코드·프리팹만 비어 있었다.

⚠️ **CSV 는 이번에 넣지 않았다.** 요청-11 이 못 박은 대로 — 프리팹 경로가 없으면
CONTENT 가 `Weapons.csv` 를 쓸 수 없기 때문이다. 이 작업의 산출물이 곧 그 경로다.

### ② 새 스크립트 2개

| 파일 | 무엇 |
|---|---|
| `Assets/Scripts/Weapon/SummonWeapon.cs` | `WeaponBase` 상속. 몸통을 낳고·따라다니게 하고·몸통 자리에서 싸운다 |
| `Assets/Scripts/Weapon/SummonVisual.cs` | 16프레임 루프 재생기 + `flipX` |

> ℹ️ 요청서의 경로 `Assets/Scripts/Weapons/` · `Assets/Scripts/Visual/` 는 **존재하지 않는다.**
> 이 저장소는 `Assets/Scripts/Weapon/`(단수)이고 `*Visual.cs` 는 담당 폴더에 흩어져 있다
> (`Enemy/EnemyVisual.cs` · `Player/PlayerVisual.cs`). 둘 다 `Weapon/` 에 넣었다.

**`SummonWeapon` 에서 조심한 것**

- 🔴 **`Update()` 를 선언하지 않는다.** `WeaponBase` 의 `private void Update()` 가 쿨다운을
  돌리는데, 파생 클래스가 같은 이름을 선언하면 그걸 **가려 버려 모든 소환수가 공격을 멈춘다.**
  위치 보정은 `LateUpdate()` 에 뒀다 — 플레이어가 움직인 **뒤에** 따라가야 맞기도 하다.
- 🔑 **철거는 `OnDisable()` 하나로 끝난다.** `WeaponManager.RemoveWeapon` →
  `ObjectPool.Return` → `SetActive(false)` 가 곧 `OnDisable` 이라, `WeaponBase` 에
  새 훅을 팔 필요가 없었다. **기존 파일은 한 줄도 안 고쳤다.**
- `Pool.Return` 앞에 `if (Pool != null)` — 씬을 내릴 때도 `OnDisable` 이 불리는데
  그때 풀은 이미 파괴돼 있을 수 있다.
- 프레임률에 안 흔들리는 감쇠: `k = 1 - exp(-followLerp * dt)`.
  `Lerp(t = lerp * dt)` 로 쓰면 프레임이 튈 때 따라오는 속도가 같이 변한다.
- `FindNearestEnemy()` 를 **몸통 기준으로** override. 안 하면 소환수가 저 멀리 서서
  플레이어 옆의 적을 쏜다.

**`SummonVisual` 에서 안 넣은 것**

- ❌ 위아래 흔들림(bob) — 드래곤 ±1.6px · 문어 ±1.5px 로 **그림에 이미 그려져 있다.**
- ❌ ping-pong — 16프레임이 `sin(2π·i/16)` 이라 15 → 0 이 이음매 없이 붙는다.
- ❌ `EnemyVisual` 재사용 — 그쪽은 `_rb.linearVelocity` 로 프레임을 넘긴다. 소환수엔 강체가 없다.
- `OnEnable()` 에서 시작 프레임을 **무작위로 흩뜨린다.** 여러 마리가 같은 박자로
  날갯짓하면 복제처럼 보인다.

### 판정-③ — `sprite.bounds` 로는 잴 수 없다 (교훈 138 재발)

소환수도 오우거도 `bounds` 가 똑같이 `0.500` 으로 나온다. **`bounds` 는 셀 사각형 기준**이라
그림이 셀 안 어디에 얼마나 그려졌는지를 모른다. 알파 bbox 를 PIL 로 직접 재서 비교했다.

### 판정-⑧ — 링 피격 각도 원본

```
78,82,65,38,37,40,20,134,93,82,152,18,76,36,61,25,112,70,79,30,11,96,20,120,
24,3,64,36,17,155,95,72,77,171,18,29,53,52,53,69,76,77,22,37
```

각도는 **문어 → 플레이어 방향**을 0° 로 잰 것이다. 90 을 넘는 값이 9건 —
플레이어 반대편, 즉 **문어의 등 뒤**에서도 피해가 들어갔다.

## 검증 방법 — 프로브를 세 번 고쳐야 했다

임시 `D13Probe` 로 런 시작 → 무기 장착 → 계측 → 환불까지 스스로 몰고 갔다.
**세 번 헛돌았고, 세 번 다 "검증 장치가 틀린 것"이었다.**

| 증상 | 원인 | 고친 방법 |
|---|---|---|
| ④ 가 항상 `dist=1.20` 으로만 찍힘 | **플레이어가 안 움직인다.** 정지한 대상으로는 "따라온다"를 증명할 수 없다 | `rb.MovePosition` 으로 반지름 3 원운동을 직접 먹였다 |
| ⑧ 이 **첫 후리기 한 번만** 잡힘 | 🔴 **풀에서 나온 오브젝트는 `GetInstanceID()` 가 돌아온다.** "새 것"을 instanceID 로 가리면 두 번째부터 영영 안 잡힌다 | "지금 후리는 중인가"의 **상승 에지**로 바꿨다 |
| 시퀀스가 ⑩ 에서 통째로 멈춤 | `Time.timeScale = 0`. 레벨업 패널과 ESC 일시정지가 코루틴을 얼린다 | 프로브가 `HidePanel()` · `PauseMenuUI.Close()` 로 스스로 풀게 했다 |

피해 팝업을 셀 때 **플레이어가 맞아서 뜬 팝업을 걸러냈다** — D12 에서 이미 한 번 당한 함정이다
(`PlayerStats.cs:258` 도 팝업을 띄운다). 문어는 플레이어에게서 1.2 유닛 거리라 링 안에 플레이어가 들어온다.

프로브 스크립트와 씬 오브젝트는 **철거했다.** Refresh 후 콘솔 **0건**.
