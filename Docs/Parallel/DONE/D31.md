# D31 — 보스 패턴: 큰 잡몹에서 벗어났다 (DEV, 2026-09-03)

> `ROADMAP.md` §2-5 · §8 **10번**. 사용자 지시로 착수.

## 1. 무엇이 문제였나

`Boss1` = `Ogre` + `BossHpMult 7`. 그게 전부였다.

| 있던 것 | 없던 것 |
|---|---|
| HP 7배 · 크기 2배 · 빨간 외곽선(I-26) | **패턴** |
| 넉백 저항 · 사망 시 히트스톱·흔들림 | **페이즈** |
| 등장음 `SfxId.BossAppear` | **얼마나 남았는지 보여 주는 것** |

AI 는 `Chaser` — **잡몹과 같은 코드로 걸어왔다.** HP 1540 을 깎는 동안 화면에는
아무 표시도 없었다. "보스전"이라는 걸 알 수 있는 건 BGM 뿐이었다.

## 2. 설계에서 지킨 것 둘

### 🔴 보스 로직을 `EnemyBase.FixedUpdate` 에 넣지 않았다

거기는 적 **800마리가 매 물리 프레임** 도는 자리다 (`Docs/PERF.md`).
`if (IsBoss)` 분기 하나를 넣으면 **보스가 없는 웨이브에서도 800번씩** 검사한다.
보스는 한 판에 한 마리뿐이니 **그 인스턴스에만 붙이는 게 맞다** → `BossBrain` 컴포넌트.

그리고 `Update` 를 쓴다. 이동은 `EnemyBase` 가 물리로 계속 하고 여기서는
**타이머와 상태만** 본다 — 물리 프레임에 묶일 이유가 없다.

### 🔴 `EnemyBase` 는 읽기 전용으로만 열었다

`HpNow` · `HpMax` · `HpFraction` · `Dead` · `DisplayName`.
**HP 를 쓰는 통로는 안 만들었다** — 밖에서 쓰면 `TakeDamage` 의 방어 계산과
사망 처리를 통째로 건너뛰게 된다.

속도는 `SetSpeedMultiplier` 하나만 열되 **슬로우와 합치지 않고 따로 곱한다.**
슬로우는 "일시적으로 느려짐", 페이즈 배수는 "이 페이즈 동안 빨라짐"이라 성격이 다르다
(교훈 181 과 같은 이유다). 🔴 풀 재사용 대비로 `Initialize` 에서 `1f` 로 되돌린다 —
안 지우면 **이전 보스의 페이즈 배수가 잡몹에 남는다.**

## 3. 값은 새 CSV 로 — `Enemies.csv` 는 안 건드렸다

`Enemies.csv` 는 이미 33열이고, 보스 패턴이 붙는 적은 6종 중 **하나뿐**이다.
열을 늘리면 대부분이 빈칸이 된다. 그래서 `Bosses.csv` 를 새로 파고
`EnemyId` 로 `EnemyData.BossPattern` 을 **되꽂는** 방식을 썼다.

> ⚠️ 그래서 `Enemies.csv` 에 `BossPattern` 열이 **없다** — Export 로 내보내도 안 나온다.
> 복원은 `Bosses.csv` 가 한다. 이 사실을 `EnemyData.BossPattern` 주석에 적어 뒀다.

임포터가 값으로 만들 수 있는 실수 둘을 잡는다:

- **`SlamWindup <= 0`** → *"예고 없는 광역기는 피할 수 없다"*
- **`PhaseThresholds` 가 내림차순이 아님** → `PhaseOf` 가 엉뚱한 페이즈를 답한다

## 4. 🔴 검증 중에 내 오독을 하나 잡았다 — 그리고 그건 실제 버그였다

처음 ⑤(소환)를 볼 때 **잡몹이 4 → 15마리로 늘었다**. 소환이 도는 줄 알았다.
**틀렸다.** 그건 `Boss1` 웨이브가 스스로 소환하는 `Zombie`·`Demon` 이었다.

내가 심어 둔 경고가 잡아냈다:

```
[WaveManager] 보스 소환 대상 'Goblin' 가 이번 웨이브 소환 목록에 없다
```

원인은 내가 쓴 `ResolveSummon` 이 **이번 웨이브 소환 목록에서만** 대상을 찾게 한 것이다.
`Boss1` 의 `Spawns` 는 `Zombie|Demon` 이라 `Goblin` 이 없었고, **소환이 통째로 죽어 있었다.**

그 제약에는 근거가 없었다 — `ObjectPool.Get` 은 **큐가 없으면 만든다**(`ObjectPool.cs:38`).
"프리팹을 아무도 안 들고 있으면 안 된다"는 건 내 추측이었다.

⇒ `BossPatternData.SummonEnemy` 참조를 두고 **임포터가 꽂게** 고쳤다.
런타임에 Id 로 찾을 방법이 없으니(빌드에 `AssetDatabase` 가 없다) 이게 맞는 자리다.

🔑 **재검증은 오독할 수 없게 다시 설계했다** — "잡몹 수"가 아니라 **"Goblin 수"** 를 센다.
`Boss1` 웨이브에는 Goblin 이 없으므로 **0 이 아니면 그건 보스가 부른 것뿐이다.**

```

[D31-RT] ② HP 바: 켜짐=True · 이름='OGRE' · 페이즈표시='★★' · slider=1.00
[D31-RT] ③ HP 0.67 → 페이즈 2/3 · 표시='★' · fill 색=RGBA(0.950, 0.550, 0.150, 1)
[D31-RT] ④ HP 0.37 → 페이즈 3/3 · 표시='FINAL' · fill 색=RGBA(0.950, 0.900, 0.250, 1)
[D31-RT] ⑤ 페이즈 전환 뒤: Goblin 0 → 4마리 (2페이즈 SummonCount 와 일치) · 그 외 6마리
[D31-RT] ⑥ 내려찍기: Fx_BossSlam(Clone) scale 6.40  (= 반경 3.2 × 2)
[D31-RT] ⑦-① 발밑 슬램: HP 130 → 112  (20 − 방어 2 = 18)
[D31-RT] ⑦-② 6유닛 밖:  HP 112 그대로
[D31-RT] ⑦-③ 예고 중 8유닛 밖으로 이동: HP 112 그대로 · 남은 BossSlam 0개

```

| # | 판정 | 결과 |
|---|---|---|
| ① | 보스에 `BossBrain` 이 붙는다 | ✅ |
| ② | HP 바가 이름·페이즈와 함께 뜬다 | ✅ |
| ③ | 0.7 아래에서 2페이즈 | ✅ 색까지 바뀐다 |
| ④ | 0.4 아래에서 최종 페이즈 | ✅ `FINAL` |
| ⑤ | 페이즈 진입 시 소환 | ✅ **Goblin 0→4** |
| ⑥ | 내려찍기가 반경대로 나온다 | ✅ |
| ⑦ | **예고를 보고 피하면 안 맞는다** | ✅ 맞을 때 −18 / 피하면 0 |
| ⑧ | 보스가 죽으면 바가 내려간다 | ✅ 슬램도 풀 반환 |

**⑦ 이 이 작업의 핵심이다.** 예고 없이 터지면 그건 패턴이 아니라 그냥 체력 깎기다.
맞는 경우와 피하는 경우를 **둘 다** 재서, 판정이 "예고를 본 시점"이 아니라
**"터지는 순간의 위치"** 로 이뤄진다는 걸 확인했다.

콘솔 에러·경고 **0**. 화면은 스크린샷으로 눈으로도 확인했다.

## 6. 한 번 틀린 것 둘 (둘 다 검증 방법의 문제였다)

- **페이즈가 안 바뀐다고 봤다** — 한 `RunCommand` 안에서 피해를 세 번 넣었는데
  판정이 `Update` 에 있어 **프레임이 안 넘어갔다.** 다음 호출에서 정상 확인.
  ⇒ `Update` 기반 상태를 검증할 때는 **프레임을 넘겨야 한다.**
- **`GrantInvincibility(0f)` 로 무적이 안 풀렸다** — 구현이
  `Mathf.Max(_invincibleTimer, seconds)` 라 **줄일 수가 없다**(`PlayerStats.cs:274`).
  900초를 걸어 둔 상태라 슬램 피해가 0 으로 나왔다. 플레이 모드를 다시 켜서 해결.
  ⇒ **검증용으로 건 상태는 검증 대상을 가릴 수 있다.**
