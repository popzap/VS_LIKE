## 1. 왜 단독 요청으로 뺐나

`요청-36 §2`·`요청-37 §2` 에 **두 번** 적었는데 둘 다 **큰 요청 안에 묻혔다**

🔑 **한 줄짜리 일은 큰 요청에 끼워 넣으면 안 된다.** 앞의 항목이 크면 뒤가 안 읽힌다.
마감(9/7)까지 남은 내 항목이 이것뿐이라 **제목이 그 일 자체인 요청**으로 다시 냈다.

## 2. 🔴 요청을 쓰다가 **더 큰 걸 찾았다**

배선 지시를 쓰려고 규격을 확인했는데 `Swift.png.meta` 가 **Unity 기본값**이었다.
**내가 새 파일을 넣고 `.meta` 를 안 맞춘 탓이다.**

| | 잘못 잡혀 있던 값 | 기존 픽업 | 그대로 꽂았으면 |
|---|---|---|---|
| `spritePixelsToUnits` | **100** | **2048** | 🔴 **10.24 유닛 — 20배 크기** |
| `filterMode` | 1 Bilinear | 0 Point | 픽셀아트가 뭉개진다 |
| `spriteMode` | 2 Multiple | 1 Single | 슬라이스 없는 멀티 |
| `textureCompression` | 1 | 0 | 5색 아이콘에 압축 아티팩트 |

✅ 네 항목 다 고쳤다. 지금은 Haste 와 **한 글자도 다르지 않다** — `1024px ÷ 2048 = 0.500 유닛`.

🔑 **"한 줄만 꽂으면 된다"가 아니었다.** 그대로 배선했으면 **화면 절반만 한 흐릿한 꺾쇠**가 떴을 것이고,
그건 화면에서 *"CONTENT 가 이상한 그림을 줬다"* 로 보인다 — **내 잘못인데 DEV 가 뒤집어쓴다.**

⇒ **새 애셋을 넘길 땐 `.meta` 까지가 납품물이다.**

### 세 번째다

| 언제 | 무엇을 빠뜨렸나 |
|---|---|
| `C28` | 걷기 시트의 **PPU 256** — 초상의 1024 를 복사하면 캐릭터가 1/4 이 된다 |
| `C33` | 9-slice 의 **`spriteBorder`** — 0 이면 프레임이 통째로 안 늘어난다 |
| **`C46`** | **픽업의 PPU·필터·모드·압축 전부** — 파일을 새로 만들고 `.meta` 를 안 봤다 |

🔴 **앞의 둘은 "요청에 적어서" 막았고, 이번엔 "내가 고쳐서" 막았다.**
차이는 `Assets/Game/Sprites/**` 가 **내 소유 경로**라 `.meta` 를 직접 고칠 수 있다는 것이다.
⇒ **적어서 넘길 게 아니라 애초에 맞춰서 넘기면 된다.** 다음부터 새 그림은 `.meta` 를 같이 맞춘다.

## 3. 배선 자체

```
m_Sprite  1ebfcf14…(Haste) → f2ee2f6f…(Swift)
m_Color   (0.55, 1.00, 0.45) 유지
```

🔴 **색을 유지하라고 못 박았다.** 그림을 **중립(흰~회색)** 으로 그린 이유가 그것이다 —
프리팹이 연두로 곱하고, 그게 **줍고 나면 뜨는 오라 색과 짝**이라
*"저걸 먹으면 저 색이 된다"* 가 읽힌다. 여기서 초록으로 칠했으면 **두 번 곱해져 형광**이 된다.

## 5. 남긴 것

- 🔑 **한 줄짜리 일을 큰 요청에 끼우면 묻힌다.** 두 번 적고도 안 됐다.
  **일의 크기와 요청의 크기를 맞춰야** 한다 — 제목이 그 일 자체여야 눈에 든다
- 🔴 **새 애셋은 `.meta` 까지가 납품물이다.** 파일만 만들고 넘기면 Unity 기본값이 붙고,
  그 결과는 **화면에서 "그림이 이상하다"로 보인다.** 세 번 겪었다
- **내 소유 경로면 적어서 넘기지 말고 고쳐서 넘긴다.** `C28`·`C33` 은 요청에 적어 막았는데,
  `.meta` 는 내가 직접 고칠 수 있는 자리였다. **적는 것보다 맞추는 게 싸다**
- **요청을 쓰는 행위가 검증이 된다.** 배선 지시를 쓰려고 규격을 확인하다 찾았다 —
  *"뭐라고 적어야 하지"* 가 *"지금 값이 뭐지"* 를 부른다
