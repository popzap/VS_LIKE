## 2. 그림 5장 — **두 갈래 파이프라인이 된 이유**

`Tools/Art/gen_pickups.py`. 첫 판에서 **5장 중 3장이 못 알아볼 그림**으로 나왔다.

| 실패한 것 | 어떻게 나왔나 |
|---|---|
| Bomb | 둥근 사각형 = **"검은 자루"**. 구가 아니었다 |
| Haste | 파란 얼룩. 번개의 꺾임이 통째로 뭉갰다 |
| Gold | **"금색 식빵"**. 동전 6개가 서로 녹아 붙었다 |

### 원인 — 15논리px 에서는 그리는 게 아니라 **세는** 것이다

기존 `quantize()`(슈퍼샘플 → LANCZOS → 임계값)는 **곡선**에는 잘 듣는다.
방패·클로버는 한 번에 나왔다. 그런데 같은 방식이

- **가늘고 꺾이는 것**(번개) → 다운샘플이 계단을 지운다
- **작은 게 여러 개 겹치는 것**(동전 더미) → 서로의 잘린 모서리를 메워 한 덩어리가 된다

⇒ **성공한 2장과 실패한 3장의 경계선을 따라 파이프라인을 갈랐다.**
곡선 2종은 `quantize()`, 나머지 3종은 **손으로 픽셀을 찍는** `stamp()`/`outline()`/`shade()`.
전부 다시 쓰지 않고 **되는 것은 그대로 뒀다.**

`shade()` 는 규칙 하나다 — 행의 **맨 왼쪽 잉크에 하이라이트, 맨 오른쪽에 그림자.**
이 한 줄로 번개가 금속으로 읽힌다.

### 남은 흠 — **숨기지 않는다**

`Gold.png` 는 **"동전 더미"가 아니라 "금괴/보물 더미"로 보인다.**
가로 간격은 5로 벌려 갈랐는데(4는 붙는다), 세로 간격 4 < 동전 높이 5 라 위아래가 여전히 붙는다.
뜻은 통하고 다른 5종과 안 헷갈려서 **받아들였지만**, 요청-12 는 "노랑 동전 더미"라고 했다.
⇒ 요청-17 에 **그대로 적었다.** 기대와 다르면 낱개 3개로 줄여 다시 그린다.

**규격은 전부 맞췄다** — 픽업 4장 높이 **480**(Magnet 482) · `Luck` **672**(GoldGain 676) ·
알파 min/max 전부 **0/255**(I-41 가짜 투명 아님).

## 3. SFX 3종 — **자가 고장나 있었다**

`Tools/Audio/gen_{bomb,buff,gold}_pickup.py`. 공용 `dsp.py` 를 쓴다.

### 🔴 `compare_sfx.py` 가 부딪힐 상대를 안 보고 있었다

두 가지가 겹쳐 있었다:

1. 대상 목록이 **무기 소리만** 담고 있었다 — `XpPickup`·`Magnet`·`LevelUp`·`Heal`·`UiSelect` 가 없었다.
   **픽업을 만드는데 픽업이 표에 없었다.**
2. `TentacleLash`/`DragonSpit` 경로가 **`_Incoming/` 인 채**였다. D16 이 `Assets/` 로 옮겼는데
   목록이 안 따라갔고, 스크립트는 "(없음)"만 찍고 **조용히 건너뛰었다.**

⇒ 자가 "안전하다"고 말하고 있었는데 **재는 대상이 빠져 있었을 뿐이다.**
고치자마자 **1.0 미만 짝 두 개**가 튀어나왔고, 하필 **둘 다 쿨마다 계속 우는 무기**였다.

| 짝 | 처음 | 무엇이 붙었나 | 어떻게 뗐나 | 지금 |
|---|---:|---|---|---:|
| `BuffPickup` vs `TentacleLash` | **0.58** | 길이 0.30↔0.28 · 어택 118↔100ms · 800~3k 91↔69% — **세 축 전부** | 3음 0.30s → **4음 0.50s 로 부풀리기**(정점 231ms) | **1.09** |
| `GoldPickup` vs `DragonSpit` | **0.86** | 길이 0.20↔0.22 · 800~3k 38↔52% | 기음 2300~3200 → **3000~4200Hz** | **1.15** |

**배울 점: 검증 도구의 대상 목록은 코드가 아니라서 아무도 안 고친다.**
`_Incoming/` → `Assets/` 이동은 정상적인 절차인데, 그때마다 이 자가 조용히 눈이 하나씩 먼다.

### 만들면서 자로 잡은 것

| 소리 | 부딪힐 상대 | 어떻게 갈랐나 |
|---|---|---|
| `BombPickup` | `Explosion`(둘 다 폭발) | 🔑 대역으로는 **못 갈랐다**. **어택 3.4ms vs 78.5ms** + 길이 0.85 vs 0.57 |
| `BuffPickup` | `LevelUp`·`Heal`·`Magnet` | 저 셋은 전부 저·중역에 몸이 있다. 이것만 **0~200Hz 가 0%** |
| `GoldPickup` | `XpPickup` | 길이 2.4배 + **부딪힘이 세 번**. 대역 7/62 vs 78/22 |

- 폭탄 첫 판은 **0~200Hz 가 96.9%** 였다 — 슬램(사인)이 스펙트럼을 다 먹어서
  **노트북 스피커에서는 아무 소리도 안 날 뻔했다.** 몸통 대역을 90~500 → 180~700Hz 로
  올려 빼내고 슬램을 0.72 로 낮췄다 → 65/14/10/9
- 골드 첫 판은 **75.7/20.5** — `XpPickup` 78/22 와 **거의 같았다.** 기음 하나가 에너지의
  70% 를 먹어 "블립"이 된 것이다. 윗모드를 살려 위로 퍼뜨렸다
- 힐은 **안 만들었다** — `SfxId.Heal = 24` 가 이미 있고 배선돼 있다(Volume 0.50).
  요청-12 가 "있으면 그대로 쓴다"고 했다

## 4. 수치 — 사용자 결정 + **전제 하나를 뒤집었다**

확률은 사용자가 **C 안(종별 차등)** 을 골랐고, **"몬스터를 늘릴 예정이니 추후 조정"** 을 못박았다.
지속시간은 **무적 3초 / 공속 8초**.

### 🔴 요청-12 의 전제가 틀렸다 — "웨이브당 수백 마리(300)"

DEV 는 그 숫자로 Magnet 0.6% 를 잡았다. `Waves.csv` 를 실제로 세었다:

**`Normal1/2/3` = 65 / 82 / 104 · `Elite1/2` = 66 / 72 · `Boss1` = 18.**
`StageMapManager` 는 10층 중 층당 1노드, 1~8층 전투 70% ⇒ 전투층 기대 **7.6개**
⇒ **런당 약 530마리.** 300 의 두 배가 아니라 **층당 65~104** 다.

⇒ 6.7% 면 **층당 5~6개 = 약 15초에 하나.** 이게 기준선이다.

### 잠정값이 **다시 계산될 수 있게** 적었다

사용자가 "나중에 조정"이라고 했으므로, 숫자 6개만 적으면 그때 가서 **또 감으로 잡는다.**
그래서 `TUNING.md` 에 **불변량 2개**를 같이 박았다:

1. **픽업 간격 ~15초**
2. **무적은 런에 2번**

몬스터가 `k` 배가 되면 **6종을 통째로 `1/k`** — 2배면 `1.25/0.75/0.5/0.35/0.3/0.2%`.
표를 고치는 게 아니라 **다시 만드는** 것이다.

### 안 물어봤지만 없으면 못 만드는 값 2개

요청-12 에 **공속 버프의 세기**와 **골드 픽업의 금액**이 없었다. 없으면 D20 이 감으로 넣는다.

- **공속 ×0.5** — 만렙 `AttackSpeed` 패시브가 −0.3 이다. 버프가 그보다 **세야** 버프다
- **Gold 15G** — 상점이 5~12G. 13개 × 15G ≈ 런 수입 1,240G 의 16%
