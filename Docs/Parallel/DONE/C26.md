## 6. 어쎄신이 `minAttackSpeed` 를 성격부터 바꾼다

`C25` 가 `TUNING.md` 에 적은 최악 누적은 **0.15**(`Aegis −0.05` + `AttackSpeed` Lv5 `−0.30`
+ Haste `−0.50`), 하한 `0.10`, **여백 0.05** 였다.

어쎄신 `−0.25` 가 들어오면 **1 − 0.05 − 0.30 − 0.50 − 0.25 = −0.10** → **하한에 물린다.**

🔑 **값을 낮춰서 피할 수 있는 게 아니다.** `−0.15` 로 해도 `0.15 − 0.15 = 0.00` 이라 똑같다.
남은 여백이 0.05 뿐이므로 **공속을 주는 직업이 하나라도 생기면 하한은 반드시 물린다.**
⇒ `minAttackSpeed` 는 안전장치에서 **밸런스 숫자**로 바뀐다.

내가 하루 전에 쓴 문장("하한에 아직 안 닿는다")이 거짓이 되므로 **그 줄을 직접 고쳤다.**
repo `TUNING.md` 와 vault 체크리스트 **양쪽** 다.

## 9. 남긴 것

- **"이 값 꼭 지켜라"라고 강조된 문서 문장일수록 실물을 잰다.** §5 의 PPU 512 는
  🔴 까지 붙은 경고였고, 그래서 더 의심 없이 옮겨 적게 됐다. **강조는 정확성의 근거가 아니다**
- **임포터가 조용한 자리를 목록으로 안다.** `LoadSO` 는 짖고 `LoadRef`·`LoadSpriteSheet` 는
  안 짖는다. 짖지 않는 배선은 **순서로 방어**할 수밖에 없다(그림 → CSV)
- **설계 문서의 의도를 코드가 표현할 수 없을 때, 값을 우겨 넣지 말고 축을 바꾼다.**
  소환사의 "본인만 약하게"는 스탯으로 불가능했고, 슬롯(패시브 3칸)으로 옮겼다
- **내가 어제 쓴 문장도 오늘의 사실이 아니다.** `minAttackSpeed` "여백 0.05" 는
  직업 하나 때문에 무너진다. 새 값을 넣을 때 **기존 값의 근거가 살아 있는지** 같이 본다
