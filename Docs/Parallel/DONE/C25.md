## 4. `healPickupAmount` 30 — **DEV 값을 그대로 뒀다.** 왜 안 흔들었나

DEV 가 *"플레이어 기본 최대 체력 대비 몇 %가 맞는지는 네 판단"* 이라며 넘긴 값이다.

**나는 플레이를 못 한다.** 감으로 30→15 로 바꾸면 **DEV 의 추측이 내 추측으로 바뀔 뿐**이고,
그건 `TUNING.md` 의 방침(*"수치는 지금 잡지 않는다. 기능을 먼저 완성하고 플레이하며 조절한다"*)
을 정면으로 어기는 것이다. 그래서 값은 두고, **repo 안에서 실제로 대조 가능한 기준**을 찾았다.

| 근거 | 값 | 30 이 뜻하는 것 |
|---|---|---|
| 기본 최대체력 `StatBlock.cs:9` | **100** | **30 %** |
| 오거 접촉 피해 `Enemies.csv` | **25** | **한 대를 되돌린다** |
| 🔴 식당 `Output` `Buildings.csv:13` | **15\|25\|40\|60\|85** (쿨 60→40초) | **Lv1·Lv2 보다 크다** |

🔑 **진짜 위험은 "먹으나 마나"가 아니라 식당이 초라해 보이는 것이다.**
건물 슬롯을 쓰고 레벨까지 올린 투자가 1.5 % 랜덤 드랍보다 못하면
그건 값이 아니라 **순서가 틀린 것**이다. 그때 내릴 값은 **15**(= 식당 Lv1),
반대로 먹은 줄도 모르겠으면 **40**. 이걸 판정 기준으로 `TUNING.md` 에 박고 DEV 에 넘겼다.

> ℹ️ DEV 의 확인 요청 ② — `Pickup_Chest` 를 잡몹 표에서 뺀 것은 **맞다.**
> 상자는 엘리트·보스 **확정** 드랍이라 `chestPrefab` 줄이 따로 있는 게 정확하다.

## 5. `minAttackSpeed` 를 표 **안**에 넣은 이유

DEV 는 *"체감값이 아니라 안전장치니 표가 아니라 공속 줄 주석이 맞을 수도"* 라며 판단을 넘겼다.
**표 안에 `⚙️` 로 넣었다.** 이유가 둘이다.

1. **판정 방법이 다른 값과 똑같다** — "공속 8초 동안 발사가 부자연스럽게 끊기나"를 보면 된다
2. 🔴 **끊겼을 때 고칠 것이 하한이 아니라 바로 윗줄의 공속 세기(`−0.5`)** 다.
   두 줄이 **붙어 있어야** 다음 사람이 엉뚱한 쪽을 만지지 않는다.
   하한을 내리면 무한 발사 쪽으로 다시 열린다 (`WeaponBase.cs:54` 가 쿨다운에 곱한다)

여백은 **0.05** 다 — 최악 누적 `Aegis −0.05` + `AttackSpeed` Lv5 `−0.30` + 픽업 `−0.50` = **0.15**.
공속 세기를 `−0.6` 으로 올리자는 판정이 나오면 **하한도 같이 봐야 한다.** 그것도 적어 뒀다.
