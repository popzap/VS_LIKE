## 무엇을 했나

### ① 행운(Luck) 스탯 배관 — 없던 스탯을 새로 깔았다

`Luck` 은 이번에 처음 생긴 스탯이다. 스탯 하나를 추가하려면 **네 군데**가 같이 움직인다.

| 파일 | 무엇 |
|---|---|
| `Scripts/Player/StatBlock.cs` | `Luck = 0f` 필드 신설 + `Zero()` 에 추가 |
| `Scripts/Passive/PassiveData.cs` | `BonusLuck` 배열 + `GetLuck(level)` |
| `Scripts/Passive/PassiveEffect.cs` | `stat.Luck += Data.GetLuck(Level)` |
| `Editor/BalanceImporter.cs` | `BonusLuck` 열의 임포트 **와 익스포트** 양쪽 |

> 🔴 **`Zero()` 를 빼먹으면 안 된다** (I-21). 보너스로 쓰는 `StatBlock` 이 기본 생성자로
> 만들어지면 기본 스탯이 그대로 더해져 값이 2배가 된다. 새 필드를 넣을 때마다 같이 봐야 한다.

익스포트도 같이 고친 이유는, 임포트만 고치면 **다음 Export 때 `BonusLuck` 열이 통째로
사라져** CSV 가 조용히 망가지기 때문이다. 왕복이 맞아야 CSV 가 원본 노릇을 한다.

### ② 시한 버프 — 무적 / 공속

`PlayerStats` 에 타이머 두 개를 넣었다.

| 무엇 | 코드 |
|---|---|
| 무적 | `GrantInvincibility(sec)` — 기존 피격 무적과 같은 경로를 쓴다 |
| 공속 | `GrantHaste(sec, delta)` · `IsHasted` — `Final.AttackSpeed` 에 가산 |

🔴 **`minAttackSpeed = 0.1f` 하한을 같이 넣었다.** `WeaponBase.cs:54` 가 쿨다운에
`Final.AttackSpeed` 를 **곱하기** 때문에 이 값이 0 이나 음수가 되면 **쿨다운이 0 이 되거나
공격이 역행한다.** 오늘 기준 최악 조합이 이미 아슬아슬하다:

```
Aegis −0.05  +  AttackSpeed Lv5 −0.30  +  공속 버프 −0.50  =  0.15
```

여유가 **0.05** 밖에 없다. 픽업 하나만 더 겹쳐도 넘어간다 — 그래서 값이 아니라 **바닥**을 깔았다.

### ③ 픽업 4종 신설 — `WorldPickup` 확장

`PickupKind` 에 `Bomb` · `Invincible` · `Haste` · `Gold` 를 더했다 (기존 `Chest` · `Magnet`).

**종류마다 클래스를 나누지 않았다.** 하는 일이 "먹으면 한 번 터진다" 하나뿐이고,
나누면 프리팹 4개에 스크립트 4개가 따로 붙어 배선 실수만 는다. 프리팹마다 `kind` 가
하나로 고정돼 있으므로 자기 kind 가 안 쓰는 인스펙터 칸은 그냥 비어 있다.

폭탄의 **폭심은 픽업이 아니라 플레이어**다. 픽업은 끌려오다 먹히므로 터지는 순간의
위치가 플레이어 근처이긴 하지만 정확히 같지는 않고, "화면을 쓸었다"로 읽히려면
원의 중심이 화면 중심(= 카메라가 따라다니는 플레이어)이어야 한다.

### ④ 드랍표 — **한 번만 굴린다**

`ExperienceManager.RollPickupDrop(position)` 이 잡몹 사망 시 호출된다.

```
누적확률 한 번 통과 → 최대 하나를 떨군다
최종확률 = 기본확률 × (1 + Luck)   ← 항목마다 곱한다
```

종류마다 따로 굴리지 않은 이유는 두 가지다.

1. 그러면 한 마리가 **폭탄과 무적을 같이** 떨구는 일이 생긴다
2. 표에 적힌 "합계 6.7%" 가 실제 드랍률과 어긋난다 — 한 번만 굴리면 **합계가 곧 드랍률**이라
   표를 읽는 사람이 계산할 게 없다

행운을 합계가 아니라 **각 항목에** 곱한 것도 의도적이다. 값은 같지만 이렇게 두면
**종류별 비율이 행운과 무관하게 유지된다** (행운을 올려도 골드만 늘거나 하지 않는다).

`EnemyBase.Die()` 는 등급으로 갈랐다 — **엘리트·보스는 상자 확정, 잡몹만 드랍표.**
엘리트가 픽업까지 떨구면 상자와 겹쳐 어느 쪽을 먹은 건지 알 수 없다.

### ⑤ 드랍표를 CSV 로 배선하는 모양 — 나란한 배열

🔴 **`SceneWiring.csv` 는 구조체 배열을 못 쓴다.** `BalanceImporter.WriteProperty`(605행)가
배열 원소마다 `WriteScalar` 를 부르는데 구조체 원소는 `SerializedPropertyType.Generic` 이라
`! 타입 미지원` 으로 튕긴다. **`GameObject[]` 와 `float[]` 를 나란히 두는 것이 유일한 길**이다.

```csharp
[SerializeField] private GameObject[] pickupPrefabs;   // 같은 순서 · 같은 길이여야 한다
[SerializeField] private float[]      pickupChances;
```

나란한 배열은 **길이가 어긋나면 조용히 틀리므로** `Mathf.Min(...)` 으로 잘라 쓴다.

**힐 픽업은 새로 만들지 않고 기존 `HealPickup.prefab` 을 드랍표에 넣었다.** 원래 식당이
뱉던 물건인데, 드랍으로 나올 땐 건물 레벨이 없어 회복량을 줄 사람이 없다 —
그래서 `healPickupAmount` 를 `ExperienceManager` 가 들고 `Initialize` 로 주입한다.
안 주면 **0 을 회복하고 조용히 사라진다.**

## 하다가 발견한 것

### 🔴 B5 에 새 증상 — 광역기가 첫 사망자에서 멈춘다

`EnemyBase.Die():449` 의 NRE 가 `DetonateBomb` 의 `foreach` **밖으로 전파**된다.
그래서 뒤쪽 적은 피해를 아예 안 받고, `Collect()` 가 `Despawn()` 전에 끊겨
**폭탄 픽업이 바닥에 남는다**(`_collected=true` 라 다시 먹히지도 않는다).

같은 모양이 `AoeProjectile` · `MeleeWeapon` · `SummonWeapon` · `ToxinField` 에도 있다.
**고치지 않았다** — `WaveManager.cs` 는 D20 범위 밖이다. [`BUGS.md` B5](../BUGS.md) 에 적었다.

### ℹ️ 스프라이트 bbox 를 재는 기준이 서로 달랐다

CONTENT 가 넘긴 치수와 내가 잰 값이 안 맞아 잠깐 애셋을 의심했다.
원인은 **알파 임계값**이었다 — CONTENT 는 `alpha > 127`, `PIL.getbbox()` 는 `alpha > 0`.

`Magnet`·`GoldGain` 에는 **거의 안 보이는 AI 잔여 픽셀이 1.4~1.5%** 흩어져 있어
`a>0` bbox 가 최대 311px 부풀었다(Magnet 499×793 vs 489×482). `a>127` 로 재면 CONTENT 값과
**정확히 일치**한다. 이번에 들어온 5장은 **부분 알파가 0픽셀**로 깨끗하다.

⇒ 애셋 결함이 아니라 **측정 기준 차이**다. 앞으로 치수를 주고받을 땐 임계값을 같이 적는 게 좋다.

### ℹ️ `ExecutionResult.Log` 는 정렬 지정자를 못 쓴다

`"{1,-24}"` 가 그대로 문자로 찍힌다. `{0}` `{1}` 만 쓸 것.

### ℹ️ 대량 실험은 플레이 세션을 오염시킨다

5만 회 드랍 실험이 풀에 `WorldPickup` **5215개**를 남겼고, 그중 하나가 플레이어에게 끌려가
먹히면서 게임이 `LevelUp` 상태(`timeScale 0`)로 들어갔다. `WorldPickup.Update` 는 `LevelUp`
에서 조기 반환하므로 **그다음 검증이 통째로 막혔다.** 플레이를 껐다 켜서 해결.
**대량 스폰 실험 뒤에는 세션을 새로 시작할 것.**
