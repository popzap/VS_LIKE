## 2. 🔴 "플레이해 봐야 안다"고 넘어온 것 중 **하나는 책상에서 답이 나왔다**

`D31` 은 이렇게 물었다:

> *"`SlamWindup 0.9` 로 피할 수 있나. 기본 이동속도로 0.9초에 반경 3.2 를 벗어날 수 있는지는
> **플레이해 봐야 안다.**"*

**플레이 안 해도 된다.** `BossSlam` 을 읽으면 변수가 셋뿐이다:

- 예고 원은 **시작 시점의 플레이어 자리**에 깔리고 **따라오지 않는다**(`BossBrain.cs:104`)
- 피해는 **터지는 순간의 거리**로만 판정한다(`BossSlam.cs:66`)

⇒ 필요한 건 하나다 — **`windup` 초 안에 `radius` 만큼 걸어나가기.**
즉 **필요 속도 = `radius ÷ windup`** 이고, 직업 이속표와 대조하면 끝난다.

**임시값은 `3.2 / 0.9 = 3.56 u/s` 를 요구한다:**

| 직업 | 이속 | 반응 0초 | 반응 0.25초 |
|---|---:|---|---|
| **Demolitionist** | **3.5** | 🔴 3.15 | 🔴 2.27 |
| Warrior | 3.7 | ✅ 3.33 *(여유 4 %)* | 🔴 2.41 |
| Mage · Sentinel · Aegis | 4.0 | ✅ 3.60 | 🔴 2.60 |
| Ranger *(최속)* | 4.6 | ✅ 4.14 | 🔴 **2.99** |

- 🔴 **폭발광은 반응 0초, 완벽한 방향으로도 못 피한다** (`3.5 × 0.9 = 3.15 < 3.2`)
- 🔴 **반응 0.25초를 주면 레인저조차 못 피한다**

⇒ `D31` 의 판정 ⑦(*"예고를 깔고 빠져나가면 안 맞는다 — 실측"*)은
**이미 그 방향으로 움직이고 있을 때만** 참이었다. 그리고 이 게임에서 보스에 딜을 넣으려면
**무기 사거리(3.5~6) 안에 서 있어야** 하므로, 피해야 할 순간에 대개 **접근 중**이다.

**`2.4 / 1.15` 로 바꿨다** — 필요 속도 2.09. 반응 0.25초를 빼고도 전 직업이 **1.3배 이상** 여유로 벗어난다.
반경 2.4 는 지름 4.8 로 **화면 세로(12)의 40 %** — `D31` 이 걱정한 53 %에서 내려왔다.

## 3. 🔑 형태를 정한 것 — **보스는 플레이어를 절대 못 쫓아온다**

`Enemies.csv` 의 Ogre 에 보스 배수를 곱해 보고서야 이 싸움의 구조가 보였다:

| | 계산 | 값 |
|---|---|---|
| HP | 220 × 7 | 1540 |
| 이동 | 1.2 × **0.9**(`BossSpeedMult`) | 🔴 **1.08** |
| 접촉 피해 | 25 × 2 | 50 |

가장 느린 직업이 **3.5** 다. ⇒ **접촉 피해 50 은 거의 안 쓰인다.**
소환수(Goblin **2.2**)도 못 쫓아온다.

**그런데 그게 고장이 아니라 설계였다.** 셋이 맞물려 하나의 위협 경로를 만든다:

> 딜을 넣으려면 제 발로 사거리(3.5~6)에 들어가야 한다
> → 소환수가 보스 주위(1.75~3.5)에 깔려 **그 자리를 막는다**
> → 내려찍기가 **못 움직이는 것을 벌한다**

⇒ 🔴 **하나만 줄여도 보스가 통째로 무해해진다.** 그래서 `Summon*` 3열을 **안 건드렸다** —
바꿀 근거가 없었고, 근거 없이 건드리면 구조가 깨진다.

`PhaseSpeedMult` 만 `1.35 → 2.2` 로 올렸다(1.08 → **2.38**).
🔴 **3페이즈에도 가장 느린 직업(3.5)보다 느리게 뒀다** — 따라잡히면 카이팅이라는
이 게임의 주 생존 수단이 사라진다. **"도망칠 수는 있지만 멈춰 있을 수는 없다"** 가 목표선이다.

## 5. 예고 원 스프라이트 — *"필수는 아니다"* 가 **필수가 됐다**

`D31` 은 §4 를 선택으로 뒀다. 그런데 §2 에서 이 기술을 **"정확히 피하는 것"** 으로 다시 잡았으니
**보이는 원과 판정 원이 같아야 한다.** 지금 쓰는 `ToxinField` 는 블롭이라 다르다.

| 항목 | 값 | 왜 |
|---|---|---|
| 512×512 · **PPU 512** | 반경 **0.5** | `spriteRadiusAtScaleOne` 기본값 0.5 와 정확히 맞아 **프리팹 필드를 안 고쳐도 된다** |
| 필터 **Bilinear** | | 픽셀아트가 아니라 UI성 도형이다. Point 면 테두리가 계단이 된다 |
| RGB **전부 흰색** | | `BossSlam` 이 `telegraph.color` 를 통째로 덮어쓴다 — 색은 코드, 텍스처는 **알파로 모양만** |

모양은 **굵은 바깥 링**(알파 1.0) + 옅은 채움(0.30) + **조준선 4개**.
조준선은 어두운 타일에서 원이 흐릿할 때 방향을 잡아 주려고 넣었다.
`warnColor.a` 가 0.30 이라 링도 0.30 으로 나온다 — 더 필요하면 **0.45** 를 권했다(프리팹이라 DEV 쪽).

## 6. 남긴 것

- 🔴 **"플레이해 봐야 안다"를 그대로 받지 않는다.** `D31` 이 넘긴 5개 중 하나는
  **코드를 읽으니 나눗셈 한 번**이었다. 예고가 따라오지 않고 터지는 순간의 거리로만 판정한다는
  두 사실이 문제를 `radius ÷ windup` 으로 줄였다.
  **판정이 감각의 문제인지 산수의 문제인지부터 가른다**
- **"실측했다"도 조건을 봐야 한다.** `D31` 의 판정 ⑦ 은 실제로 통과했지만
  **이미 도망치고 있던 상태**에서였다. 같은 기술이 정지 상태에서는 전 직업이 못 피한다.
  **실측은 그 실측이 재현한 상황까지가 유효 범위다**
- **수치를 바꾸기 전에 그 수치가 왜 거기 있는지 먼저 찾는다.** 소환을 줄일 뻔했다.
  보스도 소환수도 플레이어를 못 쫓아온다는 걸 보고서야 **소환이 내려찍기를 위험하게 만드는
  유일한 장치**임을 알았다. 근거가 없으면 안 건드리는 게 근거다
- **선택이라고 넘어온 것이 내 결정 때문에 필수가 될 수 있다.** 예고 원 스프라이트는
  `D31` 기준으로는 있으면 좋은 것이었지만, 내가 이 기술을 정밀 회피로 만든 순간
  **보이는 것과 판정이 같아야 한다는 요구가 생겼다**
