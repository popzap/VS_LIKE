> 겸사겸사 요청-4(`TODO.md` §1 갱신)도 같이 닫았다 — 둘 다 같은 실플레이에서 판정된다.

## 왜 했나

B2. 걷는 적이 한 프레임이 아니라 **작은 캐릭터 뭉치**로 보였다.
원인은 DEV 가 확정했고(애셋), 수정본은 CONTENT 가 만들었다(C1).
**에디터가 필요한 부분 — 임포트와 실플레이 판정 — 만 남아서 이쪽으로 넘어왔다.**

## 🔴 이 작업의 핵심은 "png 만 덮어쓴다"

`.meta` 를 지우면 안 된다. 지우면 두 가지가 동시에 깨진다:

| 지웠을 때 | 결과 |
|---|---|
| PPU 가 기본값 **1024** 로 재생성 | 적이 **걷는 순간 크기가 절반**이 된다 (I-58 재발) |
| 스프라이트 서브애셋 GUID 재발급 | `EnemyData.WalkFrames` **16칸이 통째로 `None`** |

그래서 png 4장만 바이트 교체했다. `.meta` 6개는 **타임스탬프까지 그대로**(Aug 29 17:15)임을 확인했다.
Ogre·Zombie 는 원래 정상이라 손대지 않았다.

## 넘겨받기 전 다시 센 것

CONTENT 보고를 그대로 믿지 않고 `_Incoming/` 의 png 를 직접 열어 확인했다.

- 4장 전부 `alpha min=0 max=255` → **I-41 "가짜 투명" 아님**
- 16칸 × 4장 = **64칸 전수** 알파 덩어리 정확히 **1개**
- bbox — Goblin `149×132` · Slime `175×114` · Demon `256×211` · Wolf `230×133`
  → CONTENT 보고와 **일치**

## 검증 — 판정 기준 5개

| # | 기준 | 결과 |
|---|---|---|
| ① | PPU 512 | 6종 전부 `ppu=512` · `mode=2`(Multiple) ✅ |
| ② | 슬라이스 `frame_0`~`frame_15` 16개 | 6종 전부 `sprites=16` ✅ |
| ③ | `EnemyData.WalkFrames` 16장 · `None` 0 | 6종 전부 `count=16 None=0` ✅ |
| ④ | 🔴 실플레이 격자 0회 | 아래 ✅ |
| ⑤ | `sprite.bounds.size` 로 크기 확인 | `[0]`/`[last]` 둘 다 `(0.500, 0.500, 0.200)` — **안 변했다** ✅ |

### ④ 실플레이

`StageMapManager.RollStageType` 은 `layer == 0` 이면 항상 `Normal` 이라
`map.Layers[0][0]` 을 `SelectNode` 해서 확실히 노말 웨이브를 띄웠다.

Zombie·Wolf 는 그대로 두고, **살아 있는 적 14마리를 `Initialize` 로 Goblin/Slime 으로
강제 교체**했다 — 가장 심하게 깨져 있던 2종을 확실히 화면에 올리기 위해서다.
(`EnemyBase.Initialize(data, isElite, isBoss)` 가 public virtual 이라 즉석 교체가 된다.)

카메라 캡처 3장(`Camera.main` 인스턴스 ID 를 넘겼다 — 인자 없이 부르면 씬 뷰가 찍힌다)
전부 **낱개 캐릭터만** 보였고 격자는 **한 번도 안 나왔다.**

마지막에 화면에 실제로 쓰인 칸을 전수로 찍어 봤다:

## 검증하다 배운 것 (다음에 또 걸린다)

| 틀린 추측 | 실제 |
|---|---|
| `so.FindProperty("walkFrames")` | 필드가 **대문자** `WalkFrames` 다. 소문자로 찾으면 6종 전부 `null` 이 나와 "배선이 끊겼다"로 오해하게 된다 |
| `enemy.Data` 로 종류 확인 | `EnemyBase.Data` 는 **public 이 아니다**(`CS0122`). `sr.sprite.texture.name` 으로 식별했다 |
