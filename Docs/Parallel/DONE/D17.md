# D17 — 엘리트·보스 외곽선을 ×0.75 로 (요청-15 / C21)

**세션:** DEV · **날짜:** 2026-08-31 · **요청:** [`REQ/DEV.md` §요청-15](../REQ/DEV.md)
**설계 근거:** [`REQ/CONTENT.md` §요청-9](../REQ/CONTENT.md) 의 답 — CONTENT 가 자 두 개를 대서 값을 좁혀 왔다

---

## 왜 했나

D15 가 `_OutlineTexSize` 를 고친 뒤로 `_OutlineWidth` 는 **진짜 텍셀 수**가 됐다.
그런데 값 `14/12` 는 그 전(= 폭이 임의 배율이던 시절)에 눈으로 맞춘 숫자라
고친 뒤에는 **낱장 시절의 약 2배**로 두꺼워져 있었다.

진짜 원인은 시트 전환이 아니라 **PPU 2048 → 512** 다.
텍셀은 2W→W(½)로 줄었는데 PPU 가 ¼ 이 되어 순증 **2배**.

---

## 무엇을 했나

`EnemyBase.ApplyRankOutline()` **한 줄** + 근거 주석.

```cs
// 전
_mpb.SetFloat(OutlineWidthId, IsBoss ? 12f : IsElite ? 14f : 0f);
// 후
_mpb.SetFloat(OutlineWidthId, IsBoss ?  9f : IsElite ? 10.5f : 0f);
```

비율 **7:6 유지**, 배율만 **×0.75**.

### 변경한 파일

| 경로 | 무엇 |
|---|---|
| `Assets/Scripts/Enemy/EnemyBase.cs` | `ApplyRankOutline()` 폭 1줄 + 자 두 개를 적은 주석 |

### 왜 `7` 이 아닌가 — 자가 두 개다

`ortho 6` · 1080p → **1 유닛 = 90 화면 px.**
화면 px = `폭 ÷ 512(PPU) × SizeScale × 등급배율 × 90`.

| 자 | 값 | 근거 |
|---|---|---|
| **하한** | **2 화면 px** | 시트가 `filterMode 0`(Point)이라 그 밑은 선이 끊겨 **점선**이 된다 |
| **상한** | **키의 ~9 %** | 슬라임 엘리트는 화면에서 **23px** 뿐이라 더 굵으면 실루엣을 먹는다 |

`7` 이면 Wolf **1.36px** · Slime 1.44 · Goblin 1.60 — 가장 흔한 잡몹 셋이 점선이 된다.
`10.5` 는 하한 Wolf **2.04px** · 상한 Slime **9.2 %** 로 **양쪽에 동시에 딱 걸친다.**

### 🔴 종별 보정은 하지 않았다

두 자가 **정반대를 가리킨다.** Goblin 을 10.5 로 두고 나머지를 맞추면:

| 적 | 화면 px 균일화 | 키 대비 균일화 |
|---|---:|---:|
| Wolf | 12.4 | 14.2 |
| **Ogre** | **6.6** | **16.1** |

오우거 하나에서 6.6 대 16.1 로 갈린다. 한 숫자로 두면 두 오차를 **반씩 나눠 갖는다**
(화면 px 2.0~3.8 · 키 대비 5.0~9.2 %). 보정은 **실플레이에서 한쪽이 실제로 거슬린 뒤**에 한다.
이 판단 근거를 코드 주석에 박아 뒀다 — 안 그러면 다음 사람이 "왜 안 나눴지" 하고 또 나눈다.

## 어떻게 확인했나

### ① 속성 프로브 — `EnemyData` 6종 × 등급 3 (**삭제됨**)

실제로 `Initialize()` 를 태워 `MaterialPropertyBlock` 에 들어간 값을 읽었다.
CONTENT 가 예측한 표와 **소수점까지 일치**한다.

```
             일반          엘리트                      보스
Demon        0.00/1.250    10.50/1.625/3.00px          9.00/2.500/3.96px
Goblin       0.00/1.000    10.50/1.300/2.40px          9.00/2.000/3.16px
Ogre         0.00/1.600    10.50/2.080/3.84px          9.00/3.200/5.06px
Slime        0.00/0.900    10.50/1.170/2.16px          9.00/1.800/2.85px
Wolf         0.00/0.850    10.50/1.105/2.04px          9.00/1.700/2.69px
Zombie       0.00/1.050    10.50/1.365/2.52px          9.00/2.100/3.32px
                           (폭 / localScale / 화면px)
색: 엘리트 RGBA(0.75,0.35,1.00) · 보스 RGBA(1.00,0.25,0.15)
```

### ② 렌더 픽셀 실측 — 화면에 진짜 그려지는가

`timeScale = 0` 으로 세워 놓고 `Camera.main` 을 `RenderTexture(1920×1080)` 에 그린 뒤
`ReadPixels` 로 외곽선 색(±0.10)을 셌다. **계산이 아니라 나온 픽셀을 셌다.**

```
STAGED_0 (일반)   보라 0    빨강 0     bbox 없음
STAGED_1 (엘리트) 보라 261  빨강 0     bbox 34x31
STAGED_2 (보스)   보라 0    빨강 555   bbox 50x50
```

### ③ 🔴 선이 끊기지 않는가 (하한 자 검증)

행마다 색 픽셀의 연속 덩어리 수를 세서 점선 여부를 봤다.

```
엘리트(보라)  걸린 행 31  두께 1~26  좌우 2덩이 안 되는 행 1
보스(빨강)    걸린 행 50  두께 2~20  좌우 2덩이 안 되는 행 0
Wolf 엘리트(최악 사례, SizeScale 0.85 → 2.04px)
              보라 216  행 24  두께 1~13  끊긴 행 2
```

두께 1 인 행은 **대각선 구간**, "끊긴" 행은 **머리·발 끝 캡**이다.
`SizeScale` 이 가장 작은 Wolf 에서도 선이 이어진다 → 하한 2px 이 지켜졌다.

### ④ 실플레이 회귀 — 일반 몹에 외곽선이 안 붙는가

Warrior 로 **68.8초** 돌리며 살아 있는 적을 두 번 전수 감사했다.

```
1차 19마리 · 2차 24마리 — 전부 일반, `_OutlineWidth` 불일치 0
```

## 알게 된 것

### 자동 플레이로는 엘리트를 못 본다

68.8초를 돌려도 엘리트가 안 나온다. 등급 스폰은 웨이브 후반에 걸려 있어
**짧은 자동 검증으로는 ④ 를 못 친다.** 등급 외곽선을 볼 때는
`EnemyBase.Initialize(data, isElite:true)` 로 **세워 놓고 찍는 쪽**이 유일하게 확실하다.

### `LevelUpManager.allItems` 는 private 직렬화 필드다

`RunCommand` 에서 직접 못 읽는다. `new SerializedObject(lum).FindProperty("allItems")` 로
`arraySize` → `GetArrayElementAtIndex(i).objectReferenceValue as ItemData` 를 돌려야 한다.
레벨업이 뜨면 `timeScale = 0` 이라 **치워 주지 않으면 게임 시간이 안 흐른다.**

### 픽셀 색으로 세면 "굵기"를 계산 없이 잰다

외곽선 색이 등급마다 고정(보라/빨강)이라 **색 일치 카운트**만으로
있는지·몇 px 인지·끊겼는지를 한 번에 판정할 수 있다. 셰이더 값을 믿을 필요가 없다.

## 남은 것

- 🟡 **판정 ④ — 난전 0.2초 판별.** 사람이 봐야 한다. 안 되면 `14/12` 로 되돌린다.
  사다리는 `7/6` ← **`10.5/9`** → `14/12`
- 🟡 **보스가 엘리트보다 32 % 두꺼운 건 그대로다** (엘리트 10.5×1.3 = 13.65 vs 보스 9×2.0 = 18.0).
  비율 7:6 을 유지했으니 D15 이전과 관계가 같다. 같게 만들려면 보스를 **`6.8`** 로 (= 13.65 ÷ 2).
  보스는 덩치가 2배라 두꺼워도 실루엣을 안 먹으므로 **그대로 두는 쪽**에 무게를 둔다 — CONTENT 판단
