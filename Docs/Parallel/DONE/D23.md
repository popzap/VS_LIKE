## 1. 원인 — 왜 했나

문서가 **36개 · 약 1.1MB** 로 불었다. 특히 `SETUP_STATUS.md` 혼자 **388KB**다.
편집기에서 열면 어디에 뭐가 있는지 찾을 수 없고, "그때 그거 어디 적었더라"에

### 왜 "옮기지" 않고 정션인가

vault 로 **복사하면 두 벌이 되고, 두 벌은 반드시 갈라진다.**
`CLAUDE.md` 가 규정한 경로(`Docs/SETUP_STATUS.md` 등)와 git 이력도 전부 깨진다.
그래서 **디렉터리 정션** 하나만 걸었다 — 실체는 repo 에 그대로 있고,
옵시디언은 그걸 **들여다보기만** 한다. 사본이 없으니 갈라질 수가 없다.

```
D:\obsidian_claude\UNITY_GAME\VS_LIKE   →   C:\Unity\VS_LIKE\Docs
```

## 3. 검증 로그

### ① 정션이 진짜 양방향인가

```
> New-Item -ItemType Junction -Path 'D:\...\UNITY_GAME\VS_LIKE' -Target 'C:\Unity\VS_LIKE\Docs'
Mode  : d----l          ← l = link. 성공
```

- `D:\...\VS_LIKE\SETUP_STATUS.md` 를 열면 repo 본문이 그대로 나온다 ✅
- repo 쪽에 임시 파일을 만들자 vault 쪽에 **즉시** 보였다 → 확인 후 **삭제함** ✅
- vault 에는 repo 문서의 **사본이 하나도 없다** (`ls` 로 확인 — `.md` 실체는 지도 6개뿐) ✅

> ⚠️ `cmd //c mklink /J` 는 이 bash 에서 **동작하지 않는다.** MSYS 가 인자를 망가뜨려
> 대화형 cmd 만 뜨고 끝난다. PowerShell `New-Item -ItemType Junction` 을 써야 한다.

🔴 **1차 검사는 거짓 통과였다.** `grep -oP '\]\(\K...'` 가 이 환경에서 아무것도 못 뽑아

썼는데 `../VS_LIKE/...` 여야 했다. 고치고 재검사해 0 으로 만들었다.
**교훈: 검사 도구가 "이상 없음"을 반환하면 그 도구부터 의심한다.**
