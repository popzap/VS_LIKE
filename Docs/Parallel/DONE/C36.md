### ① 결론은 맞고 이유가 틀렸다

파일 크기(50×50)와 **스프라이트 rect**(41×41)를 혼동했다. 여백이 트리밍돼 있었다.
그런데 게임플레이가 안 변한 건 **크기가 같아서가 아니라 명중 판정이 스프라이트와 무관**해서다 —
플레이어 탄은 프리팹의 `CircleCollider2D radius 0.5`, 적탄은 `EnemyProjectile.cs:14` 의
`HitRadius = 0.45f` 상수다(주석에 *"스프라이트 크기와 무관한 고정값"* 이라고 적혀 있다).

⇒ **오히려 나아졌다.** 예전엔 0.41 짜리 그림에 0.5 짜리 판정이라 **보이는 것보다 넓게 맞았다.**

🔑 **맞는 결론이 검증을 면제해 주지 않는다.** 전제가 틀렸는데 결론이 맞으면
다음에 같은 전제를 또 쓴다.

guid 로 씬·프리팹을 훑는 건 **명령 한 줄**이다. `DESIGN_ART.md` §7 에 *"안 쓰인다"* 고 적어 놨는데

🔑 **문서에 적은 추측은 다음 사람에게 근거가 된다.** 적는 순간 재야 한다.

## 3. 🔴 내가 규격을 **덜 줬다** — 9-slice 는 텍스처만으로 규격이 아니다

`spriteBorder`(40/28/20)는 줬는데 **어디에 얹히는지**를 안 줬다.
`D40` 이 배선하다 막혔다 — `ShopRemoveRow/RemoveButton` 이 **38×38** 인데
테두리가 위아래 **20+20 = 40px** 이라 **버튼보다 테두리가 크다.**

`D40` 이 정한 규칙을 `DESIGN_ART.md` 에 그대로 남겼다:

> **테두리 총합이 짧은 변의 60 % 를 넘으면 `Image.pixelsPerUnitMultiplier` 로 그만큼 줄인다.**
> (2.2 / 1.8 / 1.4 / 1.1 / 1.0 — 대상별 표도 같이 옮겼다)

🔑 **텍스처 규격은 "무엇을 만들었나"고, 9-slice 는 "어디에 얹히나"까지가 규격이다.**
다음에 프레임을 만들면 **가장 작은 대상의 짧은 변**을 같이 재서 넘긴다.

## 5. DEV 쪽에서 가져온 것

- **`I-41` 이 또 났다.** `D42` 가 프롬프트에 *"fully transparent background"* 라고 **명시했는데도**
  알파가 전부 255 로 나왔다. 🔑 **"투명하게 그려 줘"는 안 통한다.**
  `C28` 에서 함정 표를 만들어 요청에 붙여 둔 게 막았다 — **표를 옮겨 적는 값이 여기서 나왔다**
- **`D43` 의 스캐너 대조군.** 한글 문자열을 훑을 때 *방금 넣은 영문*을 같이 찾게 해서
  그게 잡히는 걸 확인한 뒤에 "0건"을 믿었다.
  🔑 ***"0건"은 깨끗하다는 뜻이 아니라 못 봤다는 뜻일 수 있다.*** 내 판정에도 옮겨 쓴다
- **레벨업 파동은 시점만 옮겼다** — `ScreenSpaceOverlay` 캔버스가 월드 스프라이트를 무조건 덮어서
  원래 자리(패널 열림)에서는 **아무도 못 봤다.** A안(패널 닫힐 때)으로 갔고 **내 그림은 하나도 안 버려졌다**
