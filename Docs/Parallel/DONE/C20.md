## 2. 🔴 촉수는 피크 위치를 내가 못 정한다 — 코드가 정한다

```csharp
SpawnLash(range);                              // t = 0
AudioManager.Play(SfxId.WeaponFire);           // t = 0     <- 소리가 시작하는 곳
yield return new WaitForSeconds(lashHitDelay); // 0.1s
OverlapCircleAll(...)                          // t = 0.1   <- 피해가 들어가는 곳
```

소리는 후리기 **시작**에 재생되는데 맞는 건 **0.1초 뒤**다.
⇒ 클립이 "때리는 소리"가 아니라 **"휘두르다 0.1초에 때리는 소리"** 여야 한다.
**접근음(0→0.1s) + 타격(0.1s) + 물기 꼬리** 구조로 구웠다. 그림의 **프레임 3**(30fps)과도 같은 순간이다.

### 맞추는 과정에서 걸린 함정 3개

| 증상 | 원인 | 대응 |
|---|---|---|
| 피크가 **+4ms 늦음** | 어택 4ms + 밴드패스 군지연 + 물기층이 겹쳐 밀린다 | 타격층을 `SLAP_LEAD 6.5ms` **먼저** 시작 |
| 오차가 **±5ms 씩 튐** | 3ms 이동평균으로 재니 이웃한 **노이즈 봉우리** 사이를 오갔다 | 8ms 로 넓혀 포락선으로 잰다 |
| 접근음이 실제보다 **크게 나옴** | 측정창이 `HIT_AT` 까지라 **타격층 앞부분이 섞였다** | `HIT_AT - SLAP_LEAD` 까지만 잰다 |

**최종 오차 +0.3 ms.** 앞서의 ±4ms 는 소리가 아니라 **측정의 문제였다.**

> ⚠️ **`lashHitDelay` 가 바뀌면 `HIT_AT` 도 바꿔 다시 구워야 한다.** 요청-14 에 적어 보냈다.

## 3. 🔴 내 지난 판단 두 개가 틀렸다 — 찾아서 정정했다

### ① 검 0.30 → 0.35 **철회** (C19 / 요청-13 ③)

근거로 댔던 **"서로 다른 적의 타격음은 중복 컷에 안 걸린다"** 가 사실이 아니다.

```csharp
// AudioManager.cs:162 — 키가 "적"이 아니라 "클립"이다
if (_lastPlayedAt.TryGetValue(clip, out float last) && now - last < DedupeWindow) return;
```

`SFX_EnemyHit` 은 **한 클립**이고 `Strike()` 는 부채꼴 안의 적을 **같은 프레임에** 때린다
→ 전부 0.04초 창 안 → **타격음은 1회로 합쳐진다.** 겹치는 일이 애초에 없었다.
**DEV 가 아직 적용하지 않아 손실은 없다.**

### ② 실효 음량 계산이 **클립 피크를 통째로 빼먹었다**

`TUNING.md` 에 `실제 출력 = Volume × sfx_vol(0.31)` 이라 적어 뒀는데 두 군데가 틀렸다:
- `AudioManager.SfxVolume` 기본값은 **1.0** 이다 (`PlayerPrefs` 기본도 1.0)
- 더 중요한 건 **클립마다 피크가 다르다** — `EnemyHit` **0.962** vs `WeaponCast` **0.233**, **4배**

| | Volume | 클립 피크 | **실효** | |
|---|---:|---:|---:|---|
| `EnemyHit`(10) | 0.28 | **0.962** | **0.269** | 실효 2위 |
| `WeaponCast`(2) | 0.45 | **0.233** | 0.105 | 🔑 `Volume` 은 2위인데 실효는 **밑에서 4번째** |

**같은 `Volume` 이라도 실제로 들리는 크기가 4배 벌어진다** = 사다리 순서 자체가 달랐다.
⇒ `Volume` 만 보고 판단하면 안 된다. 이걸 자동으로 찍어 주는 도구를 만들었다(§5).

### ③ 점유율에서 `AttackSpeed` 패시브를 빼먹었다

`WeaponBase.cs:54` 가 `Cooldown × Final.AttackSpeed` 인데 Lv5 가 **×0.70** 이다.
다시 재면 장판은 39% 가 아니라 **56%**. **장판 0.32 결정은 유효하다 — 근거가 오히려 세졌다.**

## 5. 되돌아간 것 — 드래곤이 하필 `WeaponCast` 와 붙었다

초안이 기존 7종 중 **가장 가까운 짝(거리 1.10)** 으로 나왔다. **지금 빌려 쓰는 바로 그 소리다.**
바꾸려고 만든 소리가 원본과 제일 닮았으면 작업의 의미가 없다.

숨 스윕 2800→**2200**Hz · 펄럭임 1800–7000→**1200–4800**Hz 로 무게를
3k–9k 에서 800–3k 로 옮겨 **1.33** 까지 벌렸다.

**이걸 재려고 `Tools/Audio/compare_sfx.py` 를 만들었다.** 무기 소리만 5종이면
짝이 10개고, 하나 고칠 때마다 다시 봐야 한다 — 손으로 못 따진다.
길이 · 어택 · 대역 분포로 짝마다 거리를 찍는다.

> ℹ️ 지금 가장 가까운 짝은 내가 만든 게 아니라 **`ToxinSpill` vs `EnemyHit`(0.98)** 이다.
> 따로 들어 볼 것 — `TUNING.md` 에 항목을 남겼다.

**`Tools/Audio/dsp.py` 도 같이 뺐다.** 같은 biquad 가 4벌이 될 참이었다.
⚠️ **기존 두 스크립트는 일부러 안 고쳤다** — 그 wav 는 이미 임포트됐고 볼륨을 귀로
맞춰 가는 중이라, 리팩터링으로 출력이 1비트라도 달라지면 그 판정이 무효가 된다.
