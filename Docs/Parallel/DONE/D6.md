# D6 — 적 타격감 상수 12개를 CSV 로 (DEV)

> 2026-08-30 · 병렬 세션 DEV · [`REQ/DEV.md` 요청-2](../REQ/DEV.md) (CONTENT `C2`) 처리

## 왜 했나

적 타격감 수치 12개가 `EnemyBase.cs` 에 `const` 로 박혀 있었다.
`TUNING.md` 방침상 **플레이하며 조절해야 하는 값**인데 고칠 때마다 코드를 건드리고
재컴파일해야 했다. CONTENT 가 `Economy.csv` 에 12줄을 이미 넣어 두었고,
**코드와 씬 배선만 남아 있었다.**

### 왜 씬 컴포넌트인가 — 다른 두 길은 막혀 있다

| 시도 | 왜 안 되나 |
|---|---|
| `Economy.csv` 에 `EnemyBase,knockbackForce,6` | `BalanceImporter.FindSceneComponent`(`:892`)가 `FindObjectsByType` 로 **씬만 훑는다.** 적은 **프리팹 1개를 공유**해 씬에 없다 → `! 씬에 EnemyBase 없음` |
| `Enemies.csv` 에 열 추가 | 흔들림·히트스톱은 **엘리트/보스 여부**로 갈리는데 등급은 `EnemyData` 가 아니라 **소환 시점 인자**다 (`Initialize(data, isElite, isBoss)`) |

→ 씬 컴포넌트 하나로 모으면 **임포터를 고치지 않아도** 기존 3열 규칙에 그대로 걸린다.

## 만든 것 — `Assets/Scripts/Enemy/CombatFeel.cs`

설계 결정 두 가지가 핵심이다.

**① `Default*` `const` 를 두고 `[SerializeField]` 초기값이 그것을 참조한다.**
필드 기본값과 "컴포넌트가 없을 때의 폴백"을 **같은 상수 하나**로 묶었다.
숫자가 두 군데로 갈라지면 *컴포넌트가 없을 때만 다른 감각으로 조용히 도는* 상황이
예외 없이 생긴다. 이번 작업의 판정 기준이 "화면이 하나도 안 바뀐다"라 특히 위험했다.

**② `Awake()` 는 자기 등록만 하고, 읽기는 매번 `== null` 로 확인한다.**

```csharp
private void Awake() => _instance = this;

private static CombatFeel Current
{
    get
    {
        if (_instance == null) _instance = FindFirstObjectByType<CombatFeel>(FindObjectsInactive.Include);
        return _instance;
    }
}
```

`Awake` 캐시 금지(I-8/I-38)와 "가짜 null"(I-24)을 **둘 다** 피한다.
씬을 리로드해도 새 인스턴스의 `Awake` 가 다시 채운다.
12개 static 프로퍼티가 `c != null ? c.field : Default*` 로 답하므로
**씬에 컴포넌트가 없어도 예외 없이 기본값으로 굴러간다.**

## 바꾼 것 — `Assets/Scripts/Enemy/EnemyBase.cs`

`const` 3개를 지우고 7군데를 `CombatFeel` 정적 프로퍼티 읽기로 바꿨다.

| 위치 | 전 | 후 |
|---|---|---|
| `ApplyKnockback` | `IsBoss ? 0f : IsElite ? 0.4f : 1f` | `CombatFeel.BossKnockbackResist` / `EliteKnockbackResist` |
| `ApplyKnockback` | `KnockbackForce` · `KnockbackTime` | `CombatFeel.EnemyKnockbackForce` · `EnemyKnockbackTime` |
| `DeathPopRoutine` | `DeathPopTime` · `1.25f` ×2 | 루프 **전에** `popTime`/`popScale` 로 한 번 읽음 |
| `PlayDeathImpact` | `Shake(0.45f/0.20f, 0.5f/0.25f)` | `CombatFeel.Boss*/Elite*ShakeMagnitude·Duration` |
| `PlayDeathImpact` | `DoHitstop(0.09f/0.05f)` | `CombatFeel.BossHitstop` / `EliteHitstop` |

**잡몹의 `1f` 는 빼지 않았다** — 저항 없음이라는 기준값이지 튜닝 대상이 아니다(요청서 명시).

`DeathPopRoutine` 만 루프 전에 지역변수로 읽는다. 연출 도중에 값이 바뀌면 보간이 튄다.
넉백·임팩트는 한 번 읽고 끝이라 그대로 호출해도 된다.

| ⑥ | 폴백이 도나 | ✅ 컴포넌트 없는 상태의 `EnemyKnockbackForce` 가 `6` |

### ⑤ 가 이 작업의 핵심이다

④만으로는 **"안 바뀐 것"과 "안 읽힌 것"을 구분할 수 없다.**
12줄이 전부 원래 값이라 배선이 통째로 죽어 있어도 화면은 똑같다.
그래서 `enemyKnockbackForce` 를 `20` 으로 올려 왕복시켰다.

```
[D6] 기준값 force=20 eliteResist=0.4 bossResist=0
[D6] Enemy_Goblin(Clone) elite=False boss=False 넉백속도=20.000 dir.x=1.00
[D6] 엘리트 넉백속도=8.000  (기대 8.000 = 20 × 0.4)
[D6] 보스   넉백속도=0.000  (기대 0.000 = 저항 0)
```

**CSV → 인스펙터 → 게임** 세 구간이 전부 살아 있다.
엘리트 `8.000` 은 `EliteKnockbackResist` 까지 곱해진 값이라 **저항 2줄도 같이 증명한다.**

복구 후:
```
[D6] ① 잡몹 넉백=6.000 (기대 6.000)
[D6] ② 보스 사망 → timeScale=0 (기대 0 · BossHitstop=0.09)
```

### 엘리트/보스는 노말 웨이브에서 어떻게 검증했나

Elite/Boss 노드로 가지 않고 **기존 적을 `Initialize(data, isElite:true)` 로 재초기화**했다.
등급이 `EnemyData` 가 아니라 소환 인자라 런타임에 바꿔 끼울 수 있다.

**히트스톱은 보스만 잡혔다.** `DoHitstop` 은 `CurrentState != Wave` 면 return 하고
`_hitstopRoutine != null` 이면 무시한다(겹침 방지) — 연달아 부르면 두 번째가 안 걸린다.
엘리트는 `EliteKnockbackResist` 실측(`8.000`)으로 `CombatFeel` 읽기가 이미 증명됐고,
히트스톱은 보스와 **완전히 같은 한 줄**(`DoHitstop(IsBoss ? Boss : Elite)`)이다.

**카메라 흔들림은 값을 직접 못 읽었다.** `CameraController._shakeTimer` 가 private 이고
`RunCommand` 는 `System.Reflection` 이 금지다. `PlayDeathImpact()` 안에서 `Shake` 는
`DoHitstop` **바로 앞줄**이라 `timeScale=0` 이 걸린 것이 그 줄도 돌았다는 증거다.

## 🔴 알아 둘 것 — `GameManager` 는 프리팹 인스턴스다

`CombatFeel` 이 씬에 **프리팹 오버라이드**로 붙었다:

```yaml
m_AddedComponents:
- targetCorrespondingSourceObject: {fileID: 8731808528067922064, guid: 0166ba72...}
  addedObject: {fileID: 1501063833}
```

동작에는 문제가 없다 — `FindSceneComponent` 는 씬을 훑으므로 그대로 잡힌다(검증 완료).
다만 **프리팹 오버라이드를 Revert 하면 컴포넌트가 통째로 사라진다.**
그러면 `Economy.csv` 12줄이 `! 씬에 CombatFeel 없음` 으로 조용히 건너뛰어지고,
게임은 `Default*` 폴백으로 굴러간다 — **에러 없이 CSV 만 먹통이 된다.**
