## 왜 했나

무기 두 개가 **자기 소리가 없어서 남의 것을 쓰고 있었다.**

| 무기 | 나던 소리 | 실제로 하는 일 |
|---|---|---|
| 검 (D10 에서 근접으로 재해석) | `WeaponFire` = **총소리** | 칼을 휘두른다 |
| 독 장판 (D11 신설) | `WeaponCast` = **마법 시전음** | 독을 바닥에 쏟는다 |

이게 배선 문제가 아니라 **판정 문제**라서 먼저 해야 했다.
`TUNING.md` §3 의 근접 7값·장판 값들은 "안 시원하다"를 재는 항목인데,
그 원인이 `halfAngle` 이 아니라 **총소리**일 수 있다. 소리를 안 고치고 숫자를 흔들면
**엉뚱한 값이 굳는다.**

### 임포트 규격을 손으로 맞췄다

Unity 기본값은 프로젝트 규격과 **다르다.** Refresh 직후 두 wav 는
`compressionFormat: 1`(Vorbis) · `forceToMono: 0` 으로 들어왔다 — 기존 SFX 는 전부
`2`(ADPCM) · `1` 이다. `AudioImporter` 를 직접 세팅하고 `SaveAndReimport()` 했다
(D8 에서 같은 함정을 밟았다).

```
loadType 0 · compressionFormat 2(ADPCM) · quality 1 · 44100 · preloadAudioData 0
forceToMono 1 · normalize 1 · 3D 1
```

> ℹ️ **CONTENT 는 스테레오로 구워 왔지만 프로젝트가 모노로 접는다.**
> 요청서의 "모노 합산 피크 0.344 / 0.383" 이 **실제로 들리는 값**이다.
> 좌우 상쇄가 없다고 미리 재 둔 게 그대로 맞았다 — 실측 `ch=1`.

## 어떻게 확인했나

### 임시 프로브 — `Assets/Scripts/Dev/D14SfxProbe.cs` (**삭제됨**)

`AudioManager` 의 보이스 풀(16개)을 매 프레임 훑어 **새로 시작한 클립**을 로그로 남긴다.
빌려 쓰던 `WeaponFire`·`WeaponCast` 도 **대조군으로 같이** 셌다 — "새 소리가 난다"만으로는
**옛 소리가 같이 나는지**를 알 수 없기 때문이다.

🔴 **상승 엣지를 `isPlaying` 만으로 잡으면 안 된다.** 보이스는 재사용되므로
`isPlaying` 이 계속 `true` 인 채 클립만 바뀌는 순간을 놓친다. `(!wasPlaying || clip != lastClip)`
두 조건을 같이 봤다.

Sword Lv5(3연타) + Toxin Lv1 을 지급하고 한 판 돌렸다.

```
[D14] 프로브 시작 — 보이스 17개, SfxVolume=0.31
[D14] SWING #1 vol=0.094 pitch=1.115 t=42.491
[D14] SWING #5 vol=0.094 pitch=0.971 t=48.496
[D14] SWING #6 vol=0.094 pitch=0.968 t=48.745
[D14] SWING #7 vol=0.094 pitch=0.968 t=48.999
[D14] TOXIN #1 vol=0.119 pitch=1.072 t=47.634
[D14] 프로브 집계 — Swing=7 Toxin=1 | 대조 Fire=0 Cast=0
```

### 판정

| # | 확인할 것 | 결과 |
|---|---|---|
| ① | 클립 2개가 `Assets/Game/Audio/` 에 있고 `AudioLibrary` 에 물렸다 | ✅ `GetSfx(4)`→`SFX_WeaponSwing` · `GetSfx(5)`→`SFX_ToxinSpill` |
| ② | Swing **0.30/0.12** · Toxin **0.38/0.10** | ✅ 실측 그대로 |
| ③ | `WeaponSwing=4` · `ToxinSpill=5` · 기존 번호 무변경 | ✅ 1·2·3·10·11·… 전부 그대로 |
| ④ | `MeleeWeapon` 에 `WeaponFire` 가, `FieldWeapon` 에 `WeaponCast` 가 없다 | ✅ + **실플레이 대조 Fire=0 / Cast=0** |
| ⑤ | 컴파일 에러 0 | ✅ |
| ⑥ | 검 = 총소리가 아닌 "쉭" | 🟡 **지정 클립이 울리는 것까지 확인.** 소리 자체는 사람이 들어야 한다 |
| ⑦ | 장판 = 마법음이 아닌 "철퍽 + 치익" | 🟡 〃 |
| ⑧ | Lv5 3연타가 뭉개지지 않는다 | 🟡 **간격 실측 0.249 · 0.254s** (설계 0.247s 와 일치). 겹침 **31ms** — 뭉개짐 여부는 청취 |
| ⑨ | 둘을 같이 들었을 때 구분된다 | 🟡 청취 |
| ⑩ | 원거리·폭탄 소리는 그대로 | ✅ `ProjectileWeapon:26` · `AoeWeapon:28` · `SummonWeapon:159,174` 무변경 |

**볼륨 실측이 계산과 맞다** — Swing `0.30 × 0.31(sfx_vol) = 0.094` · Toxin `0.38 × 0.31 = 0.119`.

> ℹ️ **이번엔 소리가 들린다.** D8 때 이 기계의 `sfx_vol` 이 `0.00` 이라 청취 판정이 통째로
> 막혔었는데 지금은 `0.31` 이다. 🟡 4건은 "못 들어서"가 아니라 **기계가 판정할 수 없어서** 남는다.

## 알게 된 것

### 🔴 검 클립이 연타 간격보다 **이미** 길다 — 늘릴 여지가 없다

| 값 | 실측 |
|---|---|
| `SFX_WeaponSwing` 길이 | **0.280s** |
| Lv5 연타 간격 (`hitDelay 0.067` + `comboInterval 0.18`) | **0.247s** (프로브 실측 0.249·0.254) |
| 겹침 | **0.031s** |

CONTENT 는 이걸 알고 만들었다 — "3연타 합성 피크 0.400 = 1타와 동일" 이라고 미리 재 놨고,
겹치는 31ms 는 이미 페이드아웃 구간이다. **문제가 아니다.**

다만 요청서 "같이 남겨 줄 것" **4번**의 선택지 하나가 **쓸 수 없다**:
검이 "탁"으로 들려서 `DUR` 을 **0.28 → 0.34 로 늘리면 겹침이 31ms → 93ms 가 된다.**
그때는 클립이 아니라 `MeleeWeapon.comboInterval`(0.18) 을 같이 올려야 하고,
그건 **연타의 손맛을 바꾸는 일**이라 CONTENT 혼자 정할 수 없다.
→ [`REQ/CONTENT.md` 요청-8](../REQ/CONTENT.md) 에 이 조건을 적어 보냈다.

### `AudioLibrary` 는 파일이 아니라 `SerializedObject` 로 고쳤다

`.asset` YAML 을 직접 쓰면 **에디터가 들고 있는 메모리 사본이 이기고** 다음 저장에
덮어써질 수 있다. `SerializedObject` → `ApplyModifiedPropertiesWithoutUndo` → `SaveAssets` 로
넣고 디스크를 다시 읽어 확인했다. 재실행해도 안전하도록 **Id 4·5 가 이미 있으면 중단**하게 짰다.
