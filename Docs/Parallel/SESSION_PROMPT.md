# VS_LIKE 병렬 세션 공통 프롬프트

> 세션을 열 때 아래를 **그대로 붙여넣는다.** 맨 윗줄의 파트만 바꾼다.
> `CLAUDE.md` 규칙은 전부 그대로 유효하고, 아래는 그 위에 얹는 병렬 규칙이다.

---

```
# VS_LIKE 병렬 세션 규칙

내 파트: <DEV | CONTENT>

너는 동시에 도는 2개 세션 중 하나다. 두 세션이 **같은 작업 트리**
(C:\Unity\VS_LIKE)와 **같은 Unity 에디터 하나**를 공유한다.
- DEV     = 개발·뼈대. 코드 · 씬 배선 · 에디터 전담 · 실플레이 검증
- CONTENT = 코드 외적. 그림 · 소리 · 애니메이션 소스 · 수치 · 문서
CLAUDE.md 규칙은 전부 유효하다. 아래는 그 위에 얹는 규칙이다.

## 1. 소유 경로
Docs/Parallel/BOARD.md §0 표를 따른다.
**소유하지 않은 경로는 읽기만 한다.** 고쳐야 하면 §4 로 요청을 남긴다.

## 2. 작업 시작 전 — 건너뛰지 말 것
1. Docs/Parallel/BOARD.md §1 — 상대 세션이 지금 만지는 경로
2. Docs/Parallel/BOARD.md §2 — 에디터 상태 (BROKEN 이면 그게 최우선일 수 있다)
3. Docs/Parallel/REQ/<내파트>.md — **상대 세션이 나에게 요구한 일**
   → `열림` 이 있으면 사용자 지시보다 먼저 처리할지 **물어본다**
4. Docs/Parallel/BUGS.md — 담당이 내 파트인 미해결 버그
5. Docs/TODO.md §1 — 기존 규칙
6. BOARD.md §1 에 내 줄 등록, §3 에서 이슈 번호를 선점하고 다음 번호로 올린다
   ⚠️ 경로가 상대 세션과 겹치면 **착수하지 말고 사용자에게 알린다**

## 3. Unity 에디터는 하나다 — DEV 전담

**언제나 자유로운 것** (양쪽 다, 물어볼 필요 없다)
- 코드·문서·애셋 **읽기**, 분석, 설계, 조사
- 내 소유 경로의 파일 편집·저장

**CONTENT 가 절대 하지 않는 것**
- Assets/Refresh · 메뉴 실행 · CSV Import · 플레이 모드 · 콘솔 읽기 ·
  카메라 캡처 · 애셋 임포트 · Unity AI 생성 · .unity/.prefab/.asset 편집
- CONTENT 는 .csv 를 **저장만** 하고, 새 png/wav 는 **`_Incoming/`**(Assets 밖)에
  두는 데까지만 한다. 그 다음은 §4 요청이다

**DEV 규칙**
- 상태가 바뀔 때마다 BOARD.md §2 를 갱신한다 (IDLE / BUSY / PLAYING / BROKEN)
- 🔴 IDLE 로 되돌리기 전에 **컴파일 에러 0** 을 확인한다.
  에러를 남기면 상대 세션의 검증이 통째로 막힌다
- 플레이 모드에선 CSV Import 가 InvalidOperationException 으로 실패한다.
  일시정지(Paused)도 플레이 모드다 — Stop 을 먼저 한다
- 컴파일 에러의 원인이 **CONTENT 소유 파일**이면 BROKEN 으로 두고
  REQ/CONTENT.md 에 요청을 남긴다. **남의 파일을 직접 고치지 않는다**

**⚠️ 에디터 설정 — 시작 전에 한 번**
Preferences > Asset Pipeline > **Auto Refresh 를 꺼 둔다.**
켜져 있으면 CONTENT 가 파일을 저장하는 것만으로 임포트가 돌아
DEV 의 플레이 중에 도메인 리로드가 터진다.

## 4. 상대 세션에 일을 넘길 때
Docs/Parallel/REQ/<대상>.md 맨 아래에 한 줄 추가한다.
**쓰기 직전에 파일을 다시 읽는다** (동시 쓰기는 마지막이 이긴다).

| 요청일시 | 요청자 | 상태 | 요청 내용 | 참조 |

- 남의 소유 경로를 **직접 고치지 않는다.** 요청만 남긴다
- 요청에는 **무엇을 / 왜 / 어떻게 확인하나** 셋을 반드시 적는다
- 처리했으면 상태를 `닫힘(D3)` 으로 바꾼다. **줄을 지우지 않는다**
- 내가 그 요청 때문에 막혀 있으면 BOARD.md 내 줄 상태를 `대기(REQ→DEV)` 로
- CONTENT 는 작업을 끝내면 **거의 항상** REQ/DEV.md 에 요청이 하나 생긴다
  (Import / 배선 / 검증). 잊지 말 것

## 5. 버그를 발견했을 때 — 내 파트가 아니어도
Docs/Parallel/BUGS.md 에 적고 **고치지 않는다** (CLAUDE.md §1 그대로).
**쓰기 직전에 파일을 다시 읽고**, 맨 아래 번호 +1 (B1, B2…) 을 쓴 뒤
BOARD.md §3 의 다음 번호도 같이 올린다.

| # | 발견일 | 발견자 | 담당 | 증상 / 재현 절차 | 상태 |

- `재현 절차`는 **상대 세션이 그대로 따라할 수 있게** 쓴다.
  "가끔 안 됨" 은 리포트가 아니다. 조작 순서와 콘솔 로그까지 적는다
- 담당 판정이 애매하면 BUGS.md 하단 기준표를 본다
- 내 작업이 그 버그 때문에 **검증 불가능한 경우에만**
  사용자에게 알리고 허락을 받아 고친다
- 🔴 **"동작하나?"만 여기 적는다.** "느낌이 맞나?"는 TUNING.md,
  "아직 안 만들었다"는 TODO.md 다

## 6. 이슈 번호
세션 첫 글자 + 일련번호: DEV=D1,D2… / CONTENT=C1,C2… / 버그는 공용 B1,B2…
번호는 BOARD.md §3 에서 선점하고 **즉시** 다음 번호로 올린다.
과거 이력의 I-1~I-61 은 그대로 둔다.

## 7. 공용 문서에 직접 쓰지 않는다
SETUP_STATUS.md / TODO.md 는 두 세션이 동시에 쓰면 서로 덮어쓴다.
- 완료 기록은 Docs/Parallel/DONE/<이슈번호>.md 에 쓴다
  (원인 → 변경 파일 표 → 검증 로그 — CLAUDE.md §1 형식 그대로)
- SETUP_STATUS.md / TODO.md / ROADMAP.md 반영은 **DEV 세션만** 한다
  (검증까지 끝난 걸 아는 유일한 세션이므로)
- 예외: TODO.md 에서 **내 항목 체크박스 한 줄 제거**는 허용.
  단 지우기 **직전에 파일을 다시 읽는다**
- BALANCE.md / TUNING.md 는 CONTENT 소유. DEV 는 §4 요청으로

## 8. 커밋
- 커밋 전 `git status` 로 **상대 세션의 파일이 섞였는지** 반드시 본다
- 🔴 `git add -A` / `git add .` **금지.** 내 소유 경로만 명시해서 add
- 남의 변경이 섞였으면 **커밋하지 말고** 사용자에게 알린다
- 제목 끝에 파트 태그: `승급 초상화 4종 (C4, CONTENT)`
- 푸시는 물어보고. --no-verify / --amend / push --force 금지
- ⚠️ 두 세션이 같은 트리를 쓴다. 커밋은 **한 번에 하나씩**.
  상대가 커밋 중인지는 BOARD.md 로 알 수 있다

## 9. 보고
단계별 보고 맨 앞에 [CONTENT/C2] 처럼 파트·이슈를 붙인다.

## 10. 작업 종료
BOARD.md §1 의 내 줄을 지운다.
DEV 면 §2 를 IDLE 로 (에러 0 확인 후).
```

## 이 구조가 해결하지 못하는 것

- **검증은 여전히 직렬이다.** CONTENT 가 아무리 뽑아내도
  임포트·배선·실플레이는 DEV 하나가 다 한다 → DEV 가 병목이 된다.
  `TODO.md` §1 의 미검증 항목은 **병렬화로 줄지 않는다**
- 파일 동시 쓰기는 git 머지가 아니라 **마지막 쓰기 승리**다.
  "쓰기 직전 재읽기"가 유일한 보호막이다
- CONTENT 는 **자기 결과물을 눈으로 볼 수 없다.** 게임 화면에 어떻게 나오는지는
  DEV 의 검증 보고로만 안다 → 요청에 **판정 기준**을 적는 게 그래서 중요하다
