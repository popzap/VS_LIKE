## 1. 수치가 실제로 있는 곳

고치는 비용이 다르다. **튜닝 루프의 속도가 여기서 갈린다.**

| 대상 | 위치 | 반영 방법 | 비용 |
|---|---|---|---|
| 플레이어 스탯 · 무적 · 넉백 · 상점 · XP 곡선 | `Assets/Game/Balance/Economy.csv` | `Game/Balance/Import CSV -> ScriptableObjects` | 즉시 (재컴파일 없음) |
| 적 스탯 · AI 파라미터 | `Enemies.csv` | 〃 | 즉시 |
| 무기 · 패시브 · 아이템 · 진화 | `Weapons.csv` `Passives.csv` `Items.csv` `Evolutions.csv` | 〃 | 즉시 |
| 직업 · 승급 · 소지 상한 | `Classes.csv` `ClassEvolutions.csv` | 〃 | 즉시 |
| 웨이브 구성 · `MaxAlive` | `Waves.csv` | 〃 | 즉시 |
| 건물 산출 | `Buildings.csv` | 〃 | 즉시 |
| 드랍 확률 · 애셋 배열 | `SceneWiring.csv` | 〃 | 즉시 |
| 오디오 클립별 볼륨 · 피치 | `Assets/Game/Audio/AudioLibrary.asset` (인스펙터) | 저장만 | 즉시 |
| BGM/SFX 마스터 볼륨 | 씬의 `AudioManager` 인스펙터 | 저장만 | 즉시 |
| 🟡 **적 넉백 · 사망 팝 · 히트스톱 · 처치 흔들림** | `Economy.csv` 의 `CombatFeel` 12줄 **(표는 넣었고 컴포넌트는 DEV 대기 — C2)** | 〃 | 즉시 **(배선 후)** |

> ⚠️ **Import 는 플레이 모드에서 못 돈다** (`MarkSceneDirty` 제약). 일시정지도 플레이 모드다.
> 플레이를 멈추고 → Import → 다시 플레이가 한 사이클이다.

### 🟡 적 타격 반응을 CSV 로 뺀다 — `CombatFeel` (I-59 에서 발견 → C2 에서 처리 중)

I-44 로 넣은 **적** 쪽 타격 반응이 `EnemyBase.cs` 에 `const` 로 박혀 있었다.
**플레이어** 쪽(`knockbackForce` 9 · `shakeMagnitude` 0.18 등)은 `Economy.csv` 에 있는데
적 쪽만 빠졌다. **하필 이 값들이 §2-A 에서 가장 많이 만지게 될 것들이다** —
한 번 고칠 때마다 도메인 리로드를 기다려야 해서 튜닝 루프가 몹시 느려진다.

#### 왜 `EnemyBase,knockbackForce` 로 못 넣나

두 번 막혔다. 둘 다 확인하고 기각했다.

| 시도 | 왜 안 되나 |
|---|---|
| `Economy.csv` 에 `EnemyBase,...` 로 추가 | 임포터(`BalanceImporter.FindSceneComponent`)가 **씬만 훑는다**(`FindObjectsByType`). 적은 **프리팹 1개를 공유**하므로 씬 컴포넌트가 아니다 → `! 씬에 EnemyBase 없음` |
| `Enemies.csv` 에 열로 추가 | 흔들림·히트스톱은 **엘리트/보스 여부**로 갈리는데, 등급은 `EnemyData` 가 아니라 **소환 시점 인자**다(`Initialize(data, isElite, isBoss)`). 게다가 같은 숫자를 **6줄에 복붙**하게 된다 |

#### 확정 — `CombatFeel` 씬 컴포넌트 (사용자 결정, 2026-08-30)

GameManager 오브젝트에 `CombatFeel` 을 하나 붙이고, 적이 **쓰는 시점에** 읽어 간다.
임포터는 **고칠 게 없다** — 씬 컴포넌트라 기존 3열 규칙에 그대로 걸린다.

| 항목 | 값 |
|---|---|
| CSV | `Economy.csv` §적 타격감 — **12줄. 이미 넣었다 (C2)** |
| 코드 | `CombatFeel.cs` 신설 + `EnemyBase` 가 `const` 대신 읽기 — **DEV 대기** |
| 기준선 | 12줄 전부 **지금 `const` 값 그대로**다. 첫 Import 는 **화면이 안 바뀌는 게 정상** |

| 값 | 현재 | 원래 위치 |
|---|---:|---|
| `enemyKnockbackForce` | 6.0 | `EnemyBase.cs:354` |
| `enemyKnockbackTime` | 0.10 | `EnemyBase.cs:355` |
| `eliteKnockbackResist` · `bossKnockbackResist` | 0.4 · 0 | `EnemyBase.cs:384` |
| `deathPopTime` · `deathPopScale` | 0.14 · 1.25 | `EnemyBase.cs:435` `:450` |
| 엘리트 흔들림 · 히트스톱 | `0.20 / 0.25s` · `0.05s` | `EnemyBase.cs:469` `:471` |
| 보스 흔들림 · 히트스톱 | `0.45 / 0.5s` · `0.09s` | 〃 |

> ℹ️ **넉백 저항 2줄은 원래 표에 없던 것을 새로 뺀 것이다.** `EnemyBase.cs:384` 의
> `IsBoss ? 0f : IsElite ? 0.4f : 1f` 도 똑같이 감각으로 정한 숫자인데 상수로 박혀 있었다.
> **"보스는 아예 안 밀린다"가 옳은지**는 플레이해 봐야 아는 값이다.

## 2. 체감 판정 체크리스트

각 항목은 **[ ] 무엇을 보나 → 이상하면 어디를 얼마나** 형식이다.
판정이 끝나면 체크하고 §4 에 결과를 남긴다.

### A. 플레이어 · 타격감

- [ ] **맞았을 때 맞은 걸 아는가** — 넉백 `9 / 0.15s` + 붉은 플래시 `0.12s` + 화면 흔들림 `0.18`
      + `PlayerHit` 사운드(0.70). 넷이 동시에 터진다.
      → 과하면 `shakeMagnitude` 부터 낮춘다 (`Economy.csv`). 흔들림이 가장 먼저 피로해진다
- [ ] 🔴 **`invincibleTime` 0.6 초** — **난이도에 가장 크게 작용하는 단일 수치다.**
      적 하나가 붙어 있을 때 초당 피해 = `ContactDamage ÷ 0.6`.
      Zombie(12)면 초당 20, Ogre(25)면 초당 42 — 체력 100 이면 **2.4초에 죽는다**
      → 너무 빨리 죽으면 0.8~1.0 으로. 너무 안 죽으면 0.4 로
- [ ] **`MoveSpeed` 4 가 답답하지 않은가** — 가장 빠른 적 **Wolf(4.2)보다 느리다.**
      늑대에게서 도망칠 수 없다는 뜻이다. 의도라면 두고, 아니면 5 로
- [ ] **적 넉백 6.0** 이 대열을 너무 흩뜨리지 않는가 — 뱀서라이크는 적이 **뭉쳐 있어야**
      쓸어 담는 맛이 난다. 흩어지면 3~4 로 (`CombatFeel,enemyKnockbackForce`)
- [ ] **사망 팝 0.14초** 가 시체를 쌓아 보이게 하지 않는가 (`CombatFeel,deathPopTime`)
- [ ] 🔴 **엘리트/보스 처치 히트스톱이 렉처럼 느껴지지 않는가** — 일반 0.05s · 보스 0.09s.
      **노말 웨이브에서는 검증할 수 없다**(엘리트가 안 나옴). Elite/Boss 노드로 가야 한다
      (`CombatFeel,eliteHitstop` · `bossHitstop`)
- [ ] **보스가 안 밀리는 게 위압감으로 읽히는가 아니면 그냥 안 맞는 것처럼 보이는가** —
      지금 보스는 넉백 저항 **0**(전혀 안 밀림), 엘리트는 0.4 다.
      때리는 반응이 아예 없어 보이면 보스를 0.1~0.15 로 (`CombatFeel,bossKnockbackResist`).
      ⚠️ 올리면 **벽 없는 아레나에서 보스가 밀려 도망갈 수 있다** — 그게 원래 0 인 이유다
- [ ] **플레이어 1.0 유닛 / 일반 적 0.5 유닛** 비율이 실전투에서 맞는가 —
      주인공이 일반 몹의 2배다. 엘리트(×1.3 → 0.65)·보스(×2 → 1.0)와 나란히 놓였을 때
      **위압감이 사는지**
- [ ] **플레이어 걷기** — 프레임 속도 `framesPerSecond` 12 에서 발이 겉돌지 않는지 ·
      기울기 `leanAmount` 0.10 이 과하지 않은지 (피벗이 Center 라 **발도 반대로 살짝 밀린다**)

  한 번 들어서 괜찮아도 30번 들으면 거슬릴 수 있어 한 칸 낮췄다

**만든 방식** — `Tools/Audio/gen_sword_swish.py` · `gen_toxin_splash.py`.
`Tools/Art/` 의 그림과 같이 **절차 생성이라 파라미터를 고쳐 다시 구울 수 있다.**

| 설계 | 검 (`WeaponSwing`) | 독 장판 (`ToxinSpill`) |
|---|---|---|
| 밴드패스 스윕 | 700 → **5200** → 1500 Hz (**올라간다**) | 900 → **260** Hz (**내려간다**) |

| 어택 | 25% 구간 smoothstep | **8ms** |
| 왜 어택이 반대인가 | 🔴 **딱 하는 시작음이 곧 총소리다.** 일부러 없앴다 | 🔴 **철퍽은 순간이어야 한다.** 없으면 김 빠지는 소리다 |

| 피크 / RMS | 0.400 / 0.053 | 0.420 / 0.054 |

🔑 **거품 층이 핵심이다.** 고역 노이즈만 있으면 "치이익" 하는 **스프레이**로 들린다.

| 🔴 **`spriteRadiusAtScaleOne`(장판)** | `Proj_ToxinField.prefab` **0.97** | 🔴 **체감값이 아니다. 손대지 말 것** — D11 이 그림의 알파를 실측한 값이다(그려진 원 반지름 ≈97px / PPU 100). 셀 중심도 (128,128)이 아니라 (134,132)라 **Custom pivot** `(0.5234, 0.4844)` 가 같이 걸려 있다. 흔들면 **맞는 원과 보이는 원이 어긋난다** (검증된 화면 오차 0.7px → 보정 없으면 6.7px). 크기는 위 `ProjectileSize` 로 고칠 것 |
| **소환수 크기** (C13·C14) | 드래곤·문어 둘 다 **0.26유닛** (셀 256 중 132~136px · PPU 512) = **오거의 65%** | 🔴 **`localScale` 로 고치지 말 것.** 그림 자체가 작게 그려져 있다 — 스케일로 줄이면 픽셀이 뭉개지고, 키우면 외곽선이 두꺼워진다. **무엇을 보나:** 소환수 2마리가 플레이어를 따라다닐 때 ①플레이어가 가려지나 ②난전에서 적과 헷갈리나. 가리면 작게, 안 보이면 크게 → `Tools/Art/gen_dragon.py` · `gen_octopus.py` 의 **`TARGET_H`(34)** 를 고치고 다시 굽는다 (시트·아이콘이 같이 나온다). ⚠️ **둘의 값을 따로 놀게 두지 말 것** — 같은 체급인 게 설계다 |
| **촉수 공격 반경** (C14) | `TentacleLash.png` 바깥 반지름 **0.9951유닛** (실측 99.51px / PPU 100) | 🔴 **체감값이 아니다.** 호(`1.074`)와 달리 **1.0 에 맞춰 그렸으므로** 코드가 나눌 필요가 없다 — `localScale = Range` 로 두면 그림이 곧 판정이다. 크기를 바꾸고 싶으면 **`Weapons.csv` 의 `Range`** 를 고친다. 그림 쪽을 바꿔야 할 이유가 생기면 `gen_octopus.py` 의 `R_MAX`(99.0)이고, 그땐 **이 문서의 숫자도 같이** 고친다 |
| **소환수 애니메이션 속도** (C13·C14) | 아직 **정한 사람이 없다** — 프리팹 `frameRate` (D 세션이 만들 때 정한다) | 16프레임이 **한 번의 날갯짓 / 한 호흡**이다. 12fps면 1.33초, 20fps면 0.8초. **무엇을 보나:** 드래곤이 **날고 있어 보이나**(느리면 떠 있는 게 아니라 멈춘 것 같다) · 문어가 **물속에 있어 보이나**(빠르면 경련한다). 촉수 이펙트 6프레임은 별개다 — 호의 `30`(0.2초)과 같은 감각으로 시작 |
