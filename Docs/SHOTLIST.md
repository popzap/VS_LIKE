## 0. 촬영 전 공통 설정

| 항목 | 값 | 왜 |
|---|---|---|
| Game 뷰 | **1920×1080 고정** (Free Aspect 아님) | 영상 비율이 흔들리면 편집이 어렵다 |
| 화면 녹화 | 60 fps 이상 | 🔴 **끊김을 보여 주는 샷은 30 fps 로 찍으면 안 된다** — 렉인지 녹화 탓인지 구분이 안 된다 |
| Unity 레이아웃 | Game 뷰 **최대화** (`Shift+Space`) | 인스펙터·콘솔이 보이면 화면이 지저분하다 |
| Stats 오버레이 | 샷마다 지정 (아래 표) | fps 를 보여 줄 샷과 게임만 보여 줄 샷이 다르다 |
| 🔴 마우스 | **Game 뷰 안에서 클릭 금지** | 레벨업 카드가 눌리면 무기 구성이 바뀐다 (`PERF.md` §1-3-1) |

> ℹ️ **`__PerfHarness` 오브젝트가 씬에 있으면 자동으로 측정을 시작한다.**
> 촬영용으로 플레이할 때는 인스펙터에서 `autoRun` 을 끄거나 오브젝트를 지울 것.

### 🔑 Dev 패널의 촬영 도구 (백틱 `` ` ``)

`Enemy Spawn` 절이 있다. **하네스 없이** 촬영을 통제할 수 있다.

```
Enemy Spawn  (load test / capture)
  alive 0      [+100] [+200] [+400] [+800]  [Clear]
  radius 12    ━━━●━━━━━━     [Invincible 60s]
  ☐  neighbour cap 12  (B8 = before)      limit = 64
```

| 버튼 | 하는 일 |
|---|---|
| `+100 ~ +800` | 플레이어 주변 반경 안에 즉시 소환 (`EnemyData` 6종을 돌아가며) |
| `Clear` | **씬 전체**의 적을 치운다 — 웨이브가 얹은 것까지 |
| `radius` | 4~25. 좁히면 더 뭉쳐 보인다 |
| `Invincible 60s` | 촬영 중 안 죽게 |
| 🔑 `neighbour cap 12` | **켜면 수정 전(12칸 절단) 동작이 그대로 재현된다** |

> 🔴 **`neighbour cap` 토글이 S2 의 핵심이다.** 원래 `NeighborBufSize` 는 `const` 라
> 12 ↔ 64 를 바꾸려면 재컴파일 + 도메인 리로드가 필요했고, 그러면 A벌과 B벌이
> **다른 세션**이 되어 비교가 오염된다 (측정에서 실제로 겪은 문제 — `PERF.md` §7-H 결과 ②).
> 배열은 64 로 두고 런타임에 `n` 만 자르므로 **같은 세션·같은 적 무리**로 비교할 수 있다.

⚠️ Dev 패널이 열려 있는 동안 게임은 멈춘다. **소환하고 닫은 뒤** 촬영을 시작할 것.

## 2. 성능 섹션용 — 움직임이 본질인 것

### S2. 적이 뭉치는 모습 (`B8` 의 체감)

| | |
|---|---|
| **왜** | `PERF.md` §8-6 의 *"적 800에서 85 %가 0.5유닛 안에 이웃을 둔다"* 를 **눈으로** 보여 준다. 숫자만으로는 "그래서 얼마나 겹치는데?" 가 안 와닿는다 |
| **길이** | 8~12초 × 2벌 |
| **순서** | ① `` ` `` → `+400` → `Invincible 60s` → 닫고 **10초 촬영** (cap 64 = 수정 후)<br>② `` ` `` → **`neighbour cap 12` 체크** → 닫고 **10초 촬영** (= 수정 전) |
| **핵심** | **같은 세션 · 같은 적 무리 · 토글만 다름.** 다시 소환하면 배치가 달라져 비교가 약해진다 |
| **담아야 할 것** | 적 무리가 플레이어를 따라오며 **서로 겹치는/덜 겹치는** 정도 |
| Stats | 끈다 |

⚠️ **정직하게 말해 두자면 A/B 차이가 눈에 잘 안 보일 수 있다** — 측정에서도 `0.5유닛내` 비율이
84.6 % → 85.1 % 로 거의 안 변했다. **차이가 안 보이면 그것도 결과다.**
그 경우 "버퍼를 키워도 겹침은 안 줄었다"는 §8-6 의 결론을 **영상이 뒷받침**하게 된다.

### ~~S3. 적 800 + 무기 난사~~ — ✘ **찍었지만 쓰지 않는다** (2026-09-02)

**촬영은 했는데 체감이 안 잡힌다.** 영상 대신 **데이터로 보여 준다**
→ [`fig6_frametime.svg`](Figures/fig6_frametime.svg)

🔑 **안 보이는 것이 정상이다 — 측정 결과와 일치한다.**

| | |
|---|---|
| 실제 게임 상한(130) | p50 **4.55 ms** (≈220 fps) · p99 **9.06 ms** — 60 fps 예산의 절반 |
| 적 800 | p50 은 멀쩡하고 **꼬리만** 터진다 (p95 38.6 · p99 43.7 ms) |

60 fps 녹화에서 **가끔 오는 40 ms 프레임 하나**는 눈으로 잡히지 않는다.
극적으로 보이게 편집하면 **그게 거짓말이 된다.**

> 🔑 이 실패 자체가 결론을 뒷받침한다 —
> *"적이 많으면 렉이 생긴다"* 는 전제는 §7-E 에서 이미 반증됐다.
> **영상이 밋밋한 것은 게임이 실제로 그 구간에서 멀쩡하기 때문이다.**

**찍어 둔 영상은 버리지 말 것.** "적 800 을 세워 놓고도 이 정도로 돈다"는
**긍정적 근거**로 쓸 수 있다 (Stats 오버레이가 화면에 있으므로).

### S4. 경험치 구슬이 쌓이는 모습

| | |
|---|---|
| **왜** | `ExpDrop`·`WorldPickup` 은 **수명이 없어 주울 때까지 영원히 남는다**(§8-7). 화면이 구슬로 덮이는 그림이 이 문제를 한 방에 설명한다 |

| **담아야 할 것** | 시간이 갈수록 바닥이 구슬로 덮이는 것. **타임랩스로 편집하면 더 좋다** |
