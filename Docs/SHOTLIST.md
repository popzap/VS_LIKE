> **움직임이 본질인 것만** 여기 적었다. 정지 화면으로 설명되는 것은 전부
> [`Figures/`](Figures) 의 SVG 로 이미 만들어져 있다.

> **최종 갱신:** 2026-09-02 · 근거는 [`PERF.md`](PERF.md)

## 0. 촬영 전 공통 설정

| 항목 | 값 | 왜 |
|---|---|---|
| Game 뷰 | **1920×1080 고정** (Free Aspect 아님) | 영상 비율이 흔들리면 편집이 어렵다 |
| 화면 녹화 | 60 fps 이상 | 🔴 **끊김을 보여 주는 샷은 30 fps 로 찍으면 안 된다** — 렉인지 녹화 탓인지 구분이 안 된다 |
| Unity 레이아웃 | Game 뷰 **최대화** (`Shift+Space`) | 인스펙터·콘솔이 보이면 화면이 지저분하다 |
| Stats 오버레이 | 샷마다 지정 (아래 표) | fps 를 보여 줄 샷과 게임만 보여 줄 샷이 다르다 |
| 🔴 마우스 | **Game 뷰 안에서 클릭 금지** | 레벨업 카드가 눌리면 무기 구성이 바뀐다 (`PERF.md` §1-3-1) |

> ℹ️ **`__PerfHarness` 오브젝트가 씬에 있으면 자동으로 측정을 시작한다.**
> 촬영용으로 플레이할 때는 인스펙터에서 `autoRun` 을 끄거나 오브젝트를 지울 것.

> 🔴 이건 촬영이자 **미검증 경로의 검증**이다. `TODO.md` §1 에 반 년간 열려 있던 항목이다.

## 2. 성능 섹션용 — 움직임이 본질인 것

### S2. 적이 뭉치는 모습 (`B8` 의 체감)

| | |
|---|---|
| **왜** | `PERF.md` §8-6 의 *"적 800에서 85 %가 0.5유닛 안에 이웃을 둔다"* 를 **눈으로** 보여 준다. 숫자만으로는 "그래서 얼마나 겹치는데?" 가 안 와닿는다 |
| **길이** | 8~12초 × 2벌 |
| **조건** | `__PerfHarness` 로 적 **400** 세우고 카이팅 |
| **A벌** | `NeighborBufSize = 12` (수정 전) |
| **B벌** | `NeighborBufSize = 64` (현재) |
| **담아야 할 것** | 적 무리가 플레이어를 따라오며 **서로 겹치는/덜 겹치는** 정도 |
| Stats | 끈다 |

⚠️ **정직하게 말해 두자면 A/B 차이가 눈에 잘 안 보일 수 있다** — 측정에서도 `0.5유닛내` 비율이
84.6 % → 85.1 % 로 거의 안 변했다. **차이가 안 보이면 그것도 결과다.**
그 경우 "버퍼를 키워도 겹침은 안 줄었다"는 §8-6 의 결론을 **영상이 뒷받침**하게 된다.

### S3. 적 800 + 무기 난사 (프레임이 무너지는 체감)

| | |
|---|---|
| **왜** | p95 가 정상 실행에서도 **22~49 ms** 다. "숫자로는 알겠는데 어느 정도야?" 에 답한다 |
| **길이** | 10~15초 |
| **조건** | `__PerfHarness` · `scenarioB = true` · 적 **800** |
| **담아야 할 것** | **끊김 자체**. 부드럽게 돌다가 뚝뚝 끊기는 구간 |
| Stats | 🔴 **켠다** (`Game 뷰 우상단 Stats`) — fps 가 화면에 찍혀야 증거가 된다 |
| 대조 | 같은 설정에 **적 130**(실제 상한)으로 한 벌 더. **"실제 게임 범위에서는 멀쩡하다"** 가 같이 보여야 정직하다 |

> 🔑 **S3 는 반드시 130 짜리와 쌍으로 찍는다.** 800짜리만 보여 주면
> "이 게임 느리네"로 읽힌다. 800은 `Waves.csv` 어디에도 없는 조건이다.
