# VS_LIKE

**Unity 6.3 LTS · URP · 2D 뱀파이어 서바이벌라이크**

가만히 서 있으면 죽는 게임에서 **"거기 있을 이유"를 계속 만들어 가는** 프로젝트다.
무기는 알아서 나가고 플레이어가 하는 일은 **어디에 설지 고르는 것**이다 —
그래서 이 저장소의 거의 모든 작업은 *"그 선택을 어떻게 만들 것인가"* 로 수렴한다.

## 1. 무엇을 하는 게임인가

사방에서 밀려드는 적을 피해 다니며 **10층짜리 스테이지 맵**을 올라간다.
웨이브를 버티면 레벨업 3택과 상점이 열리고, 죽으면 모아 둔 **메타 골드**로 영구 강화를 산다.

**지금 들어 있는 것**

| | 수 | 내용 |
|---|---|---|
| 무기 | 13 + 진화 4 | 검 · 활 · 총 · 기관총 · 화염구 · 폭탄 · 수리검 · 독 장판 · 마이크 · **공전체** · **지뢰** · 소환수 2종 → 엑스칼리버 · 윈드포스 · 데바스테이터 · 쿠나이 |
| 건물 | 10 | 터렛 · 곡사포 · 마을 · 농장 · 식당 · 냉각탑 · 사이렌 · **미끼** · **바리케이드** · **화톳불** |
| 패시브 | 17 | 기본 스탯 12종 + 소환수 증가 · 블링크 · 보호막 · **현상금** · **공격 범위** |
| 적 | 7 + α | 행동 6종(추격 · 원거리 · 돌진 · 측면 · 군집 · 길막) · 엘리트 · 보스 패턴 · **균열** |
| 직업 | 6 + 승급 4 | 전사 · 궁수 · 마법사 · 폭파병 · 암살자 · 소환사 → 파수꾼 · 파멸군주 · 수호자 · 이지스 |
| 그 밖에 | | 무기 진화 · 직업 승급(제단) · 상점 · 메타 강화 · 도감 · 랜덤 이벤트 8종 · 보물상자 · 픽업 6종 |

**최근에 들어간 것 — 구역 유도 시스템**

이 게임의 적은 늘 **플레이어를 중심으로** 태어난다. 그래서 어느 쪽으로 도망쳐도 세상이 똑같았고,
*아레나에 지리가 없었다.* 그걸 두 개로 풀었다:

- **균열**(Rift) — 적이 **거기서** 나온다. 방치하면 소환 간격이 점점 짧아지고, 부수면 닫힌다. *"안 가면 나빠진다."*
- **도전 석상**(Challenge Statue) — `E` 를 누르면 그 자리에서 **엘리트가 깨어난다.** *"가면 걸 수 있다."*

둘 다 한 지점에 발을 묶는데 **이유가 반대**라, 같이 놓이면 *"저 균열부터 닫을까, 지금 석상을 눌러도 될까"* 가 생긴다.
그리고 이때 비로소 터렛·바리케이드·지뢰 같은 **"한 지점을 붙드는"** 건물들이 지킬 대상을 갖는다.

## 3. 열어 보는 법

1. **Unity 6000.3.8f1** 로 프로젝트를 연다 (다른 버전은 URP 설정이 깨질 수 있다).
2. `Assets/Scenes/SampleScene.unity` 를 연다.
3. 재생.

> 밸런스 수치를 고쳤다면 **`Game/Balance/Import CSV -> ScriptableObjects`** 메뉴를 한 번 실행한다. (§4)

---

## 4. 수치는 전부 CSV 가 원본이다

```
Assets/Game/Balance/*.csv   ──[Import 메뉴]──▶   Assets/Game/**/*.asset (ScriptableObject)
         ▲                                                     │
         └──────────────[Export 메뉴 · 회수용]──────────────────┘
```

- 🔴 **인스펙터에서 `.asset` 을 직접 고치지 말 것** — 다음 Import 때 덮어써진다.
  실수로 고쳤다면 `Game/Balance/Export ScriptableObjects -> CSV` 로 회수한다.
- 새 아이템·웨이브·직업은 **`SceneWiring.csv`** 에도 경로를 넣어야 게임에 등장한다.
- 열의 뜻과 지금 값의 근거는 [`Docs/BALANCE.md`](Docs/BALANCE.md) 에 전부 적혀 있다.
  🔑 **무기마다 같은 열을 다르게 읽는다** — 예를 들어 `Range` 는 검에는 호의 반지름,
  공전체에는 공전 반지름, 지뢰에는 기폭 반경이다.

## 6. 문서

이 저장소는 **문서를 작업의 산출물이 아니라 작업의 일부**로 다룬다.
*무엇을 고쳤나* 보다 **왜 그렇게 고쳤나**와 **무엇을 재서 확인했나**를 남긴다.

| 문서 | 담는 것 |
|---|---|
| [`Docs/SETUP_STATUS.md`](Docs/SETUP_STATUS.md) | **완료 이력.** 작업마다 원인 → 바꾼 파일 → **검증 로그**(대조군 포함) |
| [`Docs/TODO.md`](Docs/TODO.md) | 아직 안 된 것 · 미검증 경로 · 결정 대기 |
| [`Docs/BALANCE.md`](Docs/BALANCE.md) | 수치를 고치는 법과 지금 값의 근거 |
| [`Docs/TUNING.md`](Docs/TUNING.md) | **사람이 플레이해야만 판정되는 것** (답이 숫자인 것들) |
| [`Docs/ROADMAP.md`](Docs/ROADMAP.md) | 장르 완성도 갭 분석 |
| [`Docs/PERF.md`](Docs/PERF.md) | 성능 측정 기록 |
| [`Docs/Parallel/`](Docs/Parallel/) | 두 세션(코드/콘텐츠) 병렬 작업 규칙 · 버그 대장 · 요청 주고받기 |

**판정 원칙 하나** — 이 저장소의 검증 로그에는 거의 항상 **대조군**이 같이 적혀 있다.
*"균열은 8초에 0.00 움직였다"* 만으로는 아무 말도 아니고,
*"같은 자리·같은 순간에 태어난 잡몹은 12.31 움직였다"* 가 옆에 있어야 한다.
그렇게 안 재서 **세 번 틀렸던 기록**도 그대로 남겨 두었다.

## 7. 만들어진 방식

기획·코드·아트·사운드·문서를 **Claude Code 와 함께** 쌓아 올린 프로젝트다.
Unity MCP 로 에디터를 직접 조작해서, 고친 뒤에는 **플레이 모드에서 숫자를 재고 화면을 캡처해** 확인한다.
스프라이트는 생성 모델로, 효과음은 `Tools/Audio/` 의 파이썬 신시사이저로 만들었다
(만들기 전에 `compare_sfx.py` 로 **기존 소리와 안 겹치는 자리**를 먼저 잰다).
